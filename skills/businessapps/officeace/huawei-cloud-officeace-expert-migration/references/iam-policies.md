# 权限与授权说明

## 概述

本技能是**本机文件搬运工具**，不调用任何云服务 API，不访问网络，不持有、不读取、不落盘任何 AK/SK。因此**不需要任何 IAM 策略或委托授权**，也不需要云命令行客户端凭证。

本文档的作用是把「它到底碰了哪些东西」写清楚，便于在受控环境（企业内网、云上跳板机、客户现场）里做权限审批时逐条对照。

## 一、结论：零云权限

| 权限类别 | 需求 | 说明 |
|---|---|---|
| IAM 策略（`iam:*`） | 无 | 不创建、不查询、不使用任何云账号身份 |
| 云服务 API（ECS/OBS 等） | 无 | 全部逻辑为本地读写，无 HTTP 请求 |
| 云命令行凭证 | 无 | 技能自身不执行任何云服务命令 |
| 网络出口 | 无 | 离线可跑；源包与目标目录都在本机 |
| 数据库 / 中间件 | 无 | 不连任何外部存储 |

## 二、实际触碰的文件路径

路径中的 `~` 指当前用户主目录。**读**为只读访问，**写**为创建/覆盖（写入前一律备份）。

| 路径 | 读 | 写 | 用途 |
|---|---|---|---|
| 源套件目录（三端任一） | 是 | **否** | 读取清单、`agents/*.md`、`skills/`、头像；铁律：不改源端 |
| staging 输出目录（`--staging`） | 是 | 是 | dry-run 产物：专家卡、技能、报告、台账 |
| `~/.office-claw/experts/` | 是 | 是 | 专家卡 |
| `~/.office-claw/catalog.json` | 是 | 是 | 全局目录 |
| `~/.office-claw/user-catalogs/<uid>.json` | 是 | 是 | `breeds` / `roster` / `variants` |
| `~/.office-claw/users/<uid>/user-experts.json` | 是 | 是 | UI 专家列表数据源 |
| `~/.office-claw/users/<uid>/user-teams.json` | 是 | 是 | 专家团条目（仅团队） |
| `~/.office-claw/connector-owner.local.json` | 是 | 否 | 只读活跃用户 `ownerUserId` |
| `~/.office-claw/skills/` | 是 | 是 | 技能目录本体 |
| `<OfficeAce 安装根>/.office-claw/`（`skills/`、`installed-skills.json`、`capabilities.json`） | 是 | 是 | custom 技能持久化源，缺一重启即丢 |
| `<安装根>/packages/green-package/web/dist/avatars/experts/` | 是 | 是 | 头像落地目录 |

`--app-root` 用于手动指定「OfficeAce 安装根」，当自动探测（`~/.office-claw` 的兄弟目录）失败时必须显式给出，否则头像与 `capabilities.json` 会写错位置。

## 三、为什么可以免审批

三条事实构成免审批依据：

1. **没有云端身份**：技能不读取云命令行客户端的配置目录、不读取环境变量里的 AK/SK，也没有任何签名逻辑。
2. **写入范围有界**：全部写操作落在 staging 与 `~/.office-claw` 两处；源套件目录为只读，脚本内无对该路径的写调用。
3. **可回滚**：每次写盘前生成时间戳备份（`<文件名>.bak-<时间戳>`），出错可原样回退。

## 四、数据敏感面（需在受控环境注意）

技能会读取并复制**真实用户数据**：`users/<uid>/` 下的专家卡包含人设、昵称、可见性、模型配置。这份数据等价于生产数据，因此：

- 不得把 staging 产物、`report.md`、`migration-manifest.json` 上传到公开仓库或外部服务；
- 交付报告里只写专家名与技能数，不粘原文正文；
- 备份文件与源数据同权限，迁移完成后按客户要求清理。

## 五、禁止事项

- 不接受用户在命令行、提示词或配置文件里以明文形式传入凭证（本技能也用不到）。
- 不把 `~/.office-claw` 整目录打包外发；需要跨机器搬运时只搬源套件包，到目标机重跑迁移。
- 不在未确认的情况下对 `--install` 放行——install 直接写用户真实数据目录，属写操作，须人工确认。
