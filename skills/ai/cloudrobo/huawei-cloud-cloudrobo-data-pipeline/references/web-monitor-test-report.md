### 本轮修正

- 文档作为键盘事件目标时没有 closest 方法：处理器增加目标检查，合成事件和常规键盘事件均可处理。
- 长重试表单的错误信息位于可滚动区域底部：出现错误后自动滚动到信息位置，浏览器断言错误处于可见区域。
- 计划、上传注册、最终输出改用检查/登记详情，不再套用“任务尚未提交”或任务字段。
- 所有输入为已有资产版本时，上传注册自动记为不适用的跳过；下游可继续，完成状态和摘要不因此告警。
- 移除资源监控页签、曲线及服务/CLI 查询实现；概览引导到 CloudRobo Console 查看资源详情，任务配置中的资源规格保留。
- 日志默认关闭自动刷新，按需手动获取；启用自动刷新后的间隔改为 60 秒，避免频繁请求与重绘。
- JS 展开控制语句并拆分多变量声明，嵌套三元改为具名判断和渲染辅助函数；复杂自动刷新条件分段检查。
- Python HTTP 处理统一返回 None，服务/节点查询返回字典、时间解析返回浮点数；对象文件读取校验结构，JSON 适配器保持单值协议。
- 将原 1470 行 `app.js` 按职责拆分成 10 个原生 ES 模块：入口 212 行，最大模块 330 行；增加生产 JS 单文件 400 行上限及未定义/未使用绑定检查。
- 静态资源保持显式白名单、会话认证和正确 MIME；扩大本地服务连接队列，支持浏览器并发加载模块。
- 对比重构前后 AST：80 个声明、事件处理器、定时器和启动逻辑一致；通知清理仅提取成公共函数。
- 修复直接打开 HTML 时静态路径失效和模块受限导致的黑块/持续连接提示：样式使用相对路径，图标增加默认尺寸与描边，普通启动脚本在文件模式下显示引导，仅在 HTTP 访问时加载业务模块。

### Windows 适配与验证边界（2026-10-17）

原有 pipeline_state.py 和 server.py 直接导入 fcntl，原生 Windows 确实无法启动。
现在二者使用 scripts/platform_utils.py：Windows 按偏移 0 锁定 1 字节并显式释放，POSIX 使用 flock。
后台启动分别采用 Windows 创建标志与 POSIX 新会话参数；后台错误流使用临时文件而不是生命周期依赖父进程的管道。
停止服务仍使用带会话认证的本地 HTTP 接口。清理演示目录前，先等待轮询/任务线程并释放启动锁。

输入支持 UTF-8 BOM；控制台与 Python 子进程使用 UTF-8；原子替换在 Windows 遇到短暂共享冲突时有限重试。
Windows 保留设备名/尾点 ID 被拒绝。浏览器测试加入 Windows Chrome 路径、Python 启动命令及可重试清理。

最初 9 项运行时测试实际在 macOS 执行，其中 Windows 锁和进程参数使用 API 替身；
新增的 2 项 CLI 无窗口检查也使用替身，当时运行时合计 11 项；当时再增加隐藏 STARTUPINFO 与包装器入口两项，合计 13 项；当前 SDK 方案删除 3 项已失效的 Web CLI 入口测试，保留 10 项运行时测试。
多进程锁、中文空格路径、BOM、本地 HTTP、后台启动/复用/停止是本机真实执行；浏览器平台仅模拟了 Windows 的 CLI 文本选择。
当前没有 Windows 执行器，尚未运行真实 msvcrt、Windows 分离进程、PowerShell 或 Windows Chrome。
因此不能把上述结果写成 Windows 实机通过；内网 Windows 请按 [原生 Windows 检查命令](web-monitor.md#windows-powershell) 复测。
