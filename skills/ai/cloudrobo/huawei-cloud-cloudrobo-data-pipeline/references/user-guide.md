## 1. 模块能完成哪些工作

模块由三部分组成：skill 负责理解需求与编排，Agent 通过 CLI 与 CloudRobo 交互；本地 Web 网站通过 Python SDK 观察和处理步骤内操作。浏览器调用本地 HTTP API，SDK 只在服务端运行。

```text
描述需求 → 生成并检查管线配置 → 确认执行计划 → 创建本地运行记录
→ 询问是否打开监控（接受则先打开）→ Agent 调用 CLI 准备输入和执行
→ Web 查看进度、日志、预览与失败处理 → Agent 核实产物并完成摘要
```

| 能力 | 你可以做什么 | 主要结果 |
|---|---|---|
| 引导创建管线 | 用自然语言说明数据和目标，由 skill 补问必要信息 | YAML 配置、可编辑草案、阅读预览 |
| 修改管线 | 增删处理步骤、改变评测范围、调整算子来源或资源池 | 新版本配置，保留旧文件 |
| 使用内置模板 | 使用已有仿真/遥操处理流程并调整字段 | 转换、清洗、质量与多样性评测的执行计划 |
| 复用中间数据 | 从已转换或已清洗的数据资产开始 | 清洗后评测，或只评测 |
| 执行与交接 | 注册数据、提交处理/评测任务、记录输入输出版本 | 可恢复的运行记录与已核实产物 |
| Web 观察 | 查看运行列表、DAG、历史尝试、日志与输出预览 | 当前运行进度与诊断线索 |
| Web 处理失败 | 确认后重新提交、跳过建议性评测、终止后续编排 | 新任务/跳过/终止记录 |
| 结果交付 | 查看完成摘要、复制产物路径、获取评测报告 | Markdown 摘要、数据资产信息、报告位置 |

自定义管线从你的目标和算子选择开始，支持纯内置算子、纯空间资产算法、两者混合。
**原始数据 → 格式转换 → 数据清洗 → 质量/多样性评测** 是一个可主动选择的内置模板，
不会作为“创建管线”的默认答案。建议每条分支围绕单数据集处理，但没有强制限制处理步骤的输入数量。
支持 A、B 各自产出一个数据集，再由支持多输入的合并算子 C 产出一个数据集；评测仍接收单个数据集。

Web 不会自动提交下一阶段。网页处理失败后，通常还需要回到 Agent 对话中回复“继续”。
停止 Web 服务也不会取消云端任务。网站目前不提供删除云端任务或无人值守 runner。

## 2. 准备环境与五分钟体验

### 2.1 解压后从哪里开始

解压完整包后，先按[环境预检](cli-installation-guide.md#environment-preflight)识别 Shell 并验证 Python 3.9+，
再进入含 `SKILL.md`、`scripts/`、`references/` 的 skill 根目录。以下假设已选中 `python`：

```bash
cd /path/to/huawei-cloud-cloudrobo-data-pipeline
python --version
```

以下所有命令均在该目录执行。将整个文件夹交给公司所用 Agent 的 skill 导入流程，保持相对目录结构完整。
不要只复制 SKILL.md；本地脚本、网页资源和参考文档都是模块的一部分。

| 使用场景 | 所需环境 |
|---|---|
| 离线创建配置、执行结构检查 | Python 3.9+；无需 CLI、凭据、网络 |
| 本地 Web 演示 | Python 3.9+、浏览器；Windows/macOS/Linux；无需安装 npm/pip 依赖 |
| 智能体真实执行 | 可用并已配置的 cloudrobo CLI、工作空间/区域、相关权限及算子 |
| Web 真实监控与重试 | 启动服务的 Python 环境安装 CloudRobo SDK，复用上述认证、端点与工作空间配置；见 [SDK 环境说明](web-monitor.md#web-sdk-setup) |
| 运行可选浏览器测试 | Node 22+、本机 Chrome/Chromium；无需 npm 安装 |

真实 CLI 安装与环境检查见 [CLI 安装说明](cli-installation-guide.md)，权限要求见 [IAM 权限](iam-policies.md)。
认证由 CLI 本地配置或环境变量提供，创建管线时无需向对话或配置文件提供 AK/SK。

首次执行前，Agent 应识别实际 Shell，查找并验证 Python 版本至少为 3.9，再统一使用该解释器。
Miniconda 的 `python` 同样适用，不能假设 Windows 一定有 `py` 或 Git Bash 一定有 `python3`。
Git Bash 使用带引号的正斜杠路径，例如 `cd 'C:/Users/name/My Project/skill'`；PowerShell 的变量、续行语法另行处理。
完整示例见 [环境预检](cli-installation-guide.md#environment-preflight)。
Windows 使用已验证的 `py -3` 或 `python` 替换命令中的 `python3`，PowerShell 使用用户目录或 `$env:TEMP` 代替 `/tmp`。
原生 Windows 启停、后台演示与检查命令见 [Windows / PowerShell](web-monitor.md#windows-powershell)。
请复制整个 skill，新的跨平台锁位于 `scripts/platform_utils.py`，不能只单独替换 server.py。
输入 JSON 可以是 UTF-8 或 UTF-8 BOM；运行记录默认位于当前用户的 `.cloudrobo/pipeline-runs/`。

### 2.2 不连接云端先体验网站

本节供你明确想查看模拟数据时使用。日常说“打开监控网站”会直接打开真实运行或运行列表，
无需先在演示/真实模式间选择；没有记录也可以打开空列表，见第 7 节。

```bash
python3 scripts/pipeline-monitor/server.py --demo --run demo-running-1001 --open
```

该命令会创建独立的临时演示数据并打开浏览器。页面顶部有“本地演示”标记，包含三个运行：

| 演示运行 | 用来体验什么 |
|---|---|
| demo-running-1001 | 正在运行的清洗步骤、历史失败尝试和日志 |
| demo-awaiting-1002 | 等待处理、重试确认、跳过建议性评测、终止确认 |
| demo-completed-1003 | 复用已有资产而跳过上传注册、TrainingReady 产物、评测报告与完成摘要（评测失败导致完成有告警） |

演示的操作只修改模拟状态，不调用云端接口。终端按 Ctrl+C 即可停止该前台服务。
若浏览器未自动打开，访问终端打印的完整地址；初次地址含访问令牌，登录后 URL 会自动清理。

需要后台运行并在之后手动停止时，给演示指定独立目录：

```bash
python3 scripts/pipeline-monitor/server.py --demo --runs-root /tmp/cloudrobo-guide-demo --background --open
python3 scripts/pipeline-monitor/server.py --runs-root /tmp/cloudrobo-guide-demo --stop
```

## 3. 通过对话创建自定义管线

### 3.1 不会写 YAML 也可以开始

对 Agent 说：

> 使用 CloudRobo 数据管线 skill，引导我创建一条自定义管线。我不会写 YAML，先生成配置，不执行。

如果已经知道输入和处理目标，可以一次提供：

> 数据在 obs://example-bucket/h5-raw/，是原始 H5 遥操数据，机器人 A2D。
> 需要转换、清洗，只做质量评测，不做多样性。清洗产物名为 demo-cleaned，先生成配置，不执行。

skill 会使用你已经给出的信息，再补问缺项，不需要重新手写配置，也不需要先准备完整的任务 JSON。
如果只说“创建管线”，首先会问希望处理什么数据、得到什么结果，有没有已选算子；不会直接生成模板。
是否需要转换取决于所选算子的输入格式：标准 LeRobot 算子接原始 H5 时需要转换，
自有空间算子能直接接收 H5 时则按其契约配置。

也可以完全不用模板，例如：

> 先查内置算子中可用的筛选、抽样能力，我选定后按“筛选 → 抽样”组合，不加清洗和评测。

> 只用我的两个空间资产算法，顺序为“内部数据过滤 → 内部标准化”，不使用内置处理步骤。

> 先用内置 H5 转 LeRobotV3，再接我的空间算法“内部标准化”，最终交付标准化的数据，不做评测。

以上空间算子名为示例；实际需从你的工作空间查询。每个步骤独立选择算子来源，
空间算法可以放在任意输入输出兼容的位置，不限于在清洗后插入。

### 3.2 一般需要回答哪些问题

| 主题 | 常见问题 | 为什么需要 |
|---|---|---|
| 当前数据阶段 | 原始、已转换、已清洗，还是其他已处理数据？ | 核对输入历史，不套用固定阶段 |
| 数据来源 | 本地目录、OBS 目录、还是已注册资产？ | 决定注册方式和输入交接 |
| 实际格式 | H5、ROS2、UMI、LeRobotV3 或其他？ | 核对首个算子能否直接接收 |
| 处理目标 | 想得到什么结果，已有想用的算子和顺序吗？ | 选择或查询能力，再确定依赖 |
| 算子来源 | 预置、工作空间、自有 OBS 代码？ | 决定发现与提交路径 |
| 机器人信息 | 算子需要的 robot/内置配置；特定指标可选的描述目录 | 数据集不必附带 YAML；机器人描述目录按指标需要，通过 OBS 挂载提供 |
| 资源与输出 | 公共/专属池、CPU/内存、worker 数；交付哪个步骤的输出？ | 决定实际任务配置与最终数据来源 |

不是每次都需要完整问一遍。可选配置挂载默认省略；只有你需要自定义参数或算子必需时才补问。
公共池 4c8g、1 worker 可以作为建议，但应由你选择或接受。专属池需要资源 ID 和池名称。

质量评测和多样性评测可以使用不同的机器人描述目录。例如：

> 两个评测都使用清洗结果，质量评测挂载机器人描述目录 obs://example-bucket/config/quality-robot/，多样性评测挂载 obs://example-bucket/config/diversity-robot/。

机器人描述目录通过算子声明的 OBS 配置挂载（如 `ROBOT_CONFIG_PATH`）传入，写在各评测成员的
`params.inputs` 中；旧的 `robot_config` 字段已移除，管线中出现会校验失败。不挂载时按算子内置/默认配置执行，
不要求补造 OBS 路径。manifest 类别也不使它必填；依赖机器人描述而未覆盖的指标应在报告中说明。
若 CLI/SDK 仍提示缺少 `robot_config`，说明客户端过旧，需要升级，不能用无关路径填充。
非法路径需要修正。确认前的计划预览会分别展示两个成员的挂载，Web 任务详情展示各任务实际提交的挂载，
重试保留原任务的挂载目录。配置示例见[自定义管线编写](custom-pipeline-authoring.md#参数资源和失败策略)。

### 3.3 如何描述算子和自定义步骤

- 预置算子：描述需要完成的功能；有环境时 skill 用 CLI 查询候选，再确认精确名称或 ID。
- 工作空间算子：提供精确名称或已知资产 ID，并说明用途和顺序；可以单独使用或组成整条管线。
- OBS 代码算子：提供代码 OBS 路径、容器挂载路径、镜像和入口命令，并说明输入输出。

例如：

> 在清洗后、评测前插入我的工作空间脱敏算子“内部数据脱敏”。其他步骤保留。

离线时允许先保存精确名称或待选择项；skill 不会捏造资产 ID、镜像、env 名称或输入挂载声明。
执行前仍会实时查询。没有查询到所需算子时，不会默默换用另一个算子。

### 3.4 什么时候创建完成

你会得到三个文件：

| 文件 | 用途 | 建议怎么用 |
|---|---|---|
| pipeline.yaml | 处理链、算子、依赖、输入与输出配置 | 交给 skill 执行或后续修改 |
| pipeline.draft.json | 同一管线，加资源选择、步骤用途和外部产物信息 | 与 YAML 一起保存，便于继续编辑和执行 |
| pipeline-preview.md | 人可读的配置、评测目录、资源与待补项 | 优先打开这个文件审阅 |

仅创建配置的请求到这里即可完成，不会注册数据、发布版本、创建任务或生成已确认的 Web 运行。
如果只是离线草案，报告会明确哪些字段尚缺、哪些平台信息尚未验证。

最终数据来源由 `pipeline.output.from_stage` 记录，输出名由 `asset_name` 指定。
单一末端处理步骤会自动成为最终来源并显示在预览里；有多个数据输出时会让你选择。
新建任务和数据输出默认使用 `管线名-步骤短名-月日时分秒`，例如 `teleop-clean-1018102430`。
同一管线共用管线名前缀，便于检索；步骤用短 ID，完整算子信息仍可在配置中查看。
默认不加随机串，同秒重名时才加 -2/-3；确认前会核对工作空间内是否已有同名资产。
64 字符限制包含整个名称、时间戳和序号；超长会提示缩短管线名或步骤短名，不静默裁剪。
你明确指定的精确名称在合法范围内会保留，超过上限会提示修改；恢复同一次运行不会反复改名。
网页重新提交处理任务会先给出新的短输出名，可确认前修改；评测继续使用原数据集名。
配置交付使用独立目录，里面仍是 pipeline.yaml、pipeline.draft.json 和 pipeline-preview.md。

其他处理步骤的中间输出名保存在草案的 `authoring.output_names`。只做评测时保留原数据并交付报告。

## 4. 修改已有管线与复用中间数据

### 4.1 修改配置

保留原目录，对 Agent 说：

> 保留原文件，把这条管线的两项评测改成仅质量评测，其他输入和处理步骤不变，另存为新版本。

或者：

> 改用专属池，resource_id 是指定资源 ID，dedicated_pool_name 是指定池名称，worker 规格保持不变。

skill 会读取已有文件，调整相关字段与依赖；你已提供的路径、机器人目录或规格不需要重新填写。
移除步骤后会检查依赖和数据交接。新版本输出到新目录，不覆盖已有三个文件。

### 4.2 从已转换数据开始

对 Agent 说“输入已经是转换后的 LeRobotV3，只做清洗和评测”，并准备：

- 数据资产 ID 与版本 ID；
- 资产名；
- 版本对应的 OBS 路径；
- 仅在所选评测指标需要或你选择提供时，补充机器人描述目录。

资产 ID 只代表数据身份，不表示已经清洗。skill 会确认实际处理阶段。
缺少版本/资产名时，有内网环境可通过只读查询补齐；离线时则先保留待补项。

### 4.3 只评测已有兼容数据

可以这样描述：

> 已有清洗数据，资产 ID example-cleaned，版本 v3，资产名 cleaned-data，
> 路径 obs://example-bucket/cleaned/。只做多样性评测，机器人描述目录为
> obs://example-bucket/config/robot/。只生成配置，不新建数据集。

得到的管线只包含所选评测，不会补造转换/清洗任务，也不要求命名一个新数据集输出。
清洗不是所有评测的强制前置；例如已转换且满足所选 LeRobot 评测输入契约的数据也可直接评测。
OBS 或本地的已有处理数据可按实际格式输入，在执行时只补所需的上传/注册准备。
上游数据路径、资产和版本会一同记录，执行前再次复核。

### 4.4 两条分支汇合为一个数据集

可以直接对智能体说：

> 左侧数据集给 A 算子，右侧数据集给 B 算子，二者结果按 A、B 顺序给我的空间合并算子 C；
> C 输出一个数据集。完成后只做质量评测。先帮我生成配置，不执行。

智能体会补齐两份初始数据的 ID、版本/路径及处理阶段，查询 A、B、C 的真实算子信息，
确认 C 确实支持所需的多数据集输入、输入顺序与单数据集输出，然后生成分支配置。
也可以将同一个初始数据集分给 A 和 B；不会因为使用多个数据集就拒绝创建。
算子信息暂时不可查时可保存待验证草案，执行前再核实，不把一个普通单输入算子自动当成合并算子。

配置中 C 的 `depends_on: [A, B]` 表示等两步结束，`input_from: [A, B]` 表示按此顺序使用两份产物。
若还要等一个评测检查，则只把检查步骤加进 depends_on；报告不进入数据输入。
网页概览可分别查看计划数据来源、等待依赖，任务配置的 dataset_configs 表格逐项展示实际提交的数据及确切版本；评测也保留一项，并与顶层资产/路径一致。
平台克隆依赖后端保存的版本元数据，创建后应回读核对；历史缺版本记录不能靠升级 skill 自动修复，也不能改用最新版本冒充。
历史尝试仍以该次实际配置为准。完整字段示例见 [多输入编排](custom-pipeline-authoring.md#multi-input)。

每条分支使用单数据集是方便理解的推荐方式；合并算子多输入属于允许的工作流。
合并后再接评测时，评测只接收 C 的单个输出。没有合并的多个最终输出需明确选择交付哪一个。

### 4.5 暂时信息不齐

说明“先保存草案，暂时不执行”。缺项可保留为 DRAFT，并在预览中列出。
循环依赖、错误字段、无效命名、未明确数据来源的多路依赖等结构错误需要先修正，不能靠“保存草案”绕过。

## 5. 如何阅读和保存配置文件

### 5.1 建议先看预览

重点核对：每条分支的数据阶段和来源是否正确，input_from 顺序和等待依赖是否符合需求，步骤顺序是否符合需求，评测范围是否多了或少了，
已挂载的配置目录（如机器人描述）是否正确；未挂载时确认按算子默认配置的评测范围。
同时检查资源池和规格是否是你选的值，产物名是否正确。
转换等中间步骤没有指定输出名时，预览会提示执行计划前需要确认。

清洗和产生下游数据的处理步骤属于阻断步骤；评测是建议性步骤。
预览中的“结构检查通过”只说明文件结构及本地规则通过，不代表算子已上线或数据已处理完成。

### 5.2 三种本地检查状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| STRUCTURE_VALID | 本地结构检查通过 | 可交付配置；执行前仍需平台复核 |
| INCOMPLETE | 缺字段、用户选择或占位符未补齐 | 补齐，或明确保存 DRAFT |
| INVALID | 结构、类型、命名、依赖或数据交接错误 | 修正后重新检查 |

资源、输出名和部分输入保存在 companion JSON，避免把它们错写成算子参数。
如果你手动修改 YAML，也请说明这是最新修改；skill 会核对 companion JSON，处理不一致处。

### 5.3 希望自己运行结构检查

由对话生成的草案 JSON 可直接作为输入：

```bash
python3 scripts/custom_pipeline.py check --input /path/to/pipeline.draft.json
python3 scripts/custom_pipeline.py export --input /path/to/pipeline.draft.json --output-dir /path/to/new-version
```

只想保留缺项草案时，export 增加 `--allow-incomplete`。脚本不覆盖已有文件，请选择新目录。
check 退出码 0 为结构通过、2 为缺项、1 为错误；允许缺项导出时会返回 0，但结果仍标 INCOMPLETE/DRAFT。

## 6. 在内网执行管线

### 6.1 从配置交给 Agent

将 YAML 和 companion JSON 一起带入内网，对 Agent 说：

> 使用 CloudRobo 数据管线 skill 执行 `/path/to/pipeline.yaml`，读取同目录草案中的资源和输入交接信息。

Agent 会先完成解释器/Shell 预检，再检查 CLI、工作空间、区域、数据版本及所需算子，构造实际任务配置。
区域优先用 `cloudrobo config get region` 读取配置，再与目标端点/已有工作空间信息核对，并在执行计划说明来源。
命令不可用、区域缺失或冲突时会在真实执行前询问；不会从镜像 URL 猜区域，也不会擅自修改配置。离线草案可暂留未确认。
数据集 OBS 路径以 show-version 返回的 url 为准，算子镜像、入口和输入声明以当次查询为准。

需要上传本地数据时，Agent 会先使用资产中心 `huawei-cloud-cloudrobo-asset` 的导入流程，
通过 `cloudrobo asset import-asset` 完成资产/版本创建和上传，你不需要另找 OBS 上传命令。
如果输入已经在 OBS，只注册资产；如果已有资产和版本，就核实后复用，不重复上传或创建。
实际上传仍在你确认计划、选择是否打开监控之后进行；导入成功后核实真实版本路径，再提交处理任务。
Agent 会通过 `record-inputs` 将每份输入的资产 ID、版本 ID、名称和 OBS 路径写入本地运行记录，
全部输入登记完整后“上传注册”才显示已登记。多输入分别展示，不把它们混成一个资产。
本次从本地导入的数据仍记录为本地来源，页面应从“待登记”变成“已登记”；不能因为导入后有了资产 ID
就把它改成“已有资产”并显示已跳过。只有运行开始时选择复用已有资产，才无需本次上传注册。
已打开的注册信息和输出预览也会随记录更新；若旧记录显示“登记信息待补全”，让 Agent 核实并补记，
无需重新上传。在运行已结束的历史记录上修改信息时需单独核实，不能通过重复上传补救。

所有算子统一按“依赖满足即进入就绪队列”调度，不需要区分普通分支或评测组。旧分组写法会在内部展开，
对话和执行都使用同一规则；算子的输入来源、独立参数和汇合条件照常保留。
Agent 使用 ready-tasks 检查就绪集合：先提交全部就绪任务，再轮询各自结果。
采用不阻塞的顺序提交：拿到 A 的任务 ID 并登记后就继续提交 B，A 在云端运行不会占着提交位置。
如果 B 已有任务 ID 却排队，说明平台正在调度资源；如果 B 一直没有任务 ID，应让 Agent 检查是否漏写了输入来源、
误设了对 A 的依赖，或先等 A 结束才继续。多分支运行时会短周期查询各活跃任务，及时提交新就绪步骤。

### 6.2 执行前看什么

执行计划应列出实际输入资产/版本，准备创建或发布的资源，各阶段算子及来源、envs、挂载、资源规格、
任务名、输出名和数据流。请核对后确认执行。仅生成配置和执行云端任务是不同操作。

与离线草案相比，真实查询可能发现算子不可用、输入声明变化、版本尚未就绪或资源不足。
这些结果需要在执行前处理，不能把草案中的旧信息直接当成最新平台配置。

已核实的 DRAFT 版本可用于支持它的平台/算子，不会仅因为未 RELEASE 就要求发布。
仅当下游明确要求 RELEASE，或失败被核实为发布状态限制时，才在智能体中确认发布；路径、权限、格式等错误单独排查。
结束时智能体统一列出中间和最终产物的版本状态，并提醒一次是否需要发布，尊重已经做出的选择。
暂不发布不影响完成状态；版本状态不混入任务的 `status`。

### 6.3 确认计划后开始监控

你确认完整执行计划后，Agent 创建本地运行记录，立即询问一次是否打开本次运行监控，
在上传、注册 OBS 资产、发布版本或提交首个任务之前就会提示，不会等到格式转换开始。
你可以选择“打开本次运行监控”或“仅终端跟踪”。选择打开时先打开本次页面，再继续输入准备；此前已要求打开则直接开，不重复询问。
此时页面已经能显示已确认计划、待准备输入和未开始的算子，无需先拿到任务 ID；已有资产无需注册的步骤显示不适用/跳过。
“运行记录已创建”表示本地准备就绪，不代表云端资产或任务已提交成功。
这个选择不阻塞终端继续执行；未回复时继续终端跟踪，不自动启动浏览器。轮询、重试或恢复时不会反复询问。
仅生成配置时不会触发此提示。之后随时可以要求“打开管线监控”。
终端是编排入口；网页中重试或跳过之后，回到终端回复“继续”，Agent 会重读状态并跟进。
发生对话中断时也从现有记录恢复，不要重新提交一条相同管线来替代恢复。

## 7. 使用 Web 网站观察任务

### 7.1 打开与停止

对 Agent 说“打开监控网站”即可。对话中已有真实运行时直接打开该运行，否则打开运行列表。
没有本地记录时会显示空列表，不会自动生成演示数据。手动命令为：

```bash
# 默认打开运行列表；run_id 不是必填项
python3 scripts/pipeline-monitor/server.py --background --open

# 打开指定的已有真实运行
python3 scripts/pipeline-monitor/server.py --run <run_id> --background --open
python3 scripts/pipeline-monitor/server.py --stop
```

默认打开空列表不需要 CLI 或云端凭据，也不需要先创建、确认或执行一条管线。
只有明确说“打开演示”“使用模拟数据体验网站”时才启用演示模式。
真实任务接口暂时不可用时会保留运行记录并显示查询错误，不会以演示数据替代。

默认运行根目录是 `~/.cloudrobo/pipeline-runs/`。使用自定义目录时，启动、停止和状态命令都要指定相同的
`--runs-root /path/to/runs`。默认端口 8765，被占用会自动选择空闲端口，以打印地址为准。
同一个 runs-root 的健康服务会被复用。

服务只监听本机 127.0.0.1；首次完整访问地址带本地访问令牌，请保留给本机使用。
没有浏览器的内网主机可通过 SSH 本地端口转发访问，转发端口需与服务实际端口相同。

### 7.2 运行列表

列表展示运行名称、run_id、状态、进度、当前步骤、开始时间和耗时。
可按名称/run_id 搜索，也可按运行中、等待处理、已完成或已终止筛选，点击“打开”进入具体运行。
列表只包含当前 runs-root 中的记录，不会自动搜索其他机器或其他目录。

列表和运行详情页均提供“删除本地记录”。成功、成功有告警、失败或已终止的 v2 运行可以删除。
点击后核对运行名和 run_id，勾选确认，再点“确认删除本地记录”；取消不会改动记录。
删除会清理该运行目录中的计划、状态、任务配置、历史事件、下载日志及页面缓存，完成后回到运行列表。
**删除本地记录不会停止或删除云端任务，不会删除 OBS 数据、资产和版本；本地历史删除后不可恢复。**
运行中/等待处理的记录需先终止后续编排；若有 pending_action，先让智能体核实提交结果。
旧版只读记录不能在网页删除。确认期间状态变化会拒绝删除，请刷新后重新确认。
若目录被占用而无法移走，页面提示失败并保留记录；若列表已移除但个别文件清理失败，
会提示 runs-root 下尚需清理的临时目录，处理文件占用或权限后再清理。

### 7.3 执行流程与事件时间线

主页面的分段进度条和 DAG 按计划展示各步骤，评测成员可以并列显示。
点击节点或进度段打开详情。当前尝试次数以 #n 标记，已有产物可表示为“外部输入”。
工作台固定在当前窗口内，浏览器整页不随内容变长。图过宽或分支过多时，在流程图区域内滚动；
运行列表和完成摘要也在各自区域内滚动。小屏幕的详情抽屉会覆盖主页面，按关闭按钮或 Escape 返回。

事件时间线记录状态变化和操作，默认收起并显示事件数，点击“展开”后在固定面板中浏览。
保留“全部”“仅操作”“仅失败”筛选，每页最多 20 条，可点“较早”“较新”翻页。
查看历史页时，新事件只显示数量提示，当前内容不会被挤动；“回到最新”恢复最新记录。
时间线内容在面板内滚动，收起后为流程图腾出空间；分页不会删除本地事件记录。
长详情先显示摘要，可点“查看完整内容”展开，刷新会保留展开状态。
手机和较矮窗口中，展开时间线会专注显示事件面板，收起后恢复流程图，避免两个区域都被挤得过小。
网页约每 3 秒取本地快照，未结束云端任务约每 15 秒查询一次；隐藏标签页会暂停网页轮询。

### 7.4 各种状态如何理解

| 状态 | 含义 | 常见处理 |
|---|---|---|
| 未开始 | 上游尚未完成 | 查看依赖，等待 |
| 待提交（等待编排） | 上游任务已结束，当前任务尚未提交；产物交接可能仍需确认 | 前往智能体查看进度并完成待确认事项，由智能体继续编排 |
| 排队中 | 平台尚未开始实际运行 | 观察资源和调度信息，避免重复提交 |
| 运行中 | 平台正在执行 | 查看日志；详细资源情况到 CloudRobo Console 查询 |
| 成功 | 当前任务成功 | 仍由 Agent 核实产物、记录交接 |
| 失败/已删除 | 当前任务失败或不存在 | 查看原因，选择允许的操作 |
| 等待处理 | Agent 已登记需要决策 | 重试、建议性跳过或终止 |
| 已跳过 | 评测未执行、已有资产无需注册，或处理已核实沿用原输入 | 评测/处理跳过均提示实际未执行内容；无需注册属于正常流程 |
| 处理中 | 已保留某项操作事务 | 等待结果，超时则核对实际任务 |
| 已终止 | 停止后续编排 | 已有云端任务可能仍在运行 |
| 可能过期/未知 | 未取得可靠最新状态或状态值未知 | 恢复查询后再操作 |

有处理或评测步骤待提交时，页面会显示“请到智能体确认进度”，步骤概览也会提醒查看是否存在产物版本或参数等
待确认事项。该提示不代表网页已读取智能体的问题，也不会自动发布版本或提交后续任务。
“阻断步骤”仍表示失败时停止后续流程，不表示当前停留的具体原因。

“Agent 可能离线”依据心跳显示，不代表云端任务已经停止；可以回到终端要求继续当前运行。

### 7.5 步骤详情与历史尝试

详情抽屉顶部可切换 #1、#2 等尝试。历史尝试用于诊断，不能从历史尝试直接执行重试/跳过。
每个任务应有提交时配置记录；缺少记录时仍可能看到状态，但网页不会据不完整信息重提。

| 页签 | 能看到什么 | 常用操作 |
|---|---|---|
| 概览 | 算子、任务 ID、输入输出、规格、时间、原始平台状态和错误 | 复制 ID、查询最新状态、进入操作 |
| 任务配置 | 提交配置、展开表格、原始 JSON、与前次差异 | 切换 JSON/表格、复制 JSON/CLI |
| 日志 | 作业/系统日志及文件内容 | 搜索、错误过滤、定位、完整日志、下载 |
| 输出预览 | proc 输出根目录的第一层文件夹及文件 | 查看文件夹名称、预览当前层文件、手动刷新；不展开子目录 |
| 评测报告 | eval 的报告预览/下载入口 | 每次点击获取新的临时链接 |

以上任务页签说明适用于处理和评测任务。Web 不提供资源监控页签；查看 CPU、内存等详细情况时，
在概览中复制任务 ID，前往 CloudRobo Console 查找对应任务。任务配置中的资源池与规格仍用于提交任务。
计划、上传和输出使用各自的检查或登记信息，不展示镜像、任务 ID、资源规格、任务尝试或重试操作：

- **计划确认**是检查项：“概览”显示运行、输入及处理范围，“检查项”列出输入数据、依赖、算子参数、
  资源输出和执行范围核对内容，并可展开已确认执行计划。日志页说明不产生日志，预览页说明不产生数据输出。
- **上传注册**按输入来源处理：本地目录需要上传并注册，OBS 目录只需注册，已提供资产 ID 和版本 ID 的
  已有资产无需重复上传或注册。仅运行开始时复用已有资产的情形保留节点并显示“已跳过”及复用原因，
  不计为未评测告警；本次上传/注册完成则显示“已登记”。
  “注册信息”和“输出预览”展示路径、资产与版本；日志页说明操作记录见终端和时间线。
  是否需要数据准备取决于输入来源，不能仅因 YAML 的处理步骤未列 upload 就跳过必要注册。
- **最终输出**是产物核对：“产物信息”和“输出预览”展示 Agent 核实的路径、资产和版本，作业日志到对应
  处理或评测步骤查看。以上节点都不会显示“任务尚未提交”。

已有资产仍需核实版本、真实路径及下游要求的发布状态；不需要上传注册不表示免去输入检查。
复制配置时敏感值可能已打码，不能把带掩码的命令直接用于真实提交。

同一任务的概览、配置、日志、输出预览在首次加载后保留在浏览器内存中，最多保留四个页签。
来回切换会恢复原内容、第一层目录列表、搜索条件和滚动位置，不重复查询日志或输出目录。
切换运行、步骤或尝试、当前任务/步骤状态变化，以及点击“查询最新状态”时，会清理旧详情。
概览仍随状态轮询更新；日志和目录使用各自的手动刷新按钮获取最新内容。刷新整个网页后会重新读取。
页面正文字号为 16 px，执行流程随可用宽度扩展；步骤较多或窗口较窄时在流程区域内横向滚动。

### 7.6 日志怎么排查

先选择作业日志或系统日志，再选择文件，首次打开会读取最新 64 KB。
日志默认关闭自动刷新，点击“手动刷新”按需读取；如需持续观察，可勾选“自动刷新 60s”。
自动刷新仅用于当前未结束任务的最新日志；查看完整日志、历史尝试或隐藏浏览器标签页时不会自动读取。
搜索按文本过滤；“仅错误行”突出 Error、Exception、Killed 等线索。“上一个/下一个错误”用于定位。
如果过滤后没有内容，先清空搜索或关闭错误过滤，再判断是否无日志。

“完整日志”通过 SDK 的 get_task_log/get_eval_task_log 获取（与原 CLI --all 行为一致）；内容较大时建议用“下载”。下载会先把日志保存到运行目录的 logs/，
再交给浏览器。界面中的行号是当前片段的相对行号，不保证等于完整远端文件的绝对行号。
Killed/退出码 137 可能与内存有关，应结合系统日志及 CloudRobo Console 中的资源详情判断，不能仅凭一行日志确定原因。

### 7.7 预览与报告

proc 从平台返回的 target_path 浏览输出文件；尚无该路径时显示等待输出的说明。
输出只列根目录第一层的文件夹和文件，文件夹排在前面，例如 data/、meta/、videos/ 和 manifest.yaml。
平台单独返回的目录列表也会展示；如果返回深层路径 data/chunk-000/episode_000001.parquet，页面只列 data/。
文件夹仅展示名称，不展开、不查询子目录；当前层文件可点击“预览”。切换页签保留列表，
“刷新目录”重新查询根目录，并清理旧列表和旧预览结果。
文件的“预览”每次点击都会重新请求平台，避免缓存过期的临时链接。
eval 报告的临时链接不长期缓存，过期后重新点击获取。平台返回 500/502/503/504 时，网页显示读取失败提示，
可短暂等待后手动点击原按钮重试一次；网页不自动重试。连续失败时保存任务 ID、文件/报告路径和错误信息，交给智能体排查。
预览读取失败不改变评测任务状态，也不需要重新提交评测。当前演示只返回模拟预览，不打开真实 OBS 文件。

详细资源监控由 CloudRobo Console 提供，本地网站不查询或缓存资源使用序列。

## 8. 在网页中处理失败

### 8.1 重新提交

1. 打开失败/删除的当前尝试，先查看错误、日志和资源。
2. 点击“重新提交”，等待服务重新查询当前预置算子并核实上游版本及路径。已核实且路径匹配的 DRAFT 输入也可继续；其他未确认可用的状态回智能体核实。
3. 检查镜像、算子 ID、入口、前后差异；可调整任务/输出名、资源、已声明 env 值及输入 url_path。
4. 勾选确认框后提交。未确认时按钮不可用；配置错误会保留弹窗并显示原因，修正后可再次提交。
5. 成功后生成新任务 ID，旧任务保留在历史尝试中。回到终端让 Agent 继续。

重试创建的是新任务，不是原地重启。镜像、algo_id 和入口来自最新查询，不能在网页随意改写。
草稿有有效期，超时后应重新打开对话框。工作空间/OBS 自定义算子的重查重提目前由终端执行。

### 8.2 跳过评测

建议性步骤尚未提交，或当前尝试失败/删除时，可以确认跳过。
尚未提交的单输入转换/清洗步骤可以点击“跳过…”，选择沿用原输入。网页会登记请求并继续阻断，
提示回到智能体核实原输入及所有下游算子的格式要求；确认兼容后才跳过，不生成新版本。
申请期间可以在网页取消。已知格式不兼容时显示禁用按钮及原因，例如原始 H5 后面直接接 LeRobot 清洗，
不能跳过必要转换。已经提交的阻断任务、多输入合并步骤、下游已经提交时不支持这种跳过。
确认跳过后摘要会说明处理未执行，不能把原数据标成已经清洗/转换。完整规则见
[保留原输入跳过](web-monitor.md#processing-skip)。
跳过评测不会消除已存在的清洗数据，但最终摘要会保留未评测告警；之后可补跑，仍需 Agent 更新最终结果。

### 8.3 终止管线

终止对话框会列出现有运行中的云端任务，并要求输入 run_id 最后四位。输入不匹配时无法确认。
终止后不再推进后续步骤，**现有云端任务不会自动停止**。如需处理这些任务，回到终端按平台能力执行。

### 8.4 操作按钮为什么不可用

可能是查看了历史尝试、运行已结束、步骤仍在排队/运行、缺少原始任务配置、状态过期、旧版只读运行，
或另一个操作正在处理。可以查看按钮提示和页面横幅。先恢复可靠状态，再决定下一步，避免重复创建。

## 9. 查看结果与导出摘要

运行进入终态后可切换“执行过程”和“完成摘要”。摘要包含产物路径、资产/版本、耗时、完成步骤、
全部任务尝试、评测结果、报告和告警。点击“复制路径”或“导出摘要”获取便于交接的结果。

清洗任务成功并不自动证明整条管线已完成；Agent 需要核实输出版本并记录最终产物。
SUCCEEDED_WITH_WARNINGS 表示完成但存在建议性失败/跳过，与文档中的 PARTIAL 含义对应。
如果产物尚未核实，页面会明确显示“尚未由 Agent 核实”，不应直接当作最终训练数据交付。

对于只转换、只清洗或只评测的自定义流程，应按实际范围说明已完成内容；不要把缺少评测的数据称为已通过全部评测。

## 10. 中断、冲突与恢复

### 10.1 用户操作后的继续

网页完成重试或跳过后，对 Agent 说“继续当前运行”。Agent 重新读取状态、跟进新的 task_id，
不会继续等待已被替换的旧任务。终端与网页同时处理同一步骤时，先完成的有效事务生效，另一方刷新后跟进。

### 10.2 创建任务超时

超时可能发生在平台已接受请求之后。页面保留“处理中/待核对”时，不要立即再点一次新建。
请让 Agent 读取 pending_action 中的任务名，使用 list-tasks/show-task 核实是否已经存在新任务，
再通过 resolve-action 登记新 ID，或在确认没有创建后释放事务。具体命令见下一节及 Web 技术说明。

### 10.3 停止、重新打开与旧记录

关闭浏览器或停止监控服务只会停止显示，不会删除运行目录或取消云端任务。
重新用相同 runs-root 和 run_id 启动即可查看已有记录。运行目录包括 plan.json、state.json、events.jsonl、
提交配置和下载日志，恢复时应一起保留。
通过“删除本地记录”移除的运行无法再从本地恢复，旧页面或旧链接会返回运行列表；云端资产和任务仍可到 Console 查询。

旧的 checkpoint 文件可导入只读查看；网页不会自动把它升级成可以修改的 v2 运行。
不要直接编辑 state.json 来解除冲突或清除 pending_action，终端和网页需要共用一致的事务协议。

## 11. 常见问题

| 现象/问题 | 说明与处理 |
|---|---|
| 我没有 YAML，能开始吗？ | 可以，说明当前数据和目标，skill 会补问并生成文件 |
| 没有内网或算子没上线，能创建吗？ | 可以保存草案；平台可用性与参数声明要在内网复核 |
| 生成配置后为什么没有任务？ | 仅创建不会执行；需要明确要求执行并核对实际计划 |
| 导出提示文件已存在 | 使用新的输出目录，原文件会保留 |
| 预览提示中间输出名没指定 | 可以先保留草案，执行计划前再确认，不会自动臆造 |
| 搜不到某个算子 | 核实区域、来源、精确名称和发布状态；不要换用其他功能冒充 |
| 新建页面显示 401 | 使用本次服务启动时打印的完整地址重新打开 |
| Windows 加载接口或周期刷新时黑色终端框闪现 | 更新完整 skill；Web 已通过 SDK 查询，不再为页面刷新启动 CLI。先停止旧服务再启动，刷新网页不能替换旧 Python 进程；自定义 runs-root 需保持一致 |
| 直接打开 HTML 只显示启动引导 | 请先启动本地监控服务，再访问终端打印的完整 HTTP 地址；直接打开文件无法读取运行记录 |
| 页面脚本加载失败 | 检查本地服务是否仍在运行、skill 文件是否完整，然后重新打开服务地址 |
| Windows 提示没有 fcntl | 使用包含 platform_utils.py 的完整新版 skill；Windows 使用 msvcrt，无需安装 fcntl |
| Windows 中 python3 找不到 | 使用 py -3 或 python，并确认版本至少为 3.9 |
| 端口 8765 打不开 | 可能已自动换端口，以实际打印地址为准 |
| 列表没有运行 | 检查 runs-root 是否相同，真实运行是否已由 Agent init |
| 节点成功，管线仍待提交 | 按页面提示到智能体查看进度，完成版本或参数等待确认事项，再继续编排 |
| 删除本地记录按钮灰色 | 运行尚未结束、存在待核实提交事务或为旧版只读记录；先处理对应状态 |
| 重试按钮灰色 | 检查当前/历史尝试、原始配置、状态新鲜度及 pending_action |
| 页面提示 Agent 可能离线 | 心跳较旧，云端任务未必停止；回终端继续当前运行 |
| 日志为空 | 检查文件类型、文件选择、搜索/错误过滤；排队阶段可能还没有日志 |
| 到哪里查看资源使用情况？ | 在概览复制任务 ID，到 CloudRobo Console 查询；本地 Web 不提供资源监控 |
| 报告地址过期 | 再次点击获取链接，实际内网访问仍需验证 |
| 点击终止后云端任务仍运行 | 符合设计；终止的是后续编排，现有任务需终端另行处理 |

## 12. 验证范围与内网复测

当前环境可验证本地创建、结构/导出、状态事务、演示网站和浏览器交互。
独立试用验证了创建、保留原文件修改、使用已有清洗资产评测，并据反馈改进自动预览。
浏览器验证覆盖页面、历史尝试、配置切换、日志筛选/下载、输出预览、Console 资源详情指引、确认/错误弹窗、
重试/跳过/终止、报告、摘要与四种视口。

这些结果不证明真实算子、任务、OBS 或内网接口已联调。详细记录见 [两轮验证报告](web-monitor-test-report.md)。

到内网后建议按以下顺序复测：

1. 用一个真实数据来源完成引导创建，检查精确算子及已声明 env/input 参数。
2. 确认执行计划，用小数据提交一次完整或部分管线，核对数据版本与任务 ID。
3. 检查真实日志、时间/错误字段和输出预览；详细资源情况到 CloudRobo Console 查询。
4. 在可控失败任务上确认重试，检查新 ID、历史保留及 Agent 后续跟进。
5. 核对建议性跳过、终止语义、产物摘要和报告链接。

## 13. 进阶命令速查

普通用户优先让 Agent 操作本节。手动使用时，`<...>` 是需替换的占位符，结果文件必须来自真实查询或明确的模拟数据。

| 目的 | 命令/入口 |
|---|---|
| 检查草案 | python3 scripts/custom_pipeline.py check --input /path/to/pipeline.draft.json |
| 导出新版本 | python3 scripts/custom_pipeline.py export --input /path/to/pipeline.draft.json --output-dir /path/to/new-version |
| 保存缺项草案 | 上条命令加 --allow-incomplete |
| 读取运行 | python3 scripts/pipeline_state.py --run RUN_ID show |
| 前台演示 | python3 scripts/pipeline-monitor/server.py --demo --open |
| 后台真实监控 | python3 scripts/pipeline-monitor/server.py --run RUN_ID --background --open |
| 停止监控 | python3 scripts/pipeline-monitor/server.py --stop |
| 更新心跳 | python3 scripts/pipeline_state.py --run RUN_ID heartbeat |
| 验证终态与产物后完成运行 | python3 scripts/pipeline_state.py --run RUN_ID finish |

创建运行和记录结果遵循共享协议：

```bash
# 仅在实际执行计划确认后初始化
python3 scripts/pipeline_state.py --run <run_id> init --plan /path/to/resolved-plan.json

# 在每次实际 create-task 前保留事务，返回 pending_action.id
python3 scripts/pipeline_state.py --run <run_id> reserve-task \
  --stage <stage_id> --expect-task none --name <confirmed_name> --config /path/to/task-config.json

# CLI 提交后核实 task_id，再登记；超时也先核对真实结果
python3 scripts/pipeline_state.py --run <run_id> resolve-action \
  --action-id <pending_action.id> --task-id <verified_task_id>

# result.json 只包含已核实的状态、时间、错误和产物字段
python3 scripts/pipeline_state.py --run <run_id> set-result \
  --stage <stage_id> --expect-task <current_task_id> --result /path/to/result.json

# 阻断失败需决策；并行成员需追加 --member <member_id>
python3 scripts/pipeline_state.py --run <run_id> await-decision \
  --stage <stage_id> --expect-task <current_task_id>
```

--expect-task none 表示当前没有任务；有任务时使用当前 ID，冲突退出码 3 表示应重读状态。
更多字段、恢复命令和 API 见 [Web 技术说明](web-monitor.md)。

### Windows 页面读取仍弹黑框时

先整体更新 skill，然后在同一个 runs-root 停止旧监控服务并重启；替换文件不会让已运行的 Python 自动重载。
新版启动器会识别旧服务并提示。执行 `python scripts/pipeline-monitor/server.py --diagnose`，
核对服务版本一致、restart_required=false、backend=sdk、available=true 及 SDK 版本。命令不查询云端，也不会输出认证令牌。
具体重启与诊断步骤见 [Windows 黑框诊断](web-monitor.md#windows-console-diagnostics)。
智能体编排保持 CLI；网站的平台读取与确认后重试使用 SDK，缺依赖时不会回退 CLI。Windows 桌面表现仍需在目标机器复测。
