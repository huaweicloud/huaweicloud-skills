# 常见问题排查

本文件支撑 SKILL.md"常见问题排查"章节,按现象定位根因并给出排查动作。

| 现象 | 可能原因 | 排查动作 |
|------|----------|----------|
| 服务反复重启(最常见) | **健康检查启动延迟过短** — vLLM V1 引擎首次启动需编译 IR + 捕获 CUDAGraph,耗时 5~10 分钟;探针过早探测超时 → 实例被杀 → 重启 → 重新编译 → 死循环。特征: 日志每次从零开始、无 Error/Traceback、pid 递增、间隔约数分钟 | ① 确认健康检查启动延迟 300s(超时 60s、周期 60s)与**失败次数 300**(部署配置已自动设置,18000s/300 分钟容忍窗口);② 确认探针路径/端口与启动脚本一致;③ 仍重启则检查实例日志定位真实原因 |
| 启动即退出,日志报 `Value error, Total number of attention heads (24) must be divisible by tensor parallel size (16)` | **TP 不是模型注意力头数的约数** — vLLM 启动硬校验: 头数必须能被 TP 整除(实测 Qwen3.8-27B 头数 24 + TP=16 → 24%16≠0,master/worker 全部崩溃)。**注意**: 该 TP 与 flavor 卡数无关,flavor 给多少卡都不能绕过架构约束;多节点场景"每节点卡数 ≠ TP"时最易踩坑(16 卡节点想全量 TP=16,但 24 头数不可被 16 整除) | ① 从模型 config.json 取 `num_attention_heads`(如 Qwen3.8-27B=24);② TP 必须取头数的约数(24 → 2/4/6/8/12/24)且 ≤ 单节点卡数;③ 改 `start_vllm.sh` 的 `TENSOR_PARALLEL_SIZE`/`TP_SIZE` 为合法值,重跑 `check_artifacts.py`(H12 传 `--num-attention-heads` 可自动拦截),重新上传 OBS 并重建服务 |
| 启动即退出 | 镜像与 NPU 驱动/CANN 不匹配 | 确认 SWR 镜像 tag 与资源池昇腾版本兼容 |
| 启动即退出,日志报 `Value error, The checkpoint ... has model type \`xxx\` but Transformers does not recognize this architecture` | **镜像内 transformers 版本过旧,不识别实验性模型新架构**(如 GLM-5.3-Flash 的 `glm5_next`)——镜像 tag 与模型文档要求的版本不配套(文档基于 v0.30.0RC,却用了稳定版 v0.23.0) | ① 核对模型页面标注的文档版本 vs 镜像版本;② 用 `docker run --rm <镜像> python -c 'import transformers; print(transformers.__version__)'` 确认镜像内 transformers;③ 换团队/内部构建的新版镜像(如 tag 直接叫模型名),或换稳定版本模型;④ 见 SKILL.md 步骤 1.0"镜像版本要求"与 2.1"镜像类型识别" |
| 启动即退出,容器初始化阶段日志报 `libcontainer: container start initialization failed ... exec user process caused "exec format error"` | ① **镜像架构与资源池不匹配**(docker inspect 镜像 `Architecture` 非 arm64);② **非标准镜像(MindIE/ATB 专用)带自定义 Entrypoint**,与 ModelArts 平台 `cmd` 组合冲突;③ 镜像内部混入 x86 二进制(架构声明正确但实际 exec 失败) | ① 确认镜像 `docker inspect <镜像> \| grep Architecture` 为 arm64,且 SWR 中镜像架构与本地一致(查 SWR 实际存储架构,勿只看本地缓存);② 确认镜像是否标准 vllm-ascend 镜像(环境变量含 `ATB_*`/`LCCL_*`/`SOC_VERSION`/CANN 版本异常 → 非标准,需按其自带入口启动,见 2.1);③ 在 ARM 节点 `docker run` 验证镜像可启动;④ 架构与 docker run 均正常仍报此错 → 平台调度节点/驱动与镜像 CANN 不兼容,需反馈团队或换资源池 |
| 创建服务返回 `400 ModelArts.8118 Insufficient NPU resources ... Requested: 16.0 Cards, Available: 0.0 Cards` | **失败/部署中的旧服务仍占用资源池全部卡数**,新服务无法调度 | ① 查旧服务状态: RUNNING/DEPLOYING/FAILED 均可能占资源;② 用 `POST /v2/{project_id}/services/{sid}/stop` 停止旧服务(FAILED 状态不可 stop 时,其实例已终止不占资源,直接创建新服务);③ 等待旧服务 STOPPED 后再创建新服务 |
| 部署到实验性模型专用镜像,容器反复 exec format error 无法定位 | 专用镜像可能基于 **MindIE/ATB 推理链路**(环境变量 `ATB_*`/`LCCL_*`、`SOC_VERSION=ascend910b1`、WorkingDir=/workspace、自定义 Entrypoint),**不是标准 vllm-ascend 镜像**,本 skill 的标准 `start_vllm.sh`/cmd 不适用 | ① 部署前在 2.1 完成镜像类型识别,确认镜像用途与启动方式;② 若为非标准镜像,询问用户镜像自带部署脚本或团队既有部署方式;③ 无法适配则换标准 vllm-ascend 镜像或稳定版模型 |
| multi_node worker 节点日志报 `RuntimeError: Remote engine N must use --headless unless in external or hybrid dp lb mode` | **vLLM 0.23.0 默认 DP LB 模式下 worker 必须追加 `--headless`,但脚本未加**(模板 `DP_LB_MODE` 逻辑被错误改为按 `DATA_PARALLEL_SIZE_LOCAL=1` 判断为 external LB→不加 → 崩溃)。`check_artifacts.py` H14 旧版误判 `dp_local=1` ⇒ external LB,已修正为按 `DP_LB_MODE` 判断 | ① 恢复 `start_vllm.sh` worker 分支为模板原始 `DP_LB_MODE` 判断: 默认/未设置→`WORKER_OPTS="--headless"` + `nohup python -m http.server 8080`;`DP_LB_MODE=external\|hybrid`→不加;② 重跑 `check_artifacts.py` H14 应 PASS;③ 覆盖上传 OBS 后重新部署 |
| PD 分离部署,日志报 `RuntimeError: expected src to have a size equal to the slice of self. src size = [128, 5120], slice size = [64, 5120]`(CUDAGraph 捕获阶段,`qwen3_next.py` forward → `_warmup_and_capture` → `_dummy_run`) | **PD 分离下 `MODEL_ARGS` 误加 `--speculative-config`(qwen3_5_mtp MTP 投机解码)**——MTP 是单引擎内优化,draft head 验证逻辑依赖单引擎 batch 展开维度;PD 分离 KV cache 跨角色传输使 batch 维度被 PD 分工切分,MTP 展开维度(128)与 PD 切分后维度(64)不匹配(5120=hidden_size) | ① PD 分离 `MODEL_ARGS` 移除 `--speculative-config`;② `--compilation-config` 简化为 `{"cudagraph_mode":"FULL_DECODE_ONLY"}`(去 `cudagraph_capture_sizes` 数组);③ `--additional-config` 去 `enable_flashcomm1` 仅留 `{"enable_cpu_binding":true}`;④ 按 SKILL.md 3.2"PD 分离 MODEL_ARGS 填充约束"填充,禁止照搬单节点示例的 MTP/flashcomm1 等单引擎优化参数 |
| 启动即退出,日志报 `pydantic_core._pydantic_core.ValidationError: 1 validation error for VllmConfig Assertion failed, Flash Comm v1 is only supported when tp_size > 1.`(紧随 `AscendConfig.enable_flashcomm1 is set from additional_config with value True.`) | **TP=1 时 `--additional-config` 含 `enable_flashcomm1: true`**——vLLM 0.23.0 AscendConfig 强制 `enable_flashcomm1` 仅 `tp_size>1` 可用,TP=1 在 `create_engine_config` 阶段崩溃(模型权重加载前分钟级秒级退出)。**与部署形式无关**(single/multi_node/pd 任何形式 TP=1 均崩,实测 Qwen3.8-27B BF16 + multi_node + TP=1 → 两实例同时 ValidationError 崩溃)。根因: agent 误把文档量化版示例(含量化版 `enable_flashcomm1`)当 BF16+TP=1 示例套用 | ① `--additional-config` 移除 `enable_flashcomm1`,仅留 `{"enable_cpu_binding":true}`;② 重跑 `check_artifacts.py` H17(强制校验 TP=1 时含 `enable_flashcomm1` 即 FAIL 阻断上传)应 PASS;③ 覆盖上传 OBS 后重新部署;④ 见 SKILL.md 3.1 "enable_flashcomm1 × TP_SIZE 通用约束" |
| 启动即退出,日志报 `error: argument --speculative-config/-sc: Value '{"method": cannot be converted to ...` 或同类 JSON 参数解析失败 | **JSON 参数用字符串变量传递,引号丢失** — 启动脚本把 `--speculative-config`/`--compilation-config`/`--additional-config` 等 JSON 参数放进 `EXTRA_ARGS` 字符串变量,`${EXTRA_ARGS}` 展开时单引号失效,argparse 收到 `{"method":` 截断值 | ① 模型特有参数(尤其 JSON)一律加入模板内置的 `MODEL_ARGS` bash 数组(每项一个元素,JSON 单引号包裹);② 普通无 JSON 参数才可走 `EXTRA_ARGS` 环境变量;③ 见 SKILL.md 步骤 3.2 说明 |
| 启动即退出,日志报 `Syntax error: "(" unexpected` | **脚本被 `sh` 执行** — 启动脚本使用 bash 数组(`MODEL_ARGS=(...)`),但 ModelArts 启动命令写成 `sh .../start_vllm.sh`,`sh`(dash)不识别数组语法 | 启动命令改为 `bash /home/ma-user/code/start_vllm.sh`(code 目录挂载到容器后,见 SKILL.md 步骤 3.2) |
| 启动即退出,日志报 `OSError: Repo id must be in the form 'repo_name' or 'namespace/repo_name': '<路径>'` | **模型权重未挂载** — `${MODEL_PATH}` 下无 `config.json`(ModelArts 模型存储地址填错层级、挂载路径与 MODEL_PATH 不一致、OBS 挂载认证凭据缺失导致挂载为空),vllm 把本地路径当 HuggingFace repo 处理 | ① 启动脚本必须内置 config.json 存在性自检(见 SKILL.md 步骤 3.2);② 检查模型配置: 存储地址精确到模型目录(如 `obs://bucket/models/<模型名>`)、挂载路径与 MODEL_PATH 一致;③ 用 OBS 对象桶挂载时确认认证凭据(临时委托凭证或 DEW AK/SK)已配置;④ 容器内 `ls -la ${MODEL_PATH}` 核对 |
| 健康检查失败,日志报 `python3: can't open file '/code/xxx.py': No such file or directory` | 探针脚本引用了**硬编码的绝对路径**(如 `/code/get_master_ip.py`),或该脚本未上传/挂载路径与预期不符 | ① 脚本内引用同目录文件一律用 `$(dirname "$0")` 相对定位(见 SKILL.md 步骤 3.3);② 核对 `CODE_OBS_PATH` 目录文件齐全并已挂载到探针引用的目录;③ 核对文件存储挂载的存储地址精确到 code 目录、挂载路径与探针配置一致 |
| OOM / 显存不足 | max-model-len 或并发过大 | 调小 `--max-model-len`,调低 `--gpu-memory-utilization`,减少 TP 卡数需求需配小模型 |
| 模型过大单节点放不下/启动 OOM | 模型权重+KV Cache 超出单节点显存 | 回到 SKILL.md 步骤 1.1 重新确定部署形式: 扩大 TP 卡数或改**多节点部署**;若为量化权重可改用 W8A8 等降低显存 |
| 多节点/PD 部署卡住或启动失败 | **节点间网络不通(HCCL/DP)**、master/worker 角色判定失败(rank table 未 completed / `POD_IP` 不匹配)、`--tensor-parallel-size` 与单节点卡数不一致 | ① 确认节点间网络互通、安全组放通 HCCL/DP 通信端口(`--data-parallel-rpc-port`);② 核对平台注入 `GLOBAL_RANK_TABLE_FILE_PATH`/`POD_IP` 与 `get_master_ip.py` 角色判定(rank table 是否 completed、POD_IP 是否匹配);③ TP_SIZE = 每台推理单元 NPU 卡数;④ 查 vllm-ascend 多机部署示例核对环境变量 |
| PD 分离请求失败/ConnectError | pd(双角色)双角色端口未打通或角色判定失败;多节点(单引擎): DP 通信或 master/worker 判定失败 | **pd(PD 分离)**: ① 核对 Prefill/Decode 双角色 `VLLM_ROLE` 注入正确与脚本内按角色内置的 `PORT`(proxy=8080/prefill=8080/decode=7100)未冲突;② 核对节点角色判定(经 `get_master_ip.py` 读 rank table)与端口网络可达。**multi_node(单引擎)**: ③ 放通 `--data-parallel-rpc-port`(13389);④ 核对 `get_master_ip.py` 读 rank table 角色判定正确 |
| 模型不支持 | 不在 vllm-ascend 支持列表 | 换支持列表内模型,或告知用户需自行适配 |
| 访问 docs.vllm.ai / quay.io 等第三方站点报 `SSL certificate problem: self-signed certificate in certificate chain`,或 curl 000(非代理真拦截) | **企业/云上代理对目标站点做 TLS 中间人(MITM)证书替换**,本机不信任其 CA;`getent`/直连 DNS 可能不通,但 curl 走代理不受影响 | ① 先按"安全编码规范"校验 URL 主机在白名单内(docs.vllm.ai 等),再重新用 `curl -sk <url>`(跳过证书校验)访问——多数场景实际可达;② `-k` 仅跳过证书校验,不影响"以官方文档为准"的 tag 决策;③ 若 `-k` 后仍 000/超时,才是代理白名单真拦截(如部分环境 github.com / modelscope.cn),再走降级机制 |

| 多机部署卡住 | HCCL 网络不通 | 检查节点间网络互通、安全组放通 |

| 多机 PD(pd)实例间 ConnectError | DP 通信端口未放通或 master/worker 角色判定失败 | 核对 `--data-parallel-rpc-port`(13389)网络放通、`get_master_ip.py` 读 rank table 角色判定正确、超节点亲和组=N |

| 调用 CreateInferService API 返回 401/403 | IAM Token 失效(24h 有效)或权限不足(缺 modelarts:service:create);token 复制截断(含非标准字符 `-`/不以 `==` 结尾)→ `APIGW.0301 decrypt token fail`;**获取 token 本身 401**: IAM 域名未确认用错 / `scope.project.name` 误用 region 原值(含 `.beta` 后缀,须去掉)/ 账号名·用户名·密码三要素错配 | ① 重新获取 Token(推荐 IAM API 获取,Python 正则完整提取,禁 shell 管道);② **获取前确认 IAM 域名与 `project_name`**(见 SKILL.md 4.3 token 获取第 ③ 条: 默认 `iam.<region>.myhuaweicloud.com`;project name 默认 region 去 `.beta` 等后缀,如 region=`cn-southwest-301.beta` → `cn-southwest-301`);③ 确认账号有 ModelArts 服务创建权限与资源池使用权限;④ 见 SKILL.md 4.3 token 获取与提取 |
