# Acceptance Criteria

## Overview

This document defines the pass/fail criteria for the OptVerse Solver Assistant skill.

## 1. CLI Command Format Validation

### 1.1 Correct Format

```
# hcloud OptVerse operations
hcloud OptVerse UploadFile --X-Chat-Route-Id=<id> --agent_type=optverse --file=<path> --cli-region=cn-east-3
hcloud OptVerse DownloadFile --chat_id=<id> --filename=<name> --X-Need-Content=true --cli-region=cn-east-3
hcloud OptVerse ListArtifacts --chat_id=<id> --cli-region=cn-east-3
hcloud OptVerse PublishChat --chat_id=<id> --name=<name> --type=optverse --cli-region=cn-east-3

# Python script for SSE
python scripts/create_chat.py --message=<text> --agent_type=optverse --filenames=<file1> [<file2> ...] [--chat_id=<id>]
```

### 1.2 Incorrect Format

```
# WRONG: using --version instead of version
hcloud OptVerse --version

# WRONG: missing required parameters
hcloud OptVerse UploadFile --file=<path>

# WRONG: using hcloud for createChat (not supported)
hcloud OptVerse CreateChat --message=<text>

# WRONG: exposing AK/SK in command line
hcloud OptVerse UploadFile --cli-access-key=AK --cli-secret-key=SK --file=<path>
```

## 2. Parameter Validation

| Parameter | Required | Valid Values | Default |
|-----------|----------|-------------|---------|
| `--cli-region` | Yes | `cn-east-3`, `cn-north-7`, etc. | `cn-east-3` |
| `--agent_type` | Yes | `optverse`, `predict`, `vrp`, `demand` | `optverse` |
| `--X-Chat-Route-Id` | Yes (UploadFile) | UUID or alphanumeric (1-64 chars) | Auto-generated by script |
| `--file` | Yes (UploadFile) | Valid file path, < 100MB | — |
| `--chat_id` | Yes (Download/List/Publish) | UUID from previous step | — |
| `--filename` | Yes (DownloadFile) | Artifact filename from ListArtifacts | — |
| `--X-Need-Content` | No | `true`, `false` | `false` |
| `--message` | Yes (create_chat.py) | 1-16384 chars | — |
| `--filenames` | No (Round 1 only) | File name array (Round 1: `["需求分析输入.md"]`; Round 2+: empty) | `[]` |

## 3. Output Format Validation

### 3.1 createChat Response

Pass criteria:
- Response is valid JSON
- Contains non-empty `chat_id` field
- Contains non-empty `id` field
- Contains `content` field (may be empty for confirmation rounds)
- `tool_calls` is a list (may be empty)

Fail criteria:
- Script exits with non-zero code
- Error message printed to stderr
- Response missing `chat_id`

### 3.2 UploadFile Response

Pass: `{"chat_id": "<uuid>"}` with non-empty chat_id
Fail: HTTP error, missing chat_id

### 3.3 ListArtifacts Response

Pass: Response contains `artifacts` array with at least one item per completed stage
Fail: Empty artifacts array (stage not yet completed)

### 3.4 DownloadFile Response

Pass: Response contains `content` field with file data
Fail: `--X-Need-Content` not set; `content` field empty

### 3.5 PublishChat Response

Pass: `{"id": "<uuid>"}` with non-empty id
Fail: HTTP error (usually means stages not all confirmed)

## 4. Security Validation

| Check | Pass Criteria | Fail Criteria |
|-------|--------------|---------------|
| AK/SK exposure | Never in stdout, logs, or reports | AK/SK visible in any output |
| AK/SK in conversation | Never asked user to type AK/SK in chat | User prompted for plaintext credentials |
| File permissions | Script not world-readable | Script readable by all users |
| Debug output | AK masked as `XXXX****XXX` | Full AK/SK in debug output |

## 5. Workflow Validation

| Stage | Pass Criteria | Fail Criteria |
|-------|--------------|---------------|
| Step 1 (Upload) | chat_id returned | Upload failed |
| Step 2 (Create Chat) | chat_id + content returned | SSE parsing failed |
| Step 3 (Download Artifacts) | Artifacts listed and downloaded | No artifacts available |
| Step 4 (Confirm Round 2) | New response ID returned | Same ID as previous round |
| Step 5 (Download Modeling) | Modeling artifacts present | Stage not advanced |
| Step 6 (Confirm Round 3) | New response ID returned | Stage not advanced |
| Step 7 (Upload Data) | File uploaded + data check started | Upload failed |
| Step 8 (Confirm Round 4) | New response ID returned | Data check not confirmed |
| Step 9 (Publish) | Published asset ID returned | Publish rejected (stages incomplete) |

## 6. Error Handling Validation

| Error Scenario | Expected Behavior |
|---------------|-------------------|
| Invalid chat_id | Script returns error, does not crash |
| SSE connection timeout | Script prints timeout error, exits with code 1 |
| Permission denied | hcloud returns error code, agent checks iam-policies.md |
| File not found | Upload returns file error |
| Token expired (if used) | Script re-authenticates automatically |
| Network error | Script retries (up to 3 times by default) |
