# IAM Policies for WAF Log Analysis

This skill has two functional phases: **log analysis** (read-only) and **rule recommendation & execution** (write operations).

## Phase 1: Log Analysis Only (Read-Only)

If you only need to query and analyze security event logs without creating rules:

```json
{
  "Version": "1.1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "waf:securityEvents:list",
        "waf:securityEvents:get"
      ],
      "Resource": [
        "*"
      ]
    }
  ]
}
```

## Phase 2: Full Skill — Analysis + Rule Execution (Recommended)

To use the full skill capabilities including creating recommended protection rules:

```json
{
  "Version": "1.1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "waf:securityEvents:list",
        "waf:securityEvents:get",
        "waf:policy:list",
        "waf:policy:get",
        "waf:policy:update",
        "waf:customRule:*",
        "waf:ccRule:*",
        "waf:whiteblackipRule:*",
        "waf:geoipRule:*",
        "waf:antiCrawlerRule:*",
        "waf:antiTamperRule:*",
        "waf:punishmentRule:*",
        "waf:antiLeakageRule:*",
        "waf:ipReputationRule:*"
      ],
      "Resource": [
        "*"
      ]
    }
  ]
}
```

## Alternative: Using Built-in Roles

| Role | Coverage |
|------|----------|
| **WAF ReadOnlyAccess** | Covers log analysis only (Phase 1) |
| **WAF FullAccess** | Covers all operations including rule creation (Phase 2) |

## Permission Explanation

| Action | API | Purpose |
|--------|-----|---------|
| `waf:securityEvents:list` | ListEvent | Query attack event list with filters |
| `waf:securityEvents:get` | ShowEvent | View details of a single attack event |
| `waf:policy:list/get` | ListPolicy, ShowPolicy | Query current policy settings |
| `waf:policy:update` | UpdatePolicy | Enable/disable protection modules |
| `waf:customRule:*` | CreateCustomRule, ListCustomRules, etc. | Precise access control rules |
| `waf:ccRule:*` | CreateCcRule, ListCcRules, etc. | CC protection rate limiting rules |
| `waf:whiteblackipRule:*` | CreateWhiteblackipRule, ListWhiteblackipRule, etc. | IP blacklist/whitelist rules |
| `waf:geoipRule:*` | CreateGeoipRule, ListGeoipRule, etc. | Geo access control rules |
| `waf:antiCrawlerRule:*` | CreateAnticrawlerRule, etc. | Anti-crawler JS challenge rules |
| `waf:antiTamperRule:*` | CreateAntiTamperRule, etc. | Anti-tamper rules |
| `waf:punishmentRule:*` | CreatePunishmentRule, etc. | Attack punishment rules |
| `waf:antiLeakageRule:*` | CreateAntileakageRule, etc. | Anti-leakage sensitive data rules |
| `waf:ipReputationRule:*` | CreateIpReputationRule, etc. | IP reputation threat intelligence rules |

## Notes

- **Phase 1 only**: Use the read-only policy if you want to restrict users to log analysis without the ability to modify WAF configuration.
- **Phase 2 (full)**: Required when users need to execute the hcloud commands generated by rule recommendations.
- The `ListAttackActionTypes` operation is a metadata query and typically does not require special permissions beyond basic WAF access.
