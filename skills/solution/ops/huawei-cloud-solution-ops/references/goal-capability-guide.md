# 目标—能力组织指南

本文件用三个差异明显的目标样本，演示如何从用户想得到的结果组织跨服务能力、替代、动态缺口
和完成证据。目标视图只引用现有 router、registry、脚本和 playbook，不复制 API 参数、实时价格、
配额、库存或服务状态。它不是唯一方案；Agent 可以调整服务、工具、参数和顺序，也可以采用
本文件没有列出的合理路径。

## 目标样本 1：企业网站上云

当用户说“把企业网站部署到华为云”时，目标往往同时涉及运行载体、网络入口、域名、HTTPS、数据、监控、日志、备份和成本。单独从某个服务出发容易遗漏目标，也容易过早锁定一种实现。

本文件演示如何围绕用户目标组织现有资料。它提供候选能力、替代路径、澄清点和验收维度，**不是唯一方案**，也不替代场景路由、实时发现、安全确认或 Agent 的判断。

### 目标摘要

典型目标可以表达为：

> 在满足网站类型、访问范围、预算和运维要求的前提下，选择可落地的华为云能力，并以用户可访问、证书有效、关键业务路径正常且可观测为完成依据。

先保留会显著改变架构的要求：

- 网站是纯静态、服务端渲染，还是 Java/其他动态应用；
- 是否需要数据库、持久文件、定时任务或后台管理；
- 目标 region、访问用户和备案等外部条件；
- 域名是否已有、由谁管理，是否要求 HTTPS；
- 可接受的持续费用、可用性、恢复目标和运维复杂度；
- 当前只需要方案，还是后续可能执行真实部署。

### 候选能力

| 目标维度 | 候选能力 | 替代路径或影响因素 |
| --- | --- | --- |
| 静态内容托管 | OBS 静态网站等对象存储能力 | 若存在 Java、会话或服务端逻辑，应转向计算类载体；也可使用已有外部构建/托管能力 |
| 动态应用运行 | ECS、Flexus、容器等计算候选 | 根据应用形态、团队经验、弹性、运维和当前 region 可用性选择 |
| 公网入口 | EIP、负载均衡、CDN 或服务自带入口候选 | 流量、源站类型、安全暴露、缓存和高可用要求会改变选择 |
| 域名解析 | DNS 与现有域名管理能力 | 域名可能由外部注册商管理；需明确变更权限和生效验证方式 |
| HTTPS | 证书管理、负载均衡/CDN/源站 TLS 能力 | 证书来源、绑定位置、续期方式和域名控制权需要确认 |
| 数据能力 | RDS 等托管数据库或用户已有数据库 | 取决于应用依赖、兼容性、网络、备份和费用；纯静态站通常不需要 |
| 日志与指标 | LTS、CES、应用自身日志和健康检查 | 先明确希望观察的用户路径、指标、日志范围和保留周期 |
| 备份与恢复 | 服务自带备份、CBR、对象版本或应用级备份候选 | 恢复目标、数据位置和演练要求决定方案 |
| 成本与治理 | 规格、计费方式、标签、预算和账单查询能力 | 实时报价、优惠和当前租户条件应查询，不能仅凭资料推断 |

Agent 应先通过路由和当前上下文缩小候选，再针对关键缺口查询。表格不规定服务组合，也不规定各操作的先后关系。

### 替代路径示例

#### 路径 A：纯静态企业展示站

可从 OBS 静态托管、域名、HTTPS、缓存和基础可观测能力中组合候选。若用户后来要求 Java 后端、数据库或服务端会话，这条路径不再满足当前目标，应重新选择运行载体。

#### 路径 B：单体 Java 应用

可从计算实例或适合的容器运行能力、数据库、网络入口、域名/HTTPS、日志与监控中组合候选。规格、网络结构和部署工具由实时条件及 Agent 判断，不在本样例中预设。

#### 路径 C：已有运行环境，只补齐上线能力

如果用户已经有计算、应用或数据库，重点可能变成入口、域名、HTTPS、观测和验收。不要因为“网站上云”重新创建已有资源。

### 只问会改变方案的问题

优先澄清以下问题；已有可靠答案时不要重复提问：

1. 网站是否包含必须在服务端运行的动态能力？
2. 是否已有应用、数据库、域名、证书或云资源需要复用？
3. 目标 region、访问范围和预算边界是什么？
4. 用户当前授权范围是仅规划、只读预检，还是在看过方案后允许执行？
5. “上线完成”的关键用户路径和可用性要求是什么？

### 已知缺口和动态事实

以下内容通常不能从本文件直接得到：

- 当前账号、project、region 的服务和 API 可用性；
- 配额、权限、已有 VPC/子网/安全组、域名和证书状态；
- 当前规格、价格、优惠、备案和外部 DNS 条件；
- 应用真实依赖、构建产物、健康检查和数据迁移方式；
- 用户是否已经看过本次方案并明确授权真实变更。

这些缺口由 Agent 通过提问、现有脚本、工具观测或官方资料补齐。遇到未预见的服务限制时，应保留目标并寻找替代能力，而不是坚持初始候选。

### 完成和证据

不同方案可以共享以下验收思路：

- 架构和费用风险已经向用户说明，真实变更得到当前方案的明确授权；
- 云资源达到所需状态，但这只说明 `resource_ready`；
- 域名解析、TLS、HTTP/应用健康和关键业务路径获得相应证据；
- 监控和日志能覆盖约定的关键路径；
- 未验证、部分成功或结果未知的内容被明确列出。

不要把资源创建成功、任务已受理或单个 HTTP 状态自动写成网站整体完成。

## 目标样本 2：跨服务资源盘点

### 用户真正需要的结果

资源盘点不是“跑完一个 List API”，而是在明确作用域内形成可解释的覆盖摘要：哪些资源域已查、
哪些失败、哪些只有部分结果、哪些尚未查询，原始证据在哪里，以及当前结论还不能回答什么。

先明确会改变覆盖边界的作用域：

- account、project、region；
- enterprise project 是明确限定、全部范围，还是当前未知；
- 需要覆盖的资源类型、region 集合和时间点；
- 当前只要摘要，还是需要资源级 artifact 和关联视图。

用户没有提供 enterprise project 时，不猜 ID；把作用域写成“未限定/全部范围”或“未知，待确认”，
避免把一个 enterprise project 的结果误报为整个 project 或 account。

### 候选能力与替代路径

| 目标维度 | 候选能力 | 替代或缺口处理 |
| --- | --- | --- |
| 上下文与作用域 | profile、account/project/region 和 enterprise project 检查 | 作用域无法确认时先输出缺口，不静默扩大结论 |
| 跨服务覆盖 | 使用 account inventory 生成核心资源只读计划 | 用户只关心某个系统时可缩小服务、region 或标签范围 |
| 完整性 | 分页、total_count、失败分桶和未查询清单 | 权限不足时保留失败并提供分批补查，不把失败当作资源为零 |
| 证据收敛 | 摘要、计数、字段结构和独立 artifact | 大输出不进入对话或 task 入口，按需生成关联视图 |
| 治理候选 | 标签、owner、绑定、监控、备份和依赖证据 | 只有资源清单时保持候选，不直接得出闲置、成本或删除结论 |

Agent 可以按风险、权限和用户优先级改变补查服务与顺序。目标卡不要求一次查询所有服务，也不把
`scripts/hcloud_account_inventory.py` 的当前 target 列表写成永久服务范围。

### 动态事实、完成和证据

- 真实资源状态、数量、标签、关联和权限必须来自当前作用域的工具观测；
- 分页未完成时只能声明部分结果；单项失败和未查询项要分别保留；
- 输出应明确覆盖、失败、部分结果和未查询项，并引用独立 artifact；
- 不能从资源清单推断账单金额，也不能仅凭“未绑定、未挂载或停止”认定闲置；
- 只有计划覆盖项已经收敛，或用户接受剩余缺口时，才把盘点阶段写成完成。

- 盘点计划：`scripts/hcloud_account_inventory.py`

## 目标样本 3：成本治理

### 用户真正需要的结果

成本治理要把已经发生的费用、当前资源证据、未来价格或合同条件分开，再给出可核验的优化候选、
证据缺口、影响和下一步。优化候选不是执行授权，也不等于已经确认的节省。

任何合计、比较或排名前先明确：

> `fact × grain × money_basis × scope × billing_period`

并按需说明币种、分页是否完整和观测时间。不同 tuple 的金额不强行相加；账单与成本数据权限失败
表示“未授权或不适用”，不是“没有费用”。

### 候选能力与替代路径

| 目标维度 | 候选能力 | 替代或缺口处理 |
| --- | --- | --- |
| 历史费用事实 | BSS 账单、成本分析、资源明细或订单侧证据 | 先选能回答问题的 fact/grain，不用资源规格反推账单 |
| 当前资源交叉验证 | 产品侧 List/Show、标签、绑定、监控、备份和依赖 | 当前资源不存在也不能否定历史账单；保留删除或延迟计费可能 |
| 优化候选 | 闲置形态、规格、计费承诺、架构或用量调整候选 | 允许并列方案，不把释放/降配写成唯一答案 |
| 用户决策 | 候选金额、证据缺口、风险、可逆性和核验成本 | 证据不足时给区间、条件或未知，不编造精确节省 |

Agent 可以调整服务、工具、参数和顺序，也可以发现目标卡未列出的优化路径。高影响动作仍需结合
owner、利用率、数据/备份、依赖、合同/包周期、退订规则、未来报价和用户确认单独判断。

### 动态事实、完成和证据

- 历史账单金额不是未来节省承诺；最多作为候选金额或带条件的参考基线；
- 历史 billed/paid/outstanding/amortized、当前资源状态和未来报价要分开表达；
- 分页不完整时不能声称完整账号总额或排名；
- 结论要说明已确认候选、仍缺证据、用户需要决定的事项和未执行的动作；
- 只有分析范围和金额口径闭合时才完成分析；释放、退订、变配或采购属于另一项受控任务。
