# Acceptance Criteria

当用户要求“完成”“上线”“可用”“修复”或需要判断任务是否可以关闭时读取本文件。先根据任务类型选择适用标准；不要为了形式完整而执行无关探测。

## 通用标准

任务只有在以下条件同时成立时才能标记为 `verified`：

- 用户目标、作用域、region/project 和关键约束明确。
- 所有已执行动作都来自用户授权范围，费用、安全和破坏性边界没有扩大。
- 结果由实际命令/API、独立资源回读或必要的业务探测支持。
- 敏感信息已脱敏，未把密码、AK/SK、token、私钥写入回复、日志或受版本控制文件。
- 部分成功、未验证项和阻塞项被明确列出，没有把未知状态写成成功。

## 按任务类型验收

| 任务类型 | 最小验收证据 |
| --- | --- |
| 查询/盘点 | 数据来源、region/project、返回条数或资源 ID、失败服务及分页完整性。 |
| 创建/修改/删除 | 提交回执、异步 job 终态、目标资源回读，以及数量和关键配置符合计划。 |
| ECS/EVS 机内操作 | 云侧状态之外，还要有 SSH/受控远程命令、挂载、进程或文件系统证据。 |
| Web/ELB/公网入口 | 安全组与绑定关系正确，后端健康，并有实际 HTTP/HTTPS 或等价业务探测。 |
| 数据库/中间件 | 实例终态、网络与访问控制正确，并完成任务要求的连接或产品健康探测。 |
| Terraform | `fmt`、`validate`、受审阅的 plan；用户确认后 apply；再用云侧查询和业务探测回读。 |
| 故障排查 | 原故障证据、采取的修复、同一路径复测结果和仍存在的风险。 |

## 不能算完成的状态

只有 dry-run、plan、`accepted`、`job_id`、HTTP 2xx、资源 `ACTIVE`、生成 probe template，或仅看到命令退出码 0，都不足以单独证明业务目标已经完成。

具体采证层次和状态表达见 `references/verification-method.md`。P0 生命周期任务可使用 `hcloud_closure_plan.py` 与 `hcloud_acceptance_closure.py` 生成和评估证据计划，但脚本结果仍必须对应当前用户目标。
