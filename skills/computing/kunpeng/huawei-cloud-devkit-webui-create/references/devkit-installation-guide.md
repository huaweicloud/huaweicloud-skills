# Installation Guide - Kunpeng DevKit WebUI Mode

This document provides the complete installation steps and scripts for Kunpeng DevKit WebUI mode, including hcloud CLI installation, Kunpeng ECS creation via Python SDK (with KMS password encryption), Python paramiko SSH connection, and DevKit installation.

> **Security architecture (aligned with SKILL.md):**
> - **Python SDK** — ECS creation + KMS encrypt/decrypt/delete (password never leaves Python process memory, never appears in `ps -ef`)
> - **hcloud CLI** — EIP/VPC operations (no password involved)
> - **Python paramiko** — SSH connection + DevKit installation (password from KMS decrypt, stays in Python memory only)
> - **No `DEVKIT_ECS_PASSWORD` environment variable.** The old expect + `$env(DEVKIT_ECS_PASSWORD)` method is prohibited (env vars are readable by other processes).

## 1. Complete Installation Workflow

### Prerequisites

| Item | Requirement |
|------|-------------|
| hcloud CLI | >= 3.2.0, with AK/SK configured (see cli-installation-guide.md) |
| Python SDK | Python 3.8+ with `huaweicloudsdkcore huaweicloudsdkecs huaweicloudsdkkms paramiko` installed |
| IAM Permissions | ECS/VPC/IMS/EIP/KMS related permissions (see iam-policies.md) |
| ECS Architecture | aarch64 (Kunpeng processor) |
| ECS OS | CentOS 7.6 / Ubuntu 18.04 (only these two are compatibility-verified) |
| ECS Disk Space | >= 2GB available |
| ECS Memory | >= 4GB |
| ECS Permissions | root |

> **⚠️ No password environment variable required.**
> The ECS password is randomly generated by the Python SDK (26 characters, in process memory only), encrypted via Python KMS SDK, and decrypted only inside the paramiko SSH subprocess. The password is **never** exported to a shell variable, environment variable, command-line argument, or conversation.
>
> ```bash
> # Verify Python SDK + paramiko are installed
> # Auto-use China mirror when system timezone is UTC+8 (faster in CN region; auto-detected via Python)
> PIP_INDEX=$(python3 -c "import time;print('-i https://mirrors.huaweicloud.com/repository/pypi/simple' if -(time.timezone)//3600==8 else '')")
> pip install $PIP_INDEX huaweicloudsdkcore huaweicloudsdkecs huaweicloudsdkkms paramiko
> python3 -c "import huaweicloudsdkecs, huaweicloudsdkkms, paramiko; print('SDK + paramiko OK')"
> ```

### Workflow Overview

```
Step 0: hcloud installation   → Install KooCLI, configure AK/SK authentication
Step 1: Create Kunpeng ECS    → Python SDK creates aarch64 ECS (random adminPass in memory) + KMS encrypts password
Step 1c: Bind EIP             → hcloud CLI creates and binds EIP (no password involved)
Step 2: SSH secure connection → Python paramiko SSH (password decrypted from KMS, in process memory only)
Step 3: Environment check     → Check system architecture, disk space, memory (run on remote ECS via paramiko)
Step 4: Install dependencies  → Install required and optional dependency packages (run on remote ECS)
Step 5: Download package      → Download DevKit-All package from OBS (run on remote ECS)
Step 5.5: Verify signature    → Verify .p7s digital signature to ensure package integrity
Step 6: Interactive install   → Automate installation interaction with expect, run in background via nohup
Step 7: Verify installation   → Check service status and port listening
Step 8: Cleanup KMS key       → After verified success, disable + schedule KMS key deletion (password unrecoverable)
```

## 3. Creating a Kunpeng ECS

For detailed steps, see [ecs-creation-guide.md](ecs-creation-guide.md).

### 3.1 List Subnets and VPCs for User Selection

**Before creating the ECS, list the first 10 subnets and their associated VPCs for the user to select a subnet (VPC is automatically associated).**

```bash
REGION="cn-north-4"

# 1. Query VPC list, build VPC_ID→VPC_NAME mapping
hcloud VPC ListVpcs --cli-region=$REGION

# 2. Query the first 10 subnets, each associated with its parent VPC name
hcloud VPC ListSubnets --cli-region=$REGION --limit=10
```

**Display format:**

> **Create Kunpeng ECS — Subnet/VPC Selection**
>
> | # | Subnet | CIDR | VPC | VPC CIDR | AZ |
> |---|--------|------|-----|----------|----|
> | 1 | subnet-dev | 10.0.0.0/24 | vpc-main | 10.0.0.0/16 | cn-north-4e |
> | 2 | subnet-test | 10.0.1.0/24 | vpc-main | 10.0.0.0/16 | cn-north-4e |
> | 3 | subnet-prod | 10.1.0.0/24 | vpc-prod | 10.1.0.0/16 | cn-north-4c |
> | ... | | | | | |
>
> Enter subnet number (1-10):

**After the user selects a subnet, VPC_ID, SUBNET_ID, and availability zone (AZ) are automatically obtained.**

### 3.2 Query Other Required Resources (in Parallel)

```bash
# After user selects subnet, query remaining resources in parallel
hcloud VPC ListSecurityGroups --cli-region=$REGION &
hcloud ECS NovaListFlavorsDetails --cli-region=$REGION &
hcloud IMS ListImages --cli-region=$REGION --__imagetype=gold --status=active &
wait
```

### 3.3 Select Kunpeng Flavor and Image

> **⚠️ You must select a Kunpeng (k-series) flavor and an aarch64 image**

Common Kunpeng flavors:

| Flavor | vCPU | Memory | Description |
|--------|------|--------|-------------|
| kc1.large.2 | 2 cores | 4GB | Kunpeng general-purpose compute |
| kc1.xlarge.2 | 4 cores | 8GB | Kunpeng general-purpose compute (recommended) |
| kc1.2xlarge.2 | 8 cores | 16GB | Kunpeng general-purpose compute |

### 3.4 Create Security Group

Create an empty security group (no inbound rules). You must manually open ports after the ECS is created.

```bash
SG_NAME="sg-devkit-kunpeng"
hcloud VPC CreateSecurityGroup --cli-region=$REGION --security_group.name=$SG_NAME
# Get SECURITY_GROUP_ID from the response
SECURITY_GROUP_ID=<from response>
```

### 3.5 Create ECS + KMS Encrypt (Python SDK)

> **⚠️ Security: Password stays in Python process memory, never exported, never in `ps -ef`.**
>
> The `scripts/create_ecs_and_setup_devkit.py create` command:
> 1. Generates a random 26-character password in memory
> 2. Creates ECS via Python SDK with `adminPass` parameter (API param, not CLI arg → no `ps -ef` leakage)
> 3. Attaches the dedicated DevKit security group
> 4. Waits for ECS to become ACTIVE
> 5. Creates KMS key and encrypts password via Python SDK (password stays in process memory)
> 6. Outputs only `server_id`, `kms_key_id`, `kms_cipher_text_file` — **password is NEVER in the output; cipher text is written to a local file (mode 600), never passed via command line**

```bash
ECS_NAME="devkit-kunpeng"

RESULT=$(python scripts/create_ecs_and_setup_devkit.py create \
  --region $REGION \
  --vpc-id $VPC_ID \
  --subnet-id $SUBNET_ID \
  --flavor kc1.xlarge.2 \
  --image-id <aarch64_image_id> \
  --az $AZ \
  --ecs-name $ECS_NAME \
  --security-group-id $SECURITY_GROUP_ID 2>/dev/null)

SERVER_ID=$(echo "$RESULT" | python3 -c "import sys,json; print(json.load(sys.stdin)['server_id'])")
KMS_KEY_ID=$(echo "$RESULT" | python3 -c "import sys,json; print(json.load(sys.stdin)['kms_key_id'])")
KMS_CIPHER_TEXT_FILE=$(echo "$RESULT" | python3 -c "import sys,json; print(json.load(sys.stdin)['kms_cipher_text_file'])")
```

> **The password is never exported.** Only `kms_key_id` and `kms_cipher_text_file` are available for the SSH install phase. The password exists only in:
> - Python process memory (during script execution, then garbage collected)
> - KMS encrypted secret (scheduled for deletion after DevKit installed)
> - Local cipher text file (mode 600, read only by the install/status subcommands)
>
> **Do NOT use `hcloud ECS CreateServers --server.adminPass=...`** — the password would be visible in `ps -ef`.

### 3.7 Bind EIP (Optional)

> **EIP Specification**: The EIP must be **pay-per-use** with **300 Mbit/s** bandwidth. Do NOT use a smaller bandwidth (e.g., 5 Mbit/s) as it will severely limit DevKit WebUI access and package download speed.

```bash
# Create EIP — pay-per-use, 300 Mbit/s bandwidth
hcloud EIP CreatePublicip \
  --cli-region=$REGION \
  --publicip.type=5_bgp \
  --bandwidth.share_type=PER \
  --bandwidth.name=${ECS_NAME}-eip \
  --bandwidth.size=300 \
  --bandwidth.charge_mode=traffic
```

## 4. SSH Connection and DevKit Installation

### Step 0: SSH Secure Connection (Python paramiko)

> **⚠️ The old `expect` + `$env(DEVKIT_ECS_PASSWORD)` method is prohibited** — environment variables are readable by other processes via `/proc/pid/environ`.
>
> The new method uses **Python paramiko**. The `create_ecs_and_setup_devkit.py install` command:
> 1. Decrypts the password from KMS (in Python process memory only)
> 2. Connects to the ECS via paramiko `SSHClient.connect(password=decrypted)` — never appears in `ps -ef`
> 3. Uploads `install_devkit_webui.sh`, `auto_install_devkit.expect`, `verify_devkit.sh` to `/tmp/` via SFTP
> 4. Starts `install_devkit_webui.sh` in the background on the remote ECS (nohup)
> 5. Deletes the password variable (`del password`) — always, even on failure

```bash
# After EIP is bound and security group ports 22/8086 are open:
python scripts/create_ecs_and_setup_devkit.py install \
  --region $REGION \
  --eip <EIP_ADDRESS> \
  --kms-key-id $KMS_KEY_ID \
  --kms-cipher-text-file $KMS_CIPHER_TEXT_FILE \
  --devkit-url "https://kunpeng-repo.obs.cn-north-4.myhuaweicloud.com/Kunpeng%20DevKit/Kunpeng%20DevKit%2026.1.RC1/DevKit-All-26.1.RC1-Linux-Kunpeng.tar.gz"
```

The `install` subcommand starts the installation in the background on the remote ECS and returns immediately. Poll progress with the `status` subcommand or `poll_devkit_status.py` (see SKILL.md "Polling Progress").

> **The password never leaves Python process memory.** It is never exported to a shell variable, env var, or CLI argument. For details see [ssh-connection-guide.md](ssh-connection-guide.md).

The steps below (Step 1-6) describe what `install_devkit_webui.sh` executes **on the remote ECS** via paramiko — they are for reference; the agent does not run them manually.

### Step 3.5: Verify Digital Signature (.p7s)

The DevKit package is signed with a PKCS#7 digital signature (`.p7s`). Always verify the signature before extraction to ensure the package has not been tampered with.

```bash
# Download the signature file (same OBS path as the package + .p7s suffix)
wget -c "https://kunpeng-repo.obs.cn-north-4.myhuaweicloud.com/Kunpeng%20DevKit/Kunpeng%20DevKit%2026.1.RC1/DevKit-All-26.1.RC1-Linux-Kunpeng.tar.gz.p7s" \
  -O DevKit-All-26.1.RC1-Linux-Kunpeng.tar.gz.p7s

# Verify the PKCS#7 detached signature
# -inform DER: .p7s files are DER-encoded
# -binary: content is binary (tar.gz), not text/MIME
# -content: the file being signed
# -noverify: skip cert chain validation (Huawei self-signed), still verifies signature-content binding
openssl cms -verify -inform DER -binary \
  -in DevKit-All-26.1.RC1-Linux-Kunpeng.tar.gz.p7s \
  -content DevKit-All-26.1.RC1-Linux-Kunpeng.tar.gz \
  -noverify -out /dev/null

# If verification fails, DO NOT proceed with installation
# A failed verification means the package may be corrupted or tampered with
```

> **⚠️ Security requirement**: If signature verification fails, abort installation immediately. Do not extract or install a package that fails verification.

### Step 4: Extract Installation Package

```bash
cd /tmp
mkdir -p DevKit-All
tar -xzf DevKit-All-26.1.RC1-Linux-Kunpeng.tar.gz -C DevKit-All
```

### Step 5: Run Interactive Installation

```bash
cd /tmp/DevKit-All/DevKit-All-26.1.RC1-Linux-Kunpeng

# Write the expect automation script
cat > /tmp/auto_install_devkit.expect << 'EXPECTEOF'
#!/usr/bin/expect -f
set timeout 600
spawn bash install.sh -a
expect {
    "access mode for your installation" { send "1\r"; exp_continue }
    "Do you want to authorize" { send "y\r"; exp_continue }
    "Enter the installation path" { send "\r"; exp_continue }
    "Please enter the installation port" { send "\r"; exp_continue }
    "is available, do you want" { send "y\r"; exp_continue }
    "Do you want to continue" { send "y\r"; exp_continue }
    "Enter the serial number of the plug-in" { send "1,2,3,4,5,6\r"; exp_continue }
    "select the number" { send "1\r"; exp_continue }
    "Enter the serial number" { send "1\r"; exp_continue }
    eof
}
EXPECTEOF

chmod +x /tmp/auto_install_devkit.expect
# Previous extraction directory retained for inspection

# Run as guarded background process (prevent SSH disconnection from interrupting installation)
PID_FILE="/tmp/devkit_install.pid"
nohup /tmp/auto_install_devkit.expect > /tmp/devkit_install.log 2>&1 &
INSTALL_PID=$!
echo "${INSTALL_PID}" > "${PID_FILE}"
echo "Install PID: ${INSTALL_PID} (saved to ${PID_FILE})"
echo "  Monitor: tail -f /tmp/devkit_install.log"
echo "  Status:  kill -0 \$(cat ${PID_FILE}) 2>/dev/null && echo RUNNING || echo STOPPED"
echo "  Abort:   kill \$(cat ${PID_FILE})  then  rm -f ${PID_FILE}"

# Poll until installation completes (with 600s timeout)
MAX_WAIT=600; WAITED=0
while kill -0 ${INSTALL_PID} 2>/dev/null && [[ ${WAITED} -lt ${MAX_WAIT} ]]; do sleep 10; WAITED=$((WAITED+10)); done

# Check installation result
tail -20 /tmp/devkit_install.log
```

## 5. Interactive Installation Steps in Detail

The DevKit installation script is interactive and includes multiple steps that require user input. This section describes each interactive step and how it is handled by expect automation.

### 5.1 Interactive Workflow Overview

```
install.sh -a
    │
    ├── [Interaction 1] Select access mode → Input: 1 (username/password)
    │
    ├── Environment check (automatic)
    │   ├── System command check
    │   ├── Dependency package check
    │   └── Plugin environment check
    │
    ├── [Interaction 2] Authorize handling of failed items → Input: y
    │
    ├── [Interaction 3] Enter installation path → Input: Enter (default /opt)
    │
    ├── [Interaction 4] Enter installation port → Input: Enter (default 8086)
    │
    ├── [Interaction 5] Confirm available port → Input: y (if prompted)
    │
    ├── [Interaction 6] Firewall port confirmation → Input: y (if prompted)
    │
    ├── [Interaction 7] Install assembly dependencies → Input: y (if glibc<2.28)
    │
    └── Install framework and plugins (automatic)
```

### 5.2 Detailed Description of Each Step

#### Interaction 1: Select Access Mode

```
Select a tool access mode for your installation:
  [1]: User name and password
  [2]: OAuth 2.0-based SSO
Enter the sequence number of the tool access mode for your installation (default: 1):
```

| Option | Description | Recommended Scenario |
|--------|-------------|---------------------|
| 1 | Username/password mode | General use (recommended) |
| 2 | OAuth 2.0 SSO mode | Enterprise SSO integration required |

**Recommended input**: `1`

#### Interaction 2: Authorize Handling of Environment Check Failures

```
Do you want to authorize the tool to handle the items failed in the installation environment check?[y/N]:
```

Appears when optional dependencies are missing (e.g., RoCE/GPU-related dependencies). Select y to authorize the tool to handle them automatically, or n to cancel the installation.

**Recommended input**: `y`

> **⚠️ Note**: The input validation for this interaction is strict; you must enter the full "y" rather than "yes".
> On first input, "y" may be interpreted as "yes" and trigger an "Incorrect entered information" prompt,
> requiring you to enter "y" again. This is the behavior of the `input_value_check` function in the script.

#### Interaction 3: Enter Installation Path

```
Enter the installation path. (The default path is /opt):
```

Press Enter to use the default path `/opt`, or enter a custom absolute path.

**Recommended input**: Enter (use default `/opt`)

> **Note**: You must use an absolute path; relative paths will be rejected.

#### Interaction 4: Enter Installation Port

```
Please enter the installation port (default: 8086):
```

Press Enter to use the default port 8086, or enter a custom port number (1-65535).

**Recommended input**: Enter (use default `8086`)

#### Interaction 5: Confirm Available Port

```
Port XXXX is available, do you want to use it? [y/N]:
```

The installation script asks whether to use a detected available port.

**Recommended input**: `y`

#### Interaction 6: Firewall Port Confirmation

```
Firewall port 'XXXX ' unavailable. You can authorize the tool to enable this port. Do you want to continue?[y/N]:
```

Appears when the firewall blocks a required port. Select y to authorize opening the port.

**Recommended input**: `y`

#### Interaction 7: Install Assembly Dependencies

```
Do you want to install the dependencies for assembly? (y/n default: y)
```

When the glibc version is lower than 2.28 (e.g., CentOS 7 defaults to glibc 2.17), the installation script automatically downloads and installs the glibc 2.28 RPM package for assembly functionality.

**Recommended input**: `y` (default value)

### 5.3 Expect Automation Script

```expect
#!/usr/bin/expect -f
set timeout 600
spawn bash install.sh -a
expect {
    "access mode for your installation" {
        send "1\r"
        exp_continue
    }
    "Do you want to authorize" {
        send "y\r"
        exp_continue
    }
    "Enter the installation path" {
        send "\r"
        exp_continue
    }
    "Please enter the installation port" {
        send "\r"
        exp_continue
    }
    "is available, do you want" {
        send "y\r"
        exp_continue
    }
    "Do you want to continue" {
        send "y\r"
        exp_continue
    }
    "Enter the serial number of the plug-in" {
        send "1,2,3,4,5,6\r"
        exp_continue
    }
    "select the number" {
        send "1\r"
        exp_continue
    }
    "Enter the serial number" {
        send "1\r"
        exp_continue
    }
    eof
}
```

#### Expect Script Key Points

1. **set timeout 600**: The installation process is lengthy; set a 10-minute timeout
2. **exp_continue**: After a match, continue waiting for the next interaction without exiting the expect block
3. **Match strings**: Select substrings that are specific enough but not duplicated for matching
4. **send "\r"**: Send Enter key (use \r instead of \n)

### 5.4 Non-Default Parameter Installation

#### Custom Installation Path

Modify the send value for "Enter the installation path" in the expect script:

```expect
"Enter the installation path" {
    send "/data/devkit\r"
    exp_continue
}
```

#### Custom Port

Modify the send value for "Please enter the installation port" in the expect script:

```expect
"Please enter the installation port" {
    send "9090\r"
    exp_continue
}
```

#### SSO Mode Installation

Modify the send value for the access mode in the expect script:

```expect
"access mode for your installation" {
    send "2\r"
    exp_continue
}
```

> **Note**: SSO mode requires additional OAuth2 authorization endpoint configuration. See the Kunpeng DevKit official documentation.

## 7. Installation Parameters and Reference Information

### 7.1 Installation Parameters

| Parameter | Default Value | Description |
|-----------|---------------|-------------|
| Install Path | `/opt` | DevKit installation root directory |
| HTTPS Port | `8086` | WebUI access port |
| HTTP Port | `8002` | Internal HTTP service port |
| gRPC Port | `50051` | RPC cluster service port, **on-demand** (automatically listens when a user starts a performance analysis task in the WebUI; not listening after installation is normal) |

| Access Mode | Username/Password | Mode 1 = username/password, Mode 2 = OAuth2 SSO |

### 7.2 Post-Installation Access

After successful installation, access the DevKit WebUI via a browser:

```
https://<server_ip>:8086
```

- On first access, you will be prompted about an untrusted certificate (self-signed certificate); choose to continue
- The root certificate is located at `/opt/DevKit/rsa/ca.crt` and can be imported into the browser to eliminate security warnings
- Default admin account: devadmin; the default password can be found in the installation log
