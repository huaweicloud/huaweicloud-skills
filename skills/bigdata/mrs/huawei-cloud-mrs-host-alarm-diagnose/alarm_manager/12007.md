# Process Fault (12007) Alarm Diagnosis Skill

## Diagnosis Flow
```
Step 1: Confirm the alarm and instance status
  |
  +-- Instance normal -> Check the monitoring metric trend
  +-- Instance abnormal -> Step 2
  Step 2: Check the host resource metrics
    |
    +-- Metric abnormal -> Resource bottleneck
    +-- Metric normal -> Step 3
```

## API Call Chain Dependencies
| Previous API | Return field | Next API | Parameter |
|-----------|---------|-----------|------|
| `start_log_search` | `task_id` | `get_log_search_progress` | `search_id` |
| `get_instances` | instance status | `get_host_process` | confirm whether the process exists |

---

## Diagnosis Steps
### Step 1: Confirm the alarm and instance status
```bash
# Query the current alarm list
python manager_api_client.py -a get_alarms --json
```

```bash
# Query the OMS instance status
python manager_api_client.py -a get_instances \
  -p 'cluster_id=<cluster_id>' \
  -p 'service_name=OMS' \
  --json
```

```bash
# Query the host process status
python manager_api_client.py -a get_host_process \
  -p 'hostname=<node_name>' \
  --json
```

**Analysis**:

| Actual result | Conclusion | Next step |
|----------|------|--------|
| Instance status normal | The alarm may have been cleared or it is a metric-type alarm | Step 2 |
| Instance status abnormal | The service is abnormal | Step 2 |
| A related alarm exists | Handle the related alarm first | Refer to the corresponding alarm diagnosis |

---
### Step 2: Check the host resource metrics
```bash
# Query the host monitoring metrics
python manager_api_client.py -a get_host_metrics \
  -p 'hostname=<node_name>' \
  -p 'metric_names=dev_cpu_surp_avg,dev_load_one_min' \
  --json
```

```bash
# Query the host resource information
python manager_api_client.py -a get_host_resource \
  -p 'hostname=<node_name>' \
  --json
```

**Analysis**:

| Actual result | Conclusion |
|----------|------|
| Metric abnormal | The alarm is caused by a resource bottleneck |
| Metric normal | Continue with the log troubleshooting |

---

## Common Root Causes and Repair Suggestions

### 1. Resource metric exceeds the threshold

**Repair suggestions**:
- Handle the specific metric that exceeded the threshold accordingly
- Clean up resources or expand capacity

### 2. Insufficient disk space

**Features**: The log contains `no space left` / `No space left on device`

**Repair suggestions**:
- Clean up log files and temporary files
- Expand the disk

### 3. Configuration or file permission exception

**Features**: The log contains `Permission denied` / `cannot open`

**Repair suggestions**:
- Check the permissions of the related files
- After fixing the permissions, wait for 5 minutes

### 4. Network or connectivity issue

**Features**: The log contains `connection refused` / `timeout`

**Repair suggestions**:
- Check network connectivity between nodes
- Use the `check_remote` API to test the reachability of the remote node
