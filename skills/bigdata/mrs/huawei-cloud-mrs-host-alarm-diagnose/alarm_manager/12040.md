# Insufficient System Entropy (12040) Alarm Diagnosis Skill

## Diagnosis Flow

```
Step 1: Obtain alarm information and confirm the alarm
  │
  ▼
Step 2: Check whether haveged is installed and running
  │
  ├─ haveged not installed → Root cause: haveged tool not installed
  ├─ haveged installed but service not running → Root cause: haveged service not started
  └─ haveged installed and running → Step 3

Step 3: Check whether rng-tools is installed and running
  │
  ├─ rng-tools not installed → Root cause: rng-tools not installed
  ├─ rng-tools installed but service not running → Root cause: rngd service not started
  └─ rng-tools installed and running → Step 4

Step 4: Check the system entropy value
  │
  ├─ Entropy < 100 → Root cause: system entropy insufficient
  └─ Entropy >= 100 → Alarm may have recovered

> After locating the root cause, jump directly to "Common Root Causes and Repair Suggestions"; no need to continue with the subsequent steps.
```

## Diagnosis Steps

### Step 1: Obtain alarm information and confirm the alarm

```bash
# Query the current alarm list (focus on the node information of the 12040 alarm)
python manager_api_client.py -a get_alarms -p 'id=12040' --json
```

> For MRS 3.2.0 and later versions, the system performs an alarm check every five minutes. It first checks whether rng-tools or haveged is enabled and correctly configured.
> If not configured, a fault alarm is sent; otherwise, it continues to check the entropy value. If the results of five consecutive checks are all less than 100, a fault alarm is reported.

---

### Step 2: Check whether haveged is installed and running

```bash
# Query the alarm node process list and look for the haveged process
python manager_api_client.py -a get_host_process \
  -p 'hostname=<node_name>' \
  --json
```

> In the returned process list, look for `haveged` related processes.

> **The Manager API cannot directly check file and service status. Manually execute on the alarm node:**
> ```bash
> # Check whether haveged is installed
> ls -l /usr/sbin/haveged
> # Or
> which haveged
>
> # Check the haveged service status
> systemctl status haveged
> ```
> If haveged is not installed (command result is empty), it means the haveged tool is not installed;
> if it is installed but the service status is inactive/stopped, it means the service is not started.

**Analysis**:

| Actual result | Conclusion | Next step |
|----------|------|--------|
| haveged not installed | **Root cause located**: haveged tool not installed → Root cause 1 | — |
| haveged installed but service not running | **Root cause located**: haveged service not started → Root cause 2 | — |
| haveged installed and running | Continue checking rng-tools | Step 3 |

---

### Step 3: Check whether rng-tools is installed and running

> **The Manager API cannot directly check package and service status. Manually execute on the alarm node:**
> ```bash
> # Check whether rng-tools is installed
> rpm -qa | grep rng-tools
> # Or
> ls -l /usr/sbin/rngd
>
> # Check the rngd service status
> systemctl status rngd
> ```

**Analysis**:

| Actual result | Conclusion | Next step |
|----------|------|--------|
| rng-tools not installed | **Root cause located**: rng-tools not installed → Root cause 3 | — |
| rng-tools installed but service not running | **Root cause located**: rngd service not started → Root cause 4 | — |
| rng-tools installed and running | Continue checking the entropy value | Step 4 |

---

### Step 4: Check the system entropy value

> **The Manager API cannot directly query the system entropy value. Manually execute on the alarm node:**
> ```bash
> # View the current system entropy value
> cat /proc/sys/kernel/random/entropy_avail
> # Check multiple times and take the average
> for i in $(seq 1 5); do cat /proc/sys/kernel/random/entropy_avail; sleep 1; done
> ```
> If the entropy value is consistently less than 100, the system entropy is indeed insufficient; if the entropy value is greater than or equal to 100, the alarm may have recovered.

**Analysis**:

| Actual result | Conclusion | Next step |
|----------|------|--------|
| Entropy consistently < 100 | **Root cause located**: system entropy insufficient → Root cause 5 | — |
| Entropy >= 100 | Alarm may have recovered | Check whether the alarm is automatically cleared |

---

### Step 5: Check entropy check logs

```bash
# Search entropy check script logs (Agent role entropycheck category)
python manager_api_client.py -a start_log_search \
  -p 'cluster_id=<cluster_id>' \
  -p 'key_word=entropy' \
  -p 'start_time=<alarm_time>' \
  -p 'end_time=<current_time>' \
  -p 'services=Manager:Manager:Agent' \
  -p 'min_log_level=WARN' \
  -p 'log_file_name=entropycheck.log' \
  --json

# Check search progress and results
python manager_api_client.py -a get_log_search_progress \
  -p 'search_id=<task_id>' \
  --json
```

> To search for multiple keywords (such as `fail`, `rng-tools`, `haveged`, `below`), you can perform multiple searches.

**Log keyword analysis**:

| Log keyword | Conclusion | Next step |
|-----------|------|--------|
| `rng-tools` / `haveged` + `not found` / `fail` | Entropy tool not correctly configured | Confirm with Step 2/3 |
| `entropy` + `below` / `< 100` | Entropy consistently insufficient | Root cause 5 |
| No obvious error | No clear error | Collect fault logs and contact O&M |

## Common Root Causes and Repair Suggestions

### 1. haveged tool not installed

**Features**: The /usr/sbin/haveged file does not exist; the haveged process is not running

**Repair suggestions**:
- Install the haveged tool: `yum install haveged` or `apt-get install haveged`
- Start the haveged service: `systemctl start haveged`
- Set auto-start on boot: `systemctl enable haveged`
- Wait for the next system detection (5 minutes) and check whether the alarm is automatically cleared

### 2. haveged service not started

**Features**: haveged is installed but the service status is inactive/stopped

**Repair suggestions**:
- Start the haveged service: `systemctl start haveged`
- Set auto-start on boot: `systemctl enable haveged`
- Wait for the next system detection and check whether the alarm is automatically cleared

### 3. rng-tools not installed

**Features**: The rng-tools package is not installed; the rngd process is not running

**Repair suggestions**:
- Install rng-tools: `yum install rng-tools`
- Configure rngd to use the hardware random number generator
- Start the rngd service: `systemctl start rngd`
- Set auto-start on boot: `systemctl enable rngd`
- Wait for the next system detection and check whether the alarm is automatically cleared

### 4. rngd service not started

**Features**: rng-tools is installed but the rngd service status is inactive/stopped

**Repair suggestions**:
- Start the rngd service: `systemctl start rngd`
- Set auto-start on boot: `systemctl enable rngd`
- Wait for the next system detection and check whether the alarm is automatically cleared

### 5. System entropy consistently insufficient

**Features**: Both haveged and rng-tools are installed and running, but the entropy value remains consistently below 100

**Repair suggestions**:
- Check haveged/rngd service logs: `journalctl -u haveged` / `journalctl -u rngd`
- Restart the haveged/rngd services
- If this is a virtual machine environment, confirm whether the VM supports a hardware random number generator (virtio-rng)
- Consider enabling the virtio-rng device in the VM configuration
- If the problem persists, collect fault logs and contact O&M personnel
