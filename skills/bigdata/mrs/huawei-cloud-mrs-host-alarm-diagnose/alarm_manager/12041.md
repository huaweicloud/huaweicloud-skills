# Critical File Permission Anomaly (12041) Alarm Diagnosis Skill

## Diagnosis Flow
```
Step 1: Confirm alarm and instance status
  |
  +-- Instance normal -> Check monitoring metric trend
  +-- Instance abnormal -> Step 2
Step 2: Check host resource metrics
  |
  +-- Metric abnormal -> Resource bottleneck
  +-- Metric normal -> Step 3
Step 3: In-depth log troubleshooting
Step 4: Manually confirm system logs
```

## API Call Chain Dependencies
| Previous API | Return fields | Next API | Parameters |
|-----------|---------|-----------|------|
| `start_log_search` | `task_id` | `get_log_search_progress` | `search_id` |
| `get_instances` | Instance status | `get_host_process` | Confirm whether the process exists |

## Diagnosis Steps
### Step 1: Confirm alarm and instance status
```bash
# Query the current alarm list
python manager_api_client.py -a get_alarms --json
```

```bash
# Query the OMS instance status
python manager_api_client.py -a get_instances \
  -p 'cluster_id=<cluster_id>' \
  -p 'service_name=OMS' \
  --json
```

```bash
# Query the host process status
python manager_api_client.py -a get_host_process \
  -p 'hostname=<node_name>' \
  --json
```

**Analysis**:

| Actual result | Conclusion | Next step |
|----------|------|--------|
| Instance status normal | The alarm may have recovered or be a metric-based alarm | Step 2 |
| Instance status abnormal | Service abnormal | Step 2 |
| Correlated alarms exist | Handle the correlated alarm first | Refer to the corresponding alarm diagnosis |

## Common Root Causes and Repair Suggestions

### 1. Resource metric exceeds threshold

**Repair suggestions**:
- Handle the specific over-threshold metric accordingly
- Clean up resources or expand capacity

### 2. Insufficient disk space

**Feature**: The log contains `no space left` / `No space left on device`

**Repair suggestions**:
- Clean up log files and temporary files
- Expand disk capacity

### 3. Configuration or file permission anomaly

**Feature**: The log contains `Permission denied` / `cannot open`

**Repair suggestions**:
- Check the permissions of the related files
- Wait 5 minutes after fixing the permissions

### 4. Network or connectivity issue

**Feature**: The log contains `connection refused` / `timeout`

**Repair suggestions**:
- Check network connectivity between nodes
- Use the `check_remote` API to test the reachability of the remote node
