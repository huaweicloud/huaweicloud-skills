# Disk Capacity Insufficient (12017) Alarm Diagnosis Skill

## Diagnosis Flow
```
Step 1: Confirm the alarm and instance status
  |
  +-- Instance normal -> check monitoring metric trend
  +-- Instance abnormal -> Step 2
  Step 2: Check host resource metrics
    |
    +-- Metric abnormal -> resource bottleneck
    +-- Metric normal -> Step 3
  Step 3: In-depth log investigation
  Step 4: Manually confirm system logs
```

## API Call Chain Dependencies
| Previous-step API | Return field | Next-step API | Parameter |
|-------------------|--------------|---------------|-----------|
| `start_log_search` | `task_id` | `get_log_search_progress` | `search_id` |
| `get_instances` | Instance status | `get_host_process` | Confirm whether the process exists |

---

## Diagnosis Steps
### Step 1: Confirm the alarm and instance status
```bash
# Query the current alarm list
python manager_api_client.py -a get_alarms --json
```

```bash
# Query the OMS instance status
python manager_api_client.py -a get_instances \
  -p 'cluster_id=<cluster_id>' \
  -p 'service_name=OMS' \
  --json
```

```bash
# Query the host process status
python manager_api_client.py -a get_host_process \
  -p 'hostname=<node_name>' \
  --json
```

**Analysis**:

| Actual result | Conclusion | Next step |
|---------------|------------|-----------|
| Instance status normal | The alarm may have recovered or is a metric-type alarm | Step 2 |
| Instance status abnormal | Service abnormal | Step 2 |
| Companion alarm present | Handle the companion alarm first | Refer to the corresponding alarm diagnosis |

---
### Step 2: Check host resource metrics
```bash
# Query host monitoring metrics
python manager_api_client.py -a get_host_metrics \
  -p 'hostname=<node_name>' \
  -p 'metric_names=dev_disk_useage,dev_host_disk_usage,dev_disk_util' \
  --json
```

```bash
# Query host resource information
python manager_api_client.py -a get_host_resource \
  -p 'hostname=<node_name>' \
  --json
```

**Analysis**:

| Actual result | Conclusion |
|---------------|------------|
| Metric abnormal | The alarm is caused by a resource bottleneck |
| Metric normal | Continue the log investigation |

---
### Step 3: In-depth log investigation

#### 3.1 Controller log (disk-insufficient type errors)

```bash
# First obtain the exact log file name
python manager_api_client.py -a get_log_filename \
  -p 'hostname=<node_name>' \
  -p 'category_name=controller' \
  -p 'path=/var/log/Bigdata/controller' \
  --json
```

```bash
# Browse the Controller log (using the exact file name)
python manager_api_client.py -a browse_log \
  -p 'hostname=<node_name>' \
  -p 'file_name=/var/log/Bigdata/controller/controller.log' \
  -p 'start_line=1' \
  -p 'end_line=200' \
  --json
```

```bash
# Search for log keywords
python manager_api_client.py -a start_log_search \
  -p 'cluster_id=<cluster_id>' \
  -p 'key_word=No space left on device' \
  -p 'start_time=<alarm_time>' \
  -p 'end_time=<current_time>' \
  -p 'services=Manager:Manager:Controller' \
  -p 'min_log_level=WARN' \
  -p 'log_file_name=controller.log' \
  --json

# Check the search progress
python manager_api_client.py -a get_log_search_progress \
  -p 'search_id=<task_id>' \
  --json
```

**Keyword analysis**:

| Log keyword | Conclusion |
|-------------|------------|
| No space left on device / disk full / I/O error / Read-only file system | The corresponding root cause is given in Common Root Causes and Repair Suggestions |
| None of the above keywords | No abnormality in this log |


---
### Step 4: Manually confirm system logs

> **The Manager API cannot directly access system log directories (such as /var/log/messages, etc.). You must manually execute this on the alarm node:**
> - View the keywords in `/var/log/messages*`: No space left on device / disk full / I/O error / Read-only file system

## Common Root Causes and Repair Suggestions

### 1. Resource metric exceeds the threshold

**Repair suggestions**:
- Handle it specifically according to the metric that exceeds the threshold
- Clear resources or expand capacity

### 2. Insufficient disk space

**Features**: `no space left` / `No space left on device` appears in the logs

**Repair suggestions**:
- Clear log files and temporary files
- Expand the disk

### 3. Abnormal configuration or file permissions

**Features**: `Permission denied` / `cannot open` appears in the logs

**Repair suggestions**:
- Check the permissions of the relevant files
- Wait 5 minutes after fixing the permissions

### 4. Network or connectivity problem

**Features**: `connection refused` / `timeout` appears in the logs

**Repair suggestions**:
- Check the network connectivity between nodes
- Use the `check_remote` interface to test the reachability of the remote node
