# NodeAgent Process Exception (12006) Alarm Diagnosis Skill

## Diagnosis Flow
```
Step 1: Confirm the alarm and instance status
  |
  +-- Process normal -> Check historical logs
  +-- Related alarm present -> Handle the related alarm first
  +-- Process abnormal -> Step 2
  Step 2: In-depth log troubleshooting
```

## API Call Chain Dependencies
| Previous API | Return field | Next API | Parameter |
|-----------|---------|-----------|------|
| `start_log_search` | `task_id` | `get_log_search_progress` | `search_id` |
| `get_instances` | instance status | `get_host_process` | confirm whether the process exists |

---

## Diagnosis Steps
### Step 1: Confirm the alarm and instance status
```bash
# Query the current alarm list
python manager_api_client.py -a get_alarms --json
```

```bash
# Query the NodeAgent instance status
python manager_api_client.py -a get_instances \
  -p 'cluster_id=<cluster_id>' \
  -p 'service_name=NodeAgent' \
  --json
```

```bash
# Query the process status on the alarm node
python manager_api_client.py -a get_host_process \
  -p 'hostname=<node_name>' \
  --json
```

> Look for the `NodeAgent`-related processes in the process list to confirm whether the process exists.

**Analysis**:

| Actual result | Conclusion | Next step |
|----------|------|--------|
| The NodeAgent process exists and its status is normal | The alarm may have been cleared | Check historical logs |
| The NodeAgent process does not exist | The process is not running | Step 2 |
| A related alarm exists (ALM-12006/12017, etc.) | Handle the related alarm first | Refer to the corresponding alarm diagnosis |

### Step 2: In-depth log troubleshooting

#### 2.1 agent log

```bash
# First obtain the exact log file name
python manager_api_client.py -a get_log_filename \
  -p 'hostname=<node_name>' \
  -p 'category_name=agent' \
  -p 'path=/var/log/Bigdata/nodeagent/agentlog' \
  --json
```

```bash
# Browse the agent log (using the exact file name)
python manager_api_client.py -a browse_log \
  -p 'hostname=<node_name>' \
  -p 'file_name=/var/log/Bigdata/nodeagent/agentlog/agent.log' \
  -p 'start_line=1' \
  -p 'end_line=200' \
  --json
```

```bash
# Search the log for keywords
python manager_api_client.py -a start_log_search \
  -p 'cluster_id=<cluster_id>' \
  -p 'key_word=ERROR' \
  -p 'start_time=<alarm_time>' \
  -p 'end_time=<current_time>' \
  -p 'services=Manager:Manager:Agent' \
  -p 'min_log_level=ERROR' \
  -p 'log_file_name=agent.log' \
  --json

# View the search progress
python manager_api_client.py -a get_log_search_progress \
  -p 'search_id=<task_id>' \
  --json
```

**Keyword analysis**:

| Log keyword | Conclusion |
|-----------|------|
| ERROR / Exception /  OutOfMemoryError / Out of memory | See the corresponding root cause in Common Root Causes and Repair Suggestions |
| None of the above keywords | No exception in this log |

## Common Root Causes and Repair Suggestions

### 1. NodeAgent process exception

**Repair suggestions**:
- Restart the NodeAgent service via the Manager UI
- Before restarting, check the logs to locate the cause of the crash
- The restart will briefly affect related services

### 2. Insufficient disk space

**Features**: The log contains `no space left` / `No space left on device`

**Repair suggestions**:
- Clean up log files and temporary files
- Expand the disk

### 3. Configuration or file permission exception

**Features**: The log contains `Permission denied` / `cannot open`

**Repair suggestions**:
- Check the permissions of the related files
- After fixing the permissions, wait for 5 minutes

### 4. Network or connectivity issue

**Features**: The log contains `connection refused` / `timeout`

**Repair suggestions**:
- Check network connectivity between nodes
- Use the `check_remote` API to test the reachability of the remote node
