# Failed to Obtain ECS Temporary AK/SK (12110) Alarm Diagnosis Skill

## Diagnosis Flow
```
Step 1: Confirm alarm and instance status
  |
  +-- Instance normal -> Check monitoring metric trends
  +-- Instance abnormal -> Step 2
  Step 2: In-depth log troubleshooting
```

## API Call Chain Dependencies
| Previous API | Returned field | Next API | Parameter |
|-----------|---------|-----------|------|
| `start_log_search` | `task_id` | `get_log_search_progress` | `search_id` |
| `get_instances` | Instance status | `get_host_process` | Confirm whether the process exists |

---

## Diagnosis Steps
### Step 1: Confirm alarm and instance status
```bash
# Query the current alarm list
python manager_api_client.py -a get_alarms --json
```

```bash
# Query OMS instance status
python manager_api_client.py -a get_instances \
  -p 'cluster_id=<cluster_id>' \
  -p 'service_name=OMS' \
  --json
```

```bash
# Query host process status
python manager_api_client.py -a get_host_process \
  -p 'hostname=<node_name>' \
  --json
```

**Analysis**:

| Actual result | Conclusion | Next step |
|----------|------|--------|
| Instance status normal | The alarm may have recovered or is a metric-type alarm | Step 2 |
| Instance status abnormal | Service exception | Step 2 |
| Companion alarm exists | Handle the companion alarm first | Refer to the corresponding alarm diagnosis |

### Step 2: In-depth log troubleshooting

#### 2.1 mrs-meta.log

```bash
# Browse mrs-meta.log
python manager_api_client.py -a browse_log \
  -p 'hostname=<node_name>' \
  -p 'file_name=/var/log/Bigdata/meta/mrs-meta.log' \
  -p 'start_line=1' \
  -p 'end_line=200' \
  --json
```

```bash
# Search log keywords
python manager_api_client.py -a start_log_search \
  -p 'cluster_id=<cluster_id>' \
  -p 'key_word=AK' \
  -p 'start_time=<alarm_time>' \
  -p 'end_time=<current_time>' \
  -p 'services=Manager:Manager:meta' \
  -p 'min_log_level=WARN' \
  -p 'log_file_name=mrs-meta.log' \
  --json

# View search progress
python manager_api_client.py -a get_log_search_progress \
  -p 'search_id=<task_id>' \
  --json
```

**Keyword analysis**:

| Log keyword | Conclusion |
|-----------|------|
| AK / SK / failed / expired / 403 / 401 / Connection refused / timed out / agency / delegation / OBS | See Common Root Causes and Repair Suggestions for the corresponding root cause |
| None of the above keywords | No exception in this log |

## Common Root Causes and Repair Suggestions

### 1. AK/SK expired or deleted

**Features**: Logs contain `expired` / `InvalidAccessKeyId` / `SignatureDoesNotMatch` / `403`

**Repair suggestions**:
- Log in to the Huawei Cloud console and check whether the temporary AK/SK used by the ECS agency is within its validity period
- If the AK/SK has expired, re-create the agency in IAM or refresh the temporary credentials
- Check the agency configuration (`agency`): confirm the agency name and permissions (OBS access permissions) are configured correctly
- After the configuration is updated, restart the meta service to apply the new credentials

### 2. ECS metadata service unreachable

**Features**: Logs contain `Connection refused` / `timed out` / `Failed to get token`; the meta service cannot obtain temporary credentials from the ECS metadata service

**Repair suggestions**:
- Execute `curl http://169.254.169.254/latest/meta-data/iam/security-credentials/` manually on the OMS/meta node to verify that the ECS metadata service is reachable
- If unreachable, check whether the ECS is an IAM agency instance (an agency must be configured in the console before temporary AK/SK can be obtained)
- Check the network route from the node to the ECS metadata service

### 3. Agency permission configuration error

**Features**: Logs contain `access denied` / `unauthorized` / `invalid_grant`

**Repair suggestions**:
- Check whether the authorization scope (global/region-level) of the IAM agency covers the current region
- Confirm that the policies bound to the agency include OBS-related permissions
- If it is a custom agency, add the required permissions such as `OBS Bucket Viewer` in IAM
- After updating the agency configuration, wait for the next credential refresh cycle (approximately 1 hour)
