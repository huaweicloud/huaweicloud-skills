# NodeAgent Process Exception Alarm Diagnosis

## 1. Diagnosis Introduction

This content mainly handles the diagnosis and handling of the **NodeAgent Process Exception (12006)** alarm. The Controller detects NodeAgent heartbeat in a 30-second cycle. When the heartbeat of a NodeAgent is not received, it attempts to restart the NodeAgent process. If three consecutive restart attempts fail, this alarm is generated. The handling process is summarized according to the official alarm documentation.

Alarm basic information:

| Item | Content |
|------|------|
| Alarm ID | 12006 |
| Alarm name | NodeAgent process exception |
| Alarm severity | Important |
| Alarm type | Service quality alarm |
| Auto-clearable | Yes |
| System impact | NodeAgent agent process exception, unable to report heartbeat to the platform |

## 3. Common Alarm Fault Handling Solutions

### 3.1 Network disconnection / hardware failure

**Symptom**: Alarm node cannot be pinged, NodeAgent heartbeat interrupted

**Handling solution**:
1. Contact the network administrator to troubleshoot network faults
2. Contact the hardware administrator to check node hardware (CPU, memory, etc.)
3. After confirming the fault is recovered, verify that the alarm is auto-cleared

### 3.2 NodeAgent process insufficient memory

**Symptom**: GC logs show frequent Full GC or memory usage remains high

**Handling solution**:
1. Modify the memory parameters in the `$NODE_AGENT_HOME/etc/agent/nodeagent.properties` file
   - `nodeagent.Xms` - initial heap memory
   - `nodeagent.Xmx` - maximum heap memory
2. Restart the Agent service:
   ```bash
   sh ${BIGDATA_HOME}/om-agent/nodeagent/bin/stop-agent.sh
   sh ${BIGDATA_HOME}/om-agent/nodeagent/bin/start-agent.sh
   ```

### 3.3 NodeAgent process fault

**Symptom**: Process does not exist or terminated abnormally

**Handling solution**:
1. View the Agent runtime logs to troubleshoot the cause: `/var/log/Bigdata/nodeagent/agentlog/agent.log`
2. View the Agent start/stop logs: `/var/log/Bigdata/nodeagent/scriptlog/nodeagent_ctl.log`
3. Restart the Agent service:
   ```bash
   sh ${BIGDATA_HOME}/om-agent/nodeagent/bin/stop-agent.sh
   sh ${BIGDATA_HOME}/om-agent/nodeagent/bin/start-agent.sh
   ```

### 3.4 SSH port configuration inconsistency (physical machine cluster)

**Symptom**: `ssh: connect to host <master node ip> port <port number>: Connection refused`

**Handling solution**:
1. Check the Port setting in `/etc/ssh/sshd_config` and `/etc/ssh/ssh_config` on the faulty host
2. Ensure consistency with the master node configuration
3. Restart the sshd service:
   ```bash
   service sshd restart
   ```
