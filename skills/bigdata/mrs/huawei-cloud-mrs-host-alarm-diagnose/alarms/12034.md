# `Periodic Backup Task Failure` (12034) Alarm Diagnosis Skill

## 1. Diagnosis Overview

This document primarily covers the diagnosis and handling of the **Periodic Backup Task Failure (12034)** alarm. The system executes periodic backup tasks every 60 minutes. If a backup task fails, this alarm is reported. When the next backup execution succeeds, the alarm is cleared.

Alarm basic information:

| Item | Description |
|------|------|
| Alarm ID | 12034 |
| Alarm Name | Periodic Backup Task Failure |
| Alarm Severity | Important |
| Alarm Type | Backup Recovery Monitoring |
| Auto-cleared | Yes |
| System Impact | No available backup packages during the backup failure period; data from that period cannot be recovered if a system abnormality occurs |

## 2. Executable Operations

This section provides the relevant operations that can be executed during the alarm analysis process.

### 2.1 Obtain Cluster OMS Active/Standby Node Information

```bash
python3 lakewatch_api_client.py -a query-management-node-info \
  -p 'cluster_id=<cluster_id>'
```

Parameter description:
- `<cluster_id>`: Cluster ID

### 2.2 Check OMS Node Disk Space

Execute the following command to check whether the OMS active node has sufficient disk space. If disk usage is near 100%, backup tasks may fail.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=disk-space' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: OMS active node name

### 2.3 Obtain OMS Key Directories

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=oms_core_dir' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: OMS active node name

### 2.4 Collect Controller Backup Logs

Execute the following command to collect backup recovery-related logs and search for backup failure keywords.

```bash
python3 lakewatch_api_client.py -a collect_alarm_log_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'alarm_time=<alarm_time>' \
  -p 'alarm_duration_minutes=30' \
  -p 'log_directory=/var/log/Bigdata/controller/backup' \
  -p 'log_file_name=backupplugin*.log' \
  -p 'keywords=["Upload backup files","file failed","insufficient disk space","backup"]' \
  -p 'log_type=local' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<alarm_time>`: Alarm trigger time
- `<node_name>`: OMS active node name

### 2.5 Collect Controller Business Logs

```bash
python3 lakewatch_api_client.py -a collect_alarm_log_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'alarm_time=<alarm_time>' \
  -p 'alarm_duration_minutes=30' \
  -p 'log_directory=/var/log/Bigdata/controller' \
  -p 'log_file_name=controller.log*' \
  -p 'keywords=["ERROR","exception","backup","failed"]' \
  -p 'log_type=local' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<alarm_time>`: Alarm trigger time
- `<node_name>`: OMS active node name

## 3. Non-Executable Operations

This section provides operations that cannot be executed through the tool during the alarm analysis process (i.e., commands that require manual login to the Manager UI or node).

### 3.1 View Backup Recovery Logs

Log in to the OMS active node as the root user and view the backup recovery logs:

```bash
cd /var/log/Bigdata/controller/backup/
ll
```

View the log file list, then view the specific log content:

```bash
vi backupplugin.log
```

Search for the following keywords:
- `Upload backup files to *** file failed` — Backup file upload failed
- `insufficient disk space` — Insufficient disk space
- `Failed to backup` — Backup failed

### 3.2 View Backup Task Configuration

In the FusionInsight Manager UI, select "Maintenance > Backup & Restore > Backup Management". Find the corresponding backup task based on the "Task Name" in the alarm location information, click "Configure" in the "Operation" column, and check whether the configuration items are correct.

### 3.3 View Backup Path Disk Space

Log in to the node where the backup path is located as the root user and execute the following command to view the remaining space of the backup path mount point:

```bash
df -h
```

In the mount details, check whether the remaining space of the backup path mount point is less than 20 GB.

### 3.4 Clean Up Backup Directory

If the backup directory has a large number of old backup packages causing insufficient space, execute the following command to clean up:

```bash
# View backup packages in the backup directory
ls -lt /srv/BigData/LocalBackup/

# Remove or delete old backup packages
rm -rf /srv/BigData/LocalBackup/<old_backup_package_directory_name>
```

- `<old_backup_package_directory_name>`: The backup package directory name to be cleaned

### 3.5 Immediate Backup Verification

In the FusionInsight Manager UI, select "Maintenance > Backup & Restore > Backup Management". On the right side of the backup task to be operated, select "More > Immediate Backup" to manually start the backup task and check whether it executes successfully.

### 3.6 Collect Fault Information

In the FusionInsight Manager UI, select "Maintenance > Logs > Download". In "Services", select "Controller". Set the log collection "Start Time" and "End Time" to 10 minutes before and after the alarm generation time, then click "Download". Contact operations personnel and send the collected fault log information.

## 4. Common Fault Repair Solutions

### 4.1 Insufficient Backup Path Disk Space

**Symptoms**:
- "insufficient disk space" or "Upload backup files to *** file failed" appears in backup logs
- Backup path mount point remaining space is less than 20 GB
- Large number of historical backup packages in the backup directory

**Repair solution**:
1. View the remaining space of the backup path mount point
2. Clean up unnecessary old backup packages until remaining space exceeds 20 GB
3. Modify "Maximum Backup Count" in the Manager UI to reduce the number of backup file sets
4. Manually start an immediate backup to verify whether it succeeds

### 4.2 Backup Configuration Item Error

**Symptoms**:
- Backup task configuration items are incorrect
- Immediate backup execution fails

**Repair solution**:
1. Check the task configuration in the Manager backup management page
2. Correct the configuration items and save
3. Manually start an immediate backup for verification

### 4.3 Network or Storage Unreachable

**Symptoms**:
- Backup logs show upload failure but not a disk space issue
- Remote backup server is unreachable

**Repair solution**:
1. Check network connectivity from the OMS node to the backup server
2. Check the backup server storage space
3. Check the backup server access permissions

### 4.4 Emergency System Recovery

**Scenario**: Backup tasks continue to fail; the system cannot produce available backup packages

**Repair solution**:
1. Confirm the OMS active node status; if active/standby switchover is needed:
   - Log in to the active OMS node as the omm user
   - Execute the active/standby switchover command: `${OMS_RUN_PATH}/workspace/ha/module/hacom/tools/ha_client_tool --ip=127.0.0.1 --port=20013 --switchover --name=product`
2. After active/standby switchover, re-execute the backup task
3. Collect Controller logs and contact operations personnel

## 5. Alarm Diagnosis Flow

### 5.1 Diagnosis Flow Diagram

```
Start
  |
  v
Obtain task name and OMS active node information from alarm information
  |
  v
Check OMS node disk space (disk-space)
  |
  +--- Disk usage near 100% ---> Clean up backup directory ---> Immediate backup verification
  |                                        |
  |                                        +--- Success ---> End
  |                                        |
  |                                        +--- Failure ---> Check backup configuration
  |
  +--- Disk space sufficient ---> Collect backup logs (backupplugin.log)
                           |
                           +--- Contains "insufficient disk space" ---> Clean up backup directory
                           |
                           +--- Contains "Upload backup files failed" ---> Check backup path space
                           |
                           +--- No clear error ---> Check backup task configuration
                                                  |
                                                  +--- Configuration incorrect ---> Correct configuration
                                                  |
                                                  +--- Configuration correct ---> Immediate backup verification
                                                                                   |
                                                                                   +--- Success ---> End
                                                                                   |
                                                                                   +--- Failure ---> Collect logs
  |
  v
End (alarm cleared)
```

### 5.2 Diagnosis Conclusion Output

Based on the diagnosis flow above, output one of the following diagnosis conclusions:

| Diagnosis conclusion | Recommended action |
|----------|----------|
| Insufficient backup path disk space | Clean up old backup packages, expand storage space |
| Backup configuration item error | Correct backup task configuration in Manager |
| Network/storage unreachable | Check network connectivity and backup server status |
| Backup service abnormality | Restart backup service or perform active/standby switchover then retry |
| Alarm still persists after processing | Collect Controller logs, contact operations personnel |
