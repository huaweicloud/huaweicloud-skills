## 2. Log Directory

### 2.1 Log Priority

> When analyzing cluster user conflicts, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |----------|----------|-------------|
> | 1 | System log | System-level user operation logs |
> | 2 | OmmServer log | Manager user management logs |
> | 3 | NodeAgent log | User detection logs |

### 2.2 Log Paths

| Log File | Path | Purpose | Priority |
|----------|------|---------|----------|
| System log | `/var/log/messages` | System-level user operation logs | 1 |
| OmmServer log | `${BIGDATA_LOG_HOME}/omserver/` | Manager user management logs | 2 |
| NodeAgent log | `${BIGDATA_LOG_HOME}/nodeagent/` | User detection logs | 3 |
| User file | `/etc/passwd` | Operating system user list | 4 |

## 3. Log Time Format

### 3.1 System Log Format

```
Dec 20 10:30:15 hostname process_name[pid]: message
```

| Field | Description | Example |
|-------|-------------|---------|
| Date time | Month Day Hour:Minute:Second | `Dec 20 10:30:15` |
| Hostname | Host name | `hostname` |
| Process info | Process name and PID | `process_name[pid]` |
| Message content | Log body | `message` |

## 7. Common Root Causes and Repair Solutions

| Root Cause | Characteristics | Repair Solution |
|------------|----------------|-----------------|
| Manager user has same name as OS user | A system user with the same name as a Manager-created user exists in `/etc/passwd` | Based on the user list in the alarm additional information, delete the conflicting OS user or Manager user |
| OS user added later | An OS user with the same name as a Manager user was manually added on the node before the alarm occurred | Delete the subsequently added OS user: `userdel <username>` |
| Manager user created later | A Manager user with the same name as an existing OS user was created in Manager before the alarm occurred | Delete the Manager user or rename the OS user |
| Multiple conflicting users | Multiple usernames (space-separated) in the alarm additional information | Analyze and delete conflicting users one by one |
| Residual users not cleaned | OS users left after node reinstall or recovery | Clean up residual users, wait for the next detection cycle (2 hours) for the alarm to auto-clear |

### Conflicting User Handling Process

1. Obtain the conflicting user list from the alarm additional information (multiple users are space-separated)
2. Log in to the alarm host as the omm user
3. Execute `cut -d: -f1 /etc/passwd` to obtain the OS user list
4. Compare and confirm the conflicting users
5. Analyze and confirm whether to delete the OS user or the Manager user
6. Execute the deletion operation
7. Wait for the next detection cycle (2 hours) to confirm alarm recovery
