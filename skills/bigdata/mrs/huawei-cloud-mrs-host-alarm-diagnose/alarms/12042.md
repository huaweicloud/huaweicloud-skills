# Key File Configuration Anomaly Log Information Description

## I. Alarm Type

| Item | Content |
|------|------|
| Alarm Name | Key File Configuration Anomaly |
| Alarm ID | 12042 |
| Alarm Type | File Configuration Monitoring |
| Alarm Severity | Important (2) |
| Detection Script | check_ssh_cfg.sh / check_hosts.sh / check_fstab.sh / check_client.sh |

---

## II. Log Directory

### 2.1 Log Priority

> When analyzing key file configuration anomalies, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |--------|----------|------|
> | 1 | NodeAgent Check Log | Detection script execution log, contains configuration check error details |
> | 2 | System Log | System-level configuration related log information |

### 2.2 Log Path

| Log File | Path | Purpose | Priority |
|----------|------|------|--------|
| NodeAgent Check Log | `${BIGDATA_LOG_HOME}/nodeagent/scriptlog/checkfileconfig.log` | Detection script execution log, contains configuration check error details | 1 |
| System Log | `/var/log/messages*` | System-level configuration related log information | 2 |

## III. Log Time Format

### 3.1 Format A: Space-separated format (NodeAgent Check Log)

```
2026-05-08 11:20:00 hostname checkfileconfig[pid]: message
```

| Field | Description | Example |
|------|------|------|
| Date and Time | Year-Month-Day Hour:Minute:Second | `2026-05-08 11:20:00` |
| Hostname | Host name | `hostname` |
| Process Information | Process name and PID | `checkfileconfig[pid]` |
| Message Content | Log body | `the hostname is not configured in '/etc/hosts'` |

## IV. Abnormal Error Keywords

### 4.1 SSH Configuration Related Keywords

| Keyword | Meaning | Severity |
|--------|------|----------|
| `UseDNS is empty` | UseDNS parameter not configured | 🔴 P0 |
| `UseDNS is not seted no` | UseDNS not set to no | 🔴 P0 |
| `MaxStartups <1.000` | MaxStartups value less than 1000 | 🟠 P1 |
| `PasswordAuthentication and ChallengeResponseAuthentication seted no at same time` | Both authentication methods disabled at the same time | 🔴 P0 |

### 4.2 hosts File Related Keywords

| Keyword | Meaning | Severity |
|--------|------|----------|
| `the hostname is not configured in '/etc/hosts'` | hostname not configured in /etc/hosts | 🔴 P0 |
| `the hostname corresponds to more than one ip` | hostname corresponds to multiple IPs | 🟠 P1 |
| `the ip in /etc/hosts is not in ifconfig list` | IP in hosts does not match actual network interface | 🔴 P0 |
| `the ip corresponds to more than one hostname` | One IP corresponds to multiple hostnames | 🟠 P1 |
| `The mapping of realmParseIp hadoopName does not exist` | Missing hadoop domain mapping | 🔴 P0 |
| `The IP address must be unreachable` | hadoop domain IP reachable (should be unreachable) | 🟠 P1 |

### 4.3 fstab File Related Keywords

| Keyword | Meaning | Severity |
|--------|------|----------|
| `can not find in /proc/mounts` | Mount point not mounted in system | 🔴 P0 |
| `fstab uuid can not match the mount one` | UUID in fstab does not match actual mount | 🔴 P0 |
| `swapuuid not contains fstab uuid` | swap configuration inconsistent | 🟠 P1 |
| `fstabuuids not contains swap uuid` | swap enabled in system not configured in fstab | 🟠 P1 |
| `get blkid dev failed` | Unable to get device UUID | 🟠 P1 |
| `readlink -e failed` | Invalid device path | 🟠 P1 |

### 4.4 Client Configuration Related Keywords

| Keyword | Meaning | Severity |
|--------|------|----------|
| `does not exist` | Softlink or actual directory does not exist | 🔴 P0 |
| `is empty` | Client directory is empty | 🟠 P1 |
| `Incorrect permissions` | Permission or owner incorrect | 🟠 P1 |
| `files owned by users other than omm` | Files owned by non-omm users exist | 🟠 P1 |

### 4.5 Abnormal Keyword Priority and Root Cause

| Priority | Keyword Combination | Root Cause | Possible Impact |
|--------|------------|----------|----------|
| P0 | `UseDNS is empty` / `UseDNS is not seted no` | SSH UseDNS configuration anomaly | Slow SSH connection |
| P0 | `PasswordAuthentication and ChallengeResponseAuthentication seted no at same time` | All SSH authentication methods disabled | Unable to SSH login |
| P0 | `the hostname is not configured in '/etc/hosts'` | hostname not configured | Hostname resolution failure |
| P0 | `the ip in /etc/hosts is not in ifconfig list` | IP in hosts does not match actual | Network communication anomaly |
| P0 | `The mapping of realmParseIp hadoopName does not exist` | Missing hadoop domain mapping | Kerberos authentication failure |
| P0 | `can not find in /proc/mounts` | Mount point not mounted | Cannot auto-mount after restart |
| P0 | `fstab uuid can not match the mount one` | UUID inconsistent | Cannot mount correctly after restart |
| P0 | `does not exist` | Client directory does not exist | Client cannot be used |
| P1 | `MaxStartups <1.000` | MaxStartups value too small | SSH connection count limited |
| P1 | `the hostname corresponds to more than one ip` | hostname corresponds to multiple IPs | Hostname resolution unstable |
| P1 | `the ip corresponds to more than one hostname` | One IP corresponds to multiple hostnames | Hostname resolution unstable |
| P1 | `swapuuid not contains fstab uuid` | swap configuration inconsistent | swap function anomaly |
| P1 | `is empty` | Client directory empty | Client cannot be used |
| P1 | `Incorrect permissions` | Permission or owner incorrect | Client cannot be used |

## VII. Common Root Causes and Repair Suggestions

### 7.1 SSH Configuration File Anomaly

**Symptom:** Log shows `UseDNS is not seted no` or `MaxStartups <1.000` or both authentication methods disabled at the same time

**Repair Suggestion:** Modify UseDNS, MaxStartups, PasswordAuthentication configuration in `/etc/ssh/sshd_config` and restart sshd service, must be manually executed after user confirmation

### 7.2 hosts File Anomaly

**Symptom:** Log shows `the hostname is not configured in '/etc/hosts'` or IP related errors

**Repair Suggestion:** Add/fix hostname and IP mapping in `/etc/hosts`, must be manually executed after user confirmation

### 7.3 fstab File Anomaly

**Symptom:** Log shows `can not find in /proc/mounts` or `fstab uuid can not match the mount one`

> **Warning**: Modifying /etc/fstab may cause the system to fail to boot, please operate with caution!

**Repair Suggestion:** Check UUID consistency and fix `/etc/fstab` configuration, must be manually executed after user confirmation

### 7.4 Client Configuration Anomaly

**Symptom:** Log shows `does not exist` or `is empty` or `Incorrect permissions`

**Repair Suggestion:** Fix client directory owner and permissions, must be manually executed after user confirmation

### 7.5 Configuration File Unexpectedly Modified

**Symptom:** Log shows configuration items do not match expectations

**Repair Suggestion:**

- Check whether other scripts or personnel modified the configuration file
- Confirm recent system change records
- Restore the correct configuration file

### 7.6 System Changes Cause Configuration Inconsistency

**Symptom:** Alarm appears after system upgrade or configuration change

**Repair Suggestion:**

- Check recent system change records
- Confirm whether changes meet expectations
- If changes need to be kept, update the check script configuration

## IX. Configuration File and Script Paths

### Configuration Files

| Configuration File | Purpose |
|----------|------|
| `/etc/ssh/sshd_config` | SSH service configuration file |
| `/etc/hosts` | Hostname resolution configuration file |
| `/etc/fstab` | File system mount configuration file |
| `${BIGDATA_HOME}/client/` | Client directory |

### Related Script Paths

| Script | Path | Detection Cycle |
|------|------|----------|
| check_ssh_cfg.sh | `${NODE_AGENT_HOME}/bin/autocheck/check_ssh_cfg.sh` | Every 5 minutes |
| check_hosts.sh | `${NODE_AGENT_HOME}/bin/autocheck/check_hosts.sh` | Every 5 minutes |
| check_fstab.sh | `${NODE_AGENT_HOME}/bin/autocheck/check_fstab.sh` | Every 5 minutes |
| check_client.sh | `${NODE_AGENT_HOME}/bin/autocheck/check_client.sh` | Every 5 minutes |

### Detection Scenario Judgment

| PATHNAME | Detection Scenario | Detection Script |
|----------|----------|----------|
| `/etc/ssh/sshd_config` | SSH configuration file anomaly | check_ssh_cfg.sh |
| `/etc/hosts` | hosts file anomaly | check_hosts.sh |
| `/etc/fstab` | fstab file anomaly | check_fstab.sh |
| `${BIGDATA_HOME}/client` | Client configuration anomaly | check_client.sh |

### Alarm Recovery Description

After repair is completed, the system will automatically check in the next detection cycle (about 5 minutes) to confirm whether the alarm is recovered.
