## II. Log Directory

### 2.1 Log Priority

> When analyzing network write packet loss rate anomalies, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |----------|----------|-------------|
> | 1 | System log | System-level network log information |
> | 2 | Kernel log | Kernel network packet loss records |

### 2.2 Log Path

| Log File | Path | Purpose | Priority |
|----------|------|---------|----------|
| System log | `/var/log/messages` | System-level network log information | 1 |
| Kernel log | `/var/log/kern.log` or `dmesg` | Kernel network packet loss records | 2 |

## VII. Common Root Causes and Repair Solutions

| Root Cause | Characteristics | Repair Solution |
|------------|----------------|-----------------|
| Unreasonable alarm threshold configuration | Packet loss rate below default threshold 0.5%, no business impact | Log in to Manager to modify threshold: O&M > Alarm > Threshold Settings > Cluster Name > Host > Network Write Info > Write Packet Loss Rate |
| Poor network environment quality | Physical network packet loss, multiple nodes alarming simultaneously | Contact network administrator to check switches, cables, optical modules, and other physical network devices |
| NIC link abnormal | System log shows `Link detected: no` or `NIC Link is Down` | Check cable connection, replace faulty cables or optical modules |
| Routing configuration abnormal | System log shows `no route to host` | Check routing table configuration, confirm default gateway is correct |
| NIC transmit queue full | Transmit packet drops and high NIC load | Increase NIC transmit queue: `ethtool -G <nic_name> tx <value>` |
