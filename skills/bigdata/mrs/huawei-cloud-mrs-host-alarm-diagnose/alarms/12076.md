## 2. Log Directory

### 2.1 Log Priority

> When analyzing process exceptions, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |--------|----------|------|
> | 1 | Startup/shutdown script log | Records process startup/stop operations, analyze first |
> | 2 | Process runtime log | Records business runtime logs, analyze business exceptions |
> | 3 | HA log | HA resource detection results |

### 2.2 Log Path

| Log File | Path | Purpose | Priority |
|----------|------|------|--------|
| Database operation log | `/var/log/Bigdata/omm/oms/db/omm_gaussdba.log` | HA detection of database status, startup/stop operations | 1 |
| gs_ctl log | `/var/log/Bigdata/omm/oms/db/gs_ctl-*.log` | gs_ctl command execution log | 1 |
| gs_ctl current log | `/var/log/Bigdata/omm/oms/db/gs_ctl-current.log` | Latest gs_ctl operation records | 1 |
| gaussdb runtime log | `/var/log/Bigdata/omm/oms/db/gaussdb-*.log` | Database runtime log | 2 |
| HA runtime log | `/var/log/Bigdata/dbservice/ha/runlog/ha.log` | HA runtime log | 5 |

## 3. Log Time Format

### 3.1 Format A: Space-Separated Format (omm_gaussdba.log)

```
2024-12-20 10:30:15.123 CST  [Thread-1234] [Level] [Module] Message content
```

| Field | Description | Example |
|------|------|------|
| Date and time | YYYY-MM-DD HH:MM:SS.milliseconds | `2024-12-20 10:30:15.123` |
| Timezone | CST timezone | `CST` |
| Thread ID | Thread identifier | `[Thread-1234]` |
| Log level | INFO/WARN/ERROR/FATAL | `[ERROR]` |
| Module name | Module identifier | `[DB]` |
| Message | Log body | `database system is not ready` |

### 3.2 Format B: T-Separated Format (gaussdb-*.log)

```
2024-12-20T10:30:15.123+08:00 2024 0 FATAL:  database system is not ready
```

| Field | Description | Example |
|------|------|------|
| Date and time | ISO 8601 format (with timezone) | `2024-12-20T10:30:15.123+08:00` |
| Year | Year | `2024` |
| Process ID | Process identifier | `0` |
| Log level | LOG/FATAL/PANIC/ERROR | `FATAL` |
| Message | Log body | `database system is not ready` |

## 4. Detailed Log Descriptions

### 4.1 Database Operation Log (omm_gaussdba.log)

#### Log Path
```
/var/log/Bigdata/omm/oms/db/omm_gaussdba.log
```

#### Error Keywords

| Keyword | Description | Severity |
|--------|------|----------|
| `FATAL` | Fatal error | P0 |
| `ERROR` | Error message | P1 |
| `WARN` | Warning message | P2 |
| `fail` | Operation failed | P1 |
| `exception` | Exception caught | P1 |
| `invalid` | Invalid parameter or state | P1 |
| `denied` | Permission denied | P1 |
| `timeout` | Timeout | P1 |
| `refused` | Connection refused | P1 |

#### Keyword Priority and Root Cause

| Priority | Keyword Combination | Root Cause | Possible Impact |
|--------|------------|----------|----------|
| P0 | `FATAL` + `database system` | Database system crash | All business interrupted |
| P1 | `ERROR` + `connect` | Connection failure | Some functions unavailable |
| P1 | `fail` + `start` | Startup failure | Service cannot start |
| P1 | `timeout` + `query` | Query timeout | Slow response |
| P1 | `refused` + `port` | Port occupied | Service cannot bind port |
| P1 | `invalid` + `password` | Authentication failure | Cannot pass verification |
| P2 | `WARN` + `memory` | High memory usage | Performance degradation |

| Priority | Keyword Combination | Root Cause | Possible Impact |

  -p 'alarm_time=<alarm_time>' \

  -p 'log_file_name=gs_ctl-*.log' \
  -p 'keywords=[]' \
  -p 'log_type=local' \

tail -500 /var/log/Bigdata/omm/oms/db/gs_ctl-current.log

#### Keyword Priority and Root Cause

| Priority | Keyword Combination | Root Cause | Possible Impact |

| P1 | `disconnect` + `peer` | Peer node disconnected | May trigger switchover |
| P1 | `timeout` + `heartbeat` | Heartbeat timeout | Network issue |
| P1 | `ERROR` + `build` | Active/standby build failure | Sync exception |
