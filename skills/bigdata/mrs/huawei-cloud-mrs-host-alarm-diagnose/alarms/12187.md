## 1. Alarm Type

| Item | Content |
|------|---------|
| Alarm Name | Disk Partition Expansion Failure |
| Alarm ID | 12187 |
| Alarm Type | Service Quality Alarm |

---

## 2. Log Directory

### 2.1 Log Priority

> When analyzing disk partition expansion failure, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |----------|----------|-------------|
> | 1 | System log | System-level disk operation log |
> | 2 | NodeAgent log | Disk expansion detection log |

### 2.2 Log Path

| Log File | Path | Purpose | Priority |
|----------|------|---------|----------|
| System log | `/var/log/messages` | System-level disk operation log | 1 |
| NodeAgent log | `${BIGDATA_LOG_HOME}/nodeagent/scriptlog/` | Disk expansion detection log | 2 |

## 7. Common Root Causes and Repair Suggestions

| Root Cause | Characteristics | Repair Suggestion |
|------------|----------------|-------------------|
| growpart tool not installed | `which growpart` produces no output or returns `no growpart` | Contact technical support to install the growpart tool: `yum install cloud-utils-growpart` |
| growpart expansion command execution failure | Partition expansion command returns error, log shows `FAILED` | Manually execute: `growpart <data_disk> <partition_number>` (e.g., `growpart /dev/vdb 1`) |
| resize2fs execution failure | Filesystem expansion failed | Manually execute: `resize2fs <disk_partition>` (e.g., `resize2fs /dev/vdb1`) |
| Device busy | Log shows `device is busy` | Stop processes occupying the partition, then retry the expansion operation |
| Insufficient disk space | Log shows `No space left on device` | Clean up disk space first, then perform expansion |
| Disk hardware failure | Disk health check abnormal | Replace the disk, then re-execute partition expansion |
