# Monitoring Metric Dump Failure (12038) Alarm Diagnosis

## 1. Diagnosis Introduction

This document covers the diagnosis and handling of the **Monitoring Metric Dump Failure (12038)** alarm. Monitoring metric dump failure occurs when, after a user configures monitoring metric dump on the FusionInsight Manager interface, the system periodically checks the dump result at the configured dump interval (default 60 seconds) and generates this alarm when the dump fails.

Alarm basic information:

| Item | Content |
|------|---------|
| Alarm ID | 12038 |
| Alarm Name | Monitoring Metric Dump Failure |
| Alarm Severity | Important |
| Alarm Type | Monitoring data dump alarm |
| Auto-Clearable | Yes |
| System Impact | Monitoring metric dump failure prevents upper-layer management systems from obtaining FusionInsight Manager monitoring metrics |

---

## 2. Executable Operations

This section provides the operations that can be executed during alarm analysis.

### 2.1 Obtain Cluster OMS Active/Standby Node Information

Execute the following command to obtain the cluster OMS active/standby node information and determine the IP address of the OMS node that generated the alarm.

```bash
python3 lakewatch_api_client.py -a query-management-node-info \
  -p 'cluster_id=<cluster_id>'
```

Parameters:
- `<cluster_id>`: Cluster ID

### 2.2 Check Network Connectivity from OMS Node to Dump Server

Execute the following command to check the network connectivity between the alarm OMS node and the monitoring metric dump server (FTP/SFTP server). If the ping succeeds, the network connection is normal; if the ping fails, the network is abnormal.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=network-connectivity-test' \
  -p 'env={"TARGET_IP":"<IP_ADDRESS>"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name (OMS node), obtained from alarm details
- `<IP_ADDRESS>`: IP address of the monitoring metric dump server (FTP/SFTP server), obtained from the Manager monitoring data upload configuration page

### 2.3 Check OMS Node Disk Space Usage

Execute the following command to check the disk space usage of the alarm OMS node and determine whether the local disk is full, preventing dump files from being generated.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=disk-space' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name (OMS node), obtained from alarm details

## 3. Manual Operations

This section provides operations that cannot be executed automatically (i.e., commands that require logging into the node or performing manual operations through the Manager interface).

### 3.1 View Monitoring Data Upload Configuration

On the FusionInsight Manager interface, view the monitoring metric dump configuration to confirm whether the FTP username, password, port, dump mode, public key, etc. match the server-side configuration.

1. Log in to FusionInsight Manager
2. Navigate to "System > Integration > Monitoring Data Upload"
3. Check the following configuration items:
   - FTP username
   - Password
   - Port
   - Dump mode (FTP or SFTP)
   - Public key (in SFTP mode)

If the configuration does not match the server-side configuration, enter the correct configuration and click "OK".

### 3.2 Check Server-Side Save Path Permission (FTP Mode)

If the dump mode is FTP, log in to the dump server via FTP and check whether the relative path "save path" under the default directory has read/write permission for the "FTP username".

```bash
ftp <server_IP>
# After login, switch to the default directory and check the save path permission
ls -l <save_path>
```

- If read/write permission is present, the permission is normal
- If read/write permission is absent, add read/write permission

### 3.3 Check Server-Side Save Path Permission (SFTP Mode)

If the dump mode is SFTP, log in to the dump server via SFTP and check whether the absolute path "save path" has read/write permission for the "FTP username".

```bash
sftp <FTP_username>@<server_IP>
# After login, check the save path permission
ls -ld <save_path>
```

- If read/write permission is present, the permission is normal
- If read/write permission is absent, add read/write permission

### 3.4 Add Read/Write Permission to Server-Side Save Path

If the save path lacks read/write permission, log in to the dump server as the root user and execute the following commands to add read/write permission for the "FTP username" on the save path.

```bash
chmod -R 755 <save_path>
chown -R <FTP_username>:<FTP_group> <save_path>
```

- `<save_path>`: Save path for monitoring metric dump, obtained from the Manager monitoring data upload configuration page
- `<FTP_username>`: FTP username, obtained from the Manager monitoring data upload configuration page
- `<FTP_group>`: FTP user's group

### 3.5 Check Server-Side Save Path Disk Space

Log in to the dump server as the root user and execute the following command to check whether there is sufficient disk space under the current save path.

```bash
df -h <save_path>
```

- If disk space is sufficient, the space is normal
- If disk space is insufficient, delete unnecessary files or change the save directory on the monitoring metric dump configuration page

### 3.6 Collect Fault Information

When the above steps do not resolve the issue, collect fault log information.

1. On the FusionInsight Manager interface, navigate to "O&M > Logs > Download"
2. Select "OMS" under "Services" and click "OK"
3. Click the edit button in the upper right corner, set the log collection "Start Time" and "End Time" to 60 minutes before and after the alarm generation time, and click "Download"
4. Contact O&M personnel and send the collected fault log information

## 4. Common Fault Handling Solutions

### 4.1 Server Network Connection Abnormal

**Symptoms**:
- OMS node cannot ping the monitoring metric dump server IP
- Network interruption or firewall blocking

**Solution**:
1. Contact the network administrator to check the network configuration and ensure normal network connectivity between the OMS node and the dump server
2. Check whether firewall rules allow FTP (port 21) or SFTP (port 22) traffic
3. After the network recovers, wait for the next dump check to see whether the alarm is automatically cleared
4. If the alarm is not cleared, continue with the subsequent diagnosis steps

### 4.2 Dump Configuration Mismatch

**Symptoms**:
- FTP username, password, port, dump mode, or public key does not match the server-side configuration
- Manager monitoring data upload page configuration is incorrect

**Solution**:
1. On the FusionInsight Manager interface, navigate to "System > Integration > Monitoring Data Upload"
2. Verify the FTP username, password, port, dump mode, public key, and other configuration items
3. Enter the correct configuration and click "OK"
4. Wait for the next dump check to see whether the alarm is automatically cleared

### 4.3 Insufficient Server-Side Save Path Permission

**Symptoms**:
- After logging in to the server via FTP/SFTP, the save path has no read/write permission
- Dump files cannot be written to the server-side save path

**Solution**:
1. Log in to the dump server as the root user
2. Execute `chmod -R 755 <save_path>` and `chown -R <FTP_username>:<FTP_group> <save_path>` to add read/write permission
3. Wait for the next dump check to see whether the alarm is automatically cleared

### 4.4 Insufficient Server-Side Save Path Disk Space

**Symptoms**:
- Disk usage of the server-side save path is close to or at 100%
- Dump files cannot be written due to insufficient disk space

**Solution**:
1. Log in to the dump server as the root user, execute `df -h <save_path>` to check disk space
2. Delete unnecessary expired dump files under the save path to free up space
3. Alternatively, change the save directory to a disk with sufficient space on the FusionInsight Manager monitoring data dump configuration page
4. Wait for the next dump check to see whether the alarm is automatically cleared

### 4.5 Insufficient OMS Node Local Disk Space

**Symptoms**:
- OMS node disk space usage is close to or at 100%
- Monitoring metric dump files fail to be generated locally

**Solution**:
1. Clean up unnecessary log files or temporary files on the OMS node
2. Expand the disk if necessary
3. Wait for the next dump check to see whether the alarm is automatically cleared

### 5.2 Diagnosis Conclusion Output

Based on the diagnosis flow above, output one of the following conclusions:

| Diagnosis Conclusion | Recommended Action |
|----------------------|---------------------|
| Server network connection abnormal | Contact network administrator to fix the network, wait for alarm to auto-clear |
| Dump configuration mismatch | Modify Manager monitoring data upload configuration, wait for alarm to auto-clear |
