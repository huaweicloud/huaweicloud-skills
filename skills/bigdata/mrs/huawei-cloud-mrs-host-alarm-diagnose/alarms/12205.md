# Disk IO Write Wait Time Exceeds Threshold Log Information

## 1. Alarm Type

| Item | Content |
|------|---------|
| Alarm Name | Disk IO Write Wait Time Exceeds Threshold |
| Alarm ID | 12205 |
| Alarm Type | Physical resource alarm |

---

## 2. Log Directory

### 2.1 Log Priority

> When analyzing disk IO write wait anomalies, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |----------|----------|-------------|
> | 1 | System log | System-level disk IO logs |
> | 2 | Kernel log | Hardware error records |
> | 3 | Disk SMART information | Disk health status |

### 2.2 Log Paths

| Log File | Path | Purpose | Priority |
|----------|------|---------|----------|
| System log | `/var/log/messages` | System-level disk IO logs | 1 |
| Kernel log | `/var/log/kern.log` or `dmesg` | Hardware error records | 2 |
| Disk SMART | Obtained via `smartctl` | Disk health status | 3 |

## 3. Log Time Format

### 3.1 System Log Format


| Field | Description | Example |

## 4. Exception Error Keywords

### 4.1 Disk IO Write Wait Keywords

| Keyword | Description | Severity |
|---------|-------------|----------|
| `w_await` | Average write operation wait time (ms); >10ms requires attention, >30ms triggers alarm | P0 |
| `svctm` | Average service time (ms); >5ms requires attention | P1 |
| `%util` | Disk utilization; >80% approaching saturation | P1 |
| `aqu-sz` | I/O queue depth; >4 indicates queue buildup | P1 |
| `w/s` | Write operations per second | P3 |
| `wkB/s` | Kilobytes written per second | P3 |
| `wrqm/s` | Merged write requests per second | P3 |

### 4.2 Hardware Error Keywords

| Keyword | Description | Severity |
|---------|-------------|----------|
| `I/O error` | I/O error | P0 |
| `read-only` | File system became read-only | P0 |
| `device reset` | Device reset | P1 |
| `timeout` | I/O timeout | P1 |
| `ata` | ATA error | P1 |
| `scsi` | SCSI error | P1 |

### 4.3 SMART Health Keywords

| Keyword | Description | Severity |
|---------|-------------|----------|
| `Reallocated_Sector_Ct` | Reallocated sector count; >0 requires attention | P1 |
| `Current_Pending_Sector` | Pending sectors | P1 |
| `Offline_Uncorrectable` | Offline uncorrectable error | P0 |

## 7. Common Root Causes and Repair Solutions

### Key Metric Judgment Matrix

| Metric | Normal | Warning | Critical | Description |
|--------|--------|---------|----------|-------------|
| w_await | <5ms | 10-30ms | >30ms | Write operation wait time |
| %util | <50% | 50-80% | >80% | Disk busy ratio |
| aqu-sz | <2 | 2-4 | >4 | I/O queue buildup |
| svctm | <2ms | 2-5ms | >5ms | Average service time |

### Key Judgment Logic

| Condition Combination | Conclusion | Next Step |
|-----------------------|------------|-----------|
| High w_await + High %util | Disk bandwidth saturated | Scale up disk / Replace with SSD / Distribute load |
| High w_await + Low %util | Hardware issue or queue configuration issue | Check hardware SMART and dmesg |
| Normal w_await + Slow business | Possibly an application-layer issue | Check application write strategy |

### Root Cause Classification Table

| Root Cause | Characteristics | Repair Solution |
|------------|----------------|-----------------|
| Unreasonable alarm threshold configuration | w_await below default threshold 10s, no business impact | Log in to Manager to modify threshold: O&M > Alarm > Threshold Settings > Cluster Name > Host > Disk > Average Time Required per Write Operation |
| Disk bandwidth saturated | %util > 80%, high w_await | Scale up disk / Replace with SSD / Distribute load to other nodes |
| Excessive dirty page synchronous flush | Sudden burst of writes, business lag | Reduce `dirty_ratio`: `sysctl -w vm.dirty_ratio=10`, switch to asynchronous flush |
| Excessive log writing | A process has extremely high write I/O | Use asynchronous logging / Lower log level |
| Frequent fsync | Database WAL, many small IOs | Batch commits / Increase `wal_buffers` |
| I/O scheduler mismatch | SSD using cfq scheduler | Change to none/mq-deadline: `echo mq-deadline > /sys/block/<dev>/queue/scheduler` |
| atime update overhead | Large numbers of small file reads accompanied by writes | Mount with `noatime` option: `mount -o remount,noatime <mount_point>` |
| Impending disk failure | smartctl reports errors, dmesg reports errors | Replace disk |
| RAID degraded rebuild | Sudden I/O surge, abnormal RAID status | Avoid rebuild window / Replace with faster disk |
| Frequent swap | High vmstat si/so | Increase memory / Set `swappiness=0`: `sysctl vm.swappiness=0` |
| File system fragmentation | Excessive file system fragmentation | Run defragmentation: `xfs_fsr <mount_point>` |
| Peak business period | High w_await during specific time periods | Scale up node or stagger high-IO business execution |
