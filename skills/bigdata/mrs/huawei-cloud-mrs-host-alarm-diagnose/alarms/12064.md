## 2. Log Directory

### 2.1 Log Priority

> When analyzing port conflicts, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |--------|----------|------|
> | 1 | System log | System-level port binding log |
> | 2 | NodeAgent log | Port conflict detection log |

### 2.2 Log Path

| Log File | Path | Purpose | Priority |
|----------|------|------|--------|
| System log | `/var/log/messages` | System-level port binding log | 1 |
| NodeAgent log | `${BIGDATA_LOG_HOME}/nodeagent/` | Port conflict detection log | 2 |
| Port configuration | `/proc/sys/net/ipv4/ip_local_port_range` | Random port range configuration | 3 |

## 7. Common Root Causes and Remediation

| Root Cause | Characteristics | Remediation |
|------|------|----------|
| Random port range configuration modified | `ip_local_port_range` minimum value < 32768 | Modify `net.ipv4.ip_local_port_range=32768 61000` in `/etc/sysctl.conf`, run `sysctl -p` to apply |
| Port range overlaps with FI component ports | Random port range covers okerberos/oldap/controller/pms/tomcat ports | Modify random port range to `32768 61000`, wait 1 hour detection cycle for alarm recovery |
| System port occupied by random allocation | Service startup port occupied by random port, log shows `Address already in use` | Modify random port range configuration, restart affected services |
| okerberos/oldap port occupied | Authentication service port occupied, causing authentication failure | Modify random port range, restart okerberos/oldap service |
| controller/pms port occupied | Process fault, affecting elastic scaling | Modify random port range, restart controller/pms process |
| tomcat port occupied | Manager page inaccessible | Modify random port range, restart tomcat: `sh ${BIGDATA_HOME}/om-server/tomcat/bin/shutdown.sh; sh ${BIGDATA_HOME}/om-server/tomcat/bin/startup.sh` |

### Remediation Steps

1. Log in to the alarm host as the root user
2. Execute `cat /proc/sys/net/ipv4/ip_local_port_range` to view the current random port range
3. If the minimum value < 32768, perform the modification:
   - `vim /etc/sysctl.conf`, modify/add `net.ipv4.ip_local_port_range = 32768 61000`
   - `sysctl -p /etc/sysctl.conf` to apply the configuration
4. Wait 1 hour detection cycle, confirm alarm recovery
