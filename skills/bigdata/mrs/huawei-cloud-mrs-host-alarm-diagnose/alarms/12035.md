# `Data Status Unknown After Restore Task Failure` (12035) Alarm Diagnosis Skill

## 1. Diagnosis Overview

This document primarily covers the diagnosis and handling of the **Data Status Unknown After Restore Task Failure (12035)** alarm. After a restore task fails, the system automatically rolls back at 60-minute intervals. If the rollback fails, it may cause data loss and other issues. If this situation occurs, the alarm is reported. If the next restore task for that task succeeds, the alarm is cleared.

Alarm basic information:

| Item | Description |
|------|------|
| Alarm ID | 12035 |
| Alarm Name | Data Status Unknown After Restore Task Failure |
| Alarm Severity | Critical |
| Alarm Type | Business Fault Alarm |
| Auto-cleared | Yes |
| System Impact | After a restore task fails, the system automatically rolls back. If the rollback fails, it may cause data loss and data status unknown issues, which may affect business functionality |

## 2. Executable Operations

This section provides the relevant operations that can be executed during the alarm analysis process.

### 2.1 Obtain Cluster OMS Active/Standby Node Information

Execute the following command to obtain OMS active/standby node information. Controller service logs are located on the active OMS node.

```bash
python3 lakewatch_api_client.py -a query-management-node-info \
  -p 'cluster_id=<cluster_id>'
```

Parameter description:
- `<cluster_id>`: Cluster ID

### 2.2 Search Controller Backup Recovery Logs

Execute the following command to search the Controller backup recovery logs on the active OMS node and locate the specific cause of the restore task failure through keywords.

```bash
python3 lakewatch_api_client.py -a collect_alarm_log_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'log_directory=/var/log/Bigdata/controller/backup' \
  -p 'log_file_name=backupplugin.log,backupplugin_ctl.log,controller_backup.log' \
  -p 'keywords=["restore","recover","rollback","fail","error","exception"]' \
  -p 'alarm_time=<alarm_time>' \
  -p 'log_type=local' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<alarm_time>`: Alarm generation time
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information (usually the active OMS node)

### 2.3 Check Node Disk Space

Execute the following command to check whether the alarm node has sufficient disk space. Insufficient disk space may cause restore task failures.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=disk-space' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information

### 2.4 Obtain OMS Key Directories

Execute the following command to obtain OMS key directory information and confirm whether the paths related to the restore task are normal.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=oms_core_dir' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information

## 3. Non-Executable Operations

This section provides operations that cannot be executed through the tool during the alarm analysis process (i.e., operations that require manual login to the Manager UI or node).

### 3.1 View Component Running Status

In the FusionInsight Manager UI, check whether the current component running status meets the restore task requirements:

1. Log in to the FusionInsight Manager UI
2. Select "Cluster > <cluster_name> > Services"
3. Check whether the current component running status meets the requirements:
   - OMS and DBService must be in normal status
   - Other components must have their services stopped
4. If the component status does not meet the requirements, the component status must be restored to the required status first

### 3.2 View Alarm Location Information and Obtain Task Name

Obtain the task name from the alarm location information in the FusionInsight Manager UI:

1. Log in to the FusionInsight Manager UI
2. Select "Maintenance > Alarms > Alarms"
3. In the alarm list, click the location information icon in the row of this alarm
4. Obtain the "Task Name" from the "Location Information"

### 3.3 View Restore Task Details and Restart

View the restore task details in the FusionInsight Manager UI and restart it:

1. Log in to the FusionInsight Manager UI
2. Select "Maintenance > Backup & Restore > Restore Management"
3. Find the corresponding restore task based on the "Task Name", and view the restore task details
4. Start the restore task and check whether it executes successfully
5. If the restore task executes successfully, wait 2 minutes and check whether the alarm is cleared
6. If the restore task execution fails, proceed to 3.4 to collect fault information

### 3.4 Download Controller Service Logs

Download Controller service logs in the FusionInsight Manager UI for fault analysis:

1. Log in to the FusionInsight Manager UI
2. Select "Maintenance > Logs > Download"
3. In "Services", select "Controller", then click "OK"
4. In the upper right corner, set the log collection "Start Time" and "End Time" to 10 minutes before and after the alarm generation time
5. Click "Download"
6. Contact operations personnel and send the collected fault log information

## 4. Common Fault Repair Solutions

### 4.1 Component Status Does Not Meet Restore Requirements

**Symptoms**:
- Before executing the restore task, the component running status does not meet requirements
- OMS or DBService status is abnormal, or other components have not had their services stopped
- Restore task execution fails

**Repair solution**:
1. In the FusionInsight Manager UI, select "Cluster > <cluster_name> > Services"
2. View the running status of each component
3. Restore OMS and DBService to normal status
4. Stop the services of other components that need to be restored
5. After the component status meets the requirements, restart the restore task
6. Wait 2 minutes and check whether the alarm is cleared

### 4.2 Restore Task Step Execution Error

**Symptoms**:
- Component status meets requirements, but the restore task execution fails
- Error messages exist in Controller backup recovery logs
- Rollback failed; data status unknown

**Repair solution**:
1. In the FusionInsight Manager UI, select "Maintenance > Backup & Restore > Restore Management"
2. Find the corresponding restore task based on the "Task Name", and view the restore task details
3. Confirm the detailed cause of the restore task failure
4. After repairing the failure cause, restart the restore task
5. Wait 2 minutes and check whether the alarm is cleared
6. If it still fails, download Controller service logs (time range is 10 minutes before and after the alarm generation time)
7. Contact operations personnel and send the collected fault log information

### 4.3 Insufficient Disk Space Causing Restore Failure

**Symptoms**:
- Node disk space is insufficient
- Data write failure during restore task execution
- "insufficient disk space" related information may appear in Controller logs

**Repair solution**:
1. Check the alarm node disk space and confirm whether available space is sufficient
2. Clean up redundant files (e.g., old backup packages, installation packages, coredump files) to free disk space
3. Ensure sufficient remaining space on the backup recovery directory mount point
4. Restart the restore task
5. Wait 2 minutes and check whether the alarm is cleared

### 4.4 Rollback Failure Causing Data Status Unknown

**Symptoms**:
- After the restore task fails, the system automatically rolls back at 60-minute intervals
- The rollback operation also fails
- Data status is unknown; may affect business functionality

**Repair solution**:
1. Confirm the restore task failure cause; prioritize repairing the root cause of the restore task failure
2. Check whether the component status meets requirements (OMS and DBService normal, other components stopped)
3. Check whether disk space is sufficient
4. After repairing the issues, restart the restore task
5. If the restore task succeeds, the alarm will be automatically cleared
6. If it still fails, collect Controller service logs and contact operations personnel

## 5. Alarm Diagnosis Flow

### 5.1 Diagnosis Flow Diagram

```
Start
  |
  v
Obtain task name and hostname from alarm location information
  |
  v
Obtain OMS active/standby node information; determine active OMS node
  |
  v
Search Controller backup recovery logs; locate failure cause
  |
  v
Check whether node disk space is sufficient
  |
  +--- Insufficient disk space ---> Clean up redundant files to free space
  |                                    |
  |                                    v
  |                           Restart restore task
  |
  +--- Sufficient disk space ---> Check whether component running status meets requirements
                                     |
                                     +--- Status does not meet ---> Restore component status to required status
                                     |                                     |
                                     |                                     v
                                     |                           Restart restore task
                                     |
                                     +--- Status meets ---> View restore task details; locate failed step
                                                              |
                                                              v
                                                        Restart restore task
                                                              |
                                                              v
                                                  Is restore task execution successful?
                                                              |
                                                              +--- Success ---> Wait 2 min, check whether alarm is cleared
                                                              |                  |
                                                              |                  +--- Alarm cleared ---> Processing complete
                                                              |                  |
                                                              |                  +--- Alarm not cleared ---> Download Controller logs, contact operations
                                                              |
                                                              +--- Failure ---> Download Controller logs, contact operations personnel
  |
  v
End (alarm cleared)
```

### 5.2 Diagnosis Conclusion Output

Based on the diagnosis flow above, output one of the following diagnosis conclusions:

| Diagnosis conclusion | Recommended action |
|----------|----------|
| Component status does not meet restore requirements | Restore OMS/DBService to normal status, stop other component services, then re-execute restore task |
| Restore task step execution failure | View restore task details, repair failed step, then re-execute restore task |
| Insufficient disk space | Clean up redundant files to free disk space, then re-execute restore task |
| Rollback failure, data status unknown | Repair root cause, then re-execute restore task to ensure data consistency |
| Alarm still persists after processing | Collect Controller service logs, contact operations personnel |
