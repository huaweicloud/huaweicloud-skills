# Insufficient System Entropy (12040) Alarm Diagnosis

## 1. Diagnosis Introduction

This document covers the diagnosis and handling of the **Insufficient System Entropy (12040)** alarm. Insufficient system entropy means that the available entropy of the node's operating system remains below 100, causing commands that rely on random numbers (such as encryption/decryption) to execute slowly and degrading instance business processing performance.

In MRS 3.2.0 and later, the system performs an alarm check every 5 minutes. It first checks whether rng-tools or haveged is enabled and correctly configured. If not configured, a fault alarm is generated. Otherwise, it continues to check the entropy value. If the entropy value is below 100 for 5 consecutive checks, a fault alarm is generated. In MRS 3.1.2 and earlier, the system checks the entropy value daily at midnight for 5 consecutive checks. If all are below 100, a fault alarm is generated. In MRS 3.3.1 and later, the alarm name changed from "Insufficient System Entropy" to "Insufficient Operating System Entropy".

Alarm basic information:

| Item | Content |
|------|---------|
| Alarm ID | 12040 |
| Alarm Name | Insufficient System Entropy (MRS 3.3.1+: Insufficient Operating System Entropy) |
| Alarm Severity | Important |
| Alarm Type | System fault alarm |
| Auto-Clearable | Yes |
| System Impact | Insufficient operating system entropy may cause encryption/decryption commands to execute slowly, degrade business processing performance of instances, and even prevent business processes from executing normally |

## 2. Executable Operations

This section provides the operations that can be executed during alarm analysis.

### 2.1 Check Whether haveged Is Installed

Execute the following command. If the result is empty, haveged is not installed; if the result is non-empty, haveged is installed.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=file-exist-check' \
  -p 'env={"FILE_PATH":"/usr/sbin/haveged"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

### 2.2 Check haveged Service Running Status

Execute the following command. If the result contains "running", the haveged service is running normally; otherwise, the haveged service is not running normally.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=service-status' \
  -p 'env={"SERVICE_NAME":"haveged"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

### 2.3 Check Whether rng-tools Is Installed

Execute the following command. If the result is empty, rng-tools is not installed; if the result is non-empty, rng-tools is installed.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=file-exist-check' \
  -p 'env={"FILE_PATH":"/usr/sbin/rngd"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

### 2.4 Check rngd Service Running Status

Execute the following command. If the result is non-empty and contains process information related to `-r/dev/urandom`, the rngd service is running normally; otherwise, the rngd service is not running normally.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=process-basic-info' \
  -p 'env={"process_name":"rngd"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

### 2.5 Check System Entropy Value

Execute the following command. If the result value is greater than or equal to 100, the system entropy value meets the requirement; if the value is less than 100, the system entropy is insufficient.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=memory-usage' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

## 3. Manual Operations

This section provides operations that cannot be executed automatically (i.e., commands that require logging into the node manually).

### 3.1 Restart haveged Service

Log in to the alarm node as the root user and execute the following command to manually restart the haveged service.

```bash
systemctl restart haveged.service
```

After execution, re-run `2.2 Check haveged Service Running Status` to confirm whether the haveged service is running normally.

### 3.2 Restart rngd Service

Log in to the alarm node as the root user and execute the following command to manually restart the rngd service.

```bash
systemctl restart rngd.service
```

After execution, re-run `2.4 Check rngd Service Running Status` to confirm whether the rngd service is running normally.

### 3.3 Install and Configure haveged (True Random Number Mode)

If haveged is not installed, contact the OS vendor to install the haveged tool. After installation, execute the following commands to start and enable auto-start on boot:

```bash
systemctl start haveged.service
systemctl enable haveged.service
```

### 3.4 Install and Configure rng-tools (Pseudo Random Number Mode)

If rng-tools is not installed, contact the OS vendor to install the rng-tools tool. After installation, configure it according to the OS type and execute the following commands to start and enable auto-start on boot:

```bash
systemctl start rngd.service
systemctl enable rngd.service
```

### 3.5 Collect Fault Information

If the alarm is not cleared after the above operations, collect fault information:

1. On the FusionInsight Manager interface, navigate to "O&M > Logs > Download"
2. Select "NodeAgent" under "Services" and click "OK"
3. Click the edit button in the upper right corner, set the log collection "Start Time" and "End Time" to 10 minutes before and after the alarm generation time, and click "Download"
4. Contact O&M personnel and send the collected fault log information

## 4. Common Fault Handling Solutions

### 4.1 haveged Not Installed or Not Started

**Symptoms**:
- `rpm -qa | grep -w "haveged"` returns empty, indicating haveged is not installed
- `service haveged status | grep "running"` returns empty, indicating haveged is installed but not running normally

**Solution**:
1. If not installed, contact the OS vendor to install the haveged tool (true random number mode)
2. If installed but not running, log in to the node as the root user and execute `systemctl restart haveged.service`
3. Wait for the next entropy check to see whether the alarm is automatically cleared

### 4.2 rng-tools Not Installed or Not Started

**Symptoms**:
- `rpm -qa | grep -w "rng-tools"` returns empty, indicating rng-tools is not installed
- `ps -ef | grep rngd | grep "\-r/dev/urandom"` returns empty, indicating the rngd service is not running normally

**Solution**:
1. If not installed, contact the OS vendor to install the rng-tools tool (pseudo random number mode) and configure it according to the OS type
2. If installed but not running, log in to the node as the root user and execute `systemctl restart rngd.service`
3. Wait for the next entropy check to see whether the alarm is automatically cleared

### 4.3 System Entropy Persistently Low

**Symptoms**:
- Both haveged and rng-tools are not installed
- Or both are installed and running, but `cat /proc/sys/kernel/random/entropy_avail` result is persistently below 100

**Solution**:
1. Check whether haveged and rng-tools are installed and running normally
2. If not installed, choose one of the following methods to configure:
   - Method 1: Install and start the haveged tool (true random number mode)
   - Method 2: Install and start the rng-tools tool (pseudo random number mode)
3. After restarting the corresponding service, wait for the next entropy check
4. Check whether the alarm is automatically cleared

## 5. Alarm Diagnosis Flow

### 5.1 Diagnosis Flow Chart

```
Start
  |
  v
Obtain hostname from alarm details
  |
  v
Check whether haveged is installed (rpm -qa | grep haveged)
  |
  +--- Installed ---> Check haveged service running status
  |                      |
  |                      +--- Running ---> Check system entropy value
  |                      |
  |                      +--- Not running ---> Restart haveged service
  |                                             |
  |                                             v
  |                                       Check system entropy value
  |
  +--- Not installed ---> Check whether rng-tools is installed
                          |
                          +--- Installed ---> Check rngd service running status
                          |                      |
                          |                      +--- Running ---> Check system entropy value
                          |                      |
                          |                      +--- Not running ---> Restart rngd service
                          |                                             |
                          |                                             v
                          |                                       Check system entropy value
                          |
                          +--- Not installed ---> Install haveged or rng-tools
                                                   |
                                                   v
                                             Check system entropy value
  |
  v
Check system entropy value (cat /proc/sys/kernel/random/entropy_avail)
  |
  +--- Entropy >= 100 ---> Wait for next entropy check
  |
  +--- Entropy < 100 ---> Install and configure haveged or rng-tools
                            |
                            v
                      Wait for next entropy check
  |
  v
Is the alarm automatically cleared?
  |
  +--- Yes ---> End (alarm cleared)
  |
  +--- No ---> Collect fault information and contact O&M personnel
```

### 5.2 Diagnosis Conclusion Output

Based on the diagnosis flow above, output one of the following conclusions:

| Diagnosis Conclusion | Recommended Action |
|----------------------|---------------------|
| haveged not installed | Contact OS vendor to install haveged |
| haveged service not running | Restart haveged service |
| rng-tools not installed | Contact OS vendor to install rng-tools |
| rngd service not running | Restart rngd service |
| System entropy persistently low | Install and configure haveged or rng-tools |
| Alarm persists after handling | Collect NodeAgent logs and contact O&M personnel |
