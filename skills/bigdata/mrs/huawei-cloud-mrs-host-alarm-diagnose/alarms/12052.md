# TCP Temporary Port Usage Rate Exceeds Threshold Diagnosis

# Alarm Diagnosis Flow

## Execute the following command to obtain alarm diagnosis information

```bash
python3 lakewatch_api_client.py -a query_alarm_skill \
  -p 'cluster_id=<cluster_id>' \
  -p 'alarm_sequence_id=<alarm_serial_no>'
```

Variable description:
<cluster_id>: Cluster ID, obtained from user input
<alarm_serial_no>: Alarm serial number, obtained from user input

## Analyze alarm cause based on obtained information

---

# Common Cause Analysis
Cause 1: TIME_WAIT accumulation
Symptom:
- TIME_WAIT state connection count is very high (>1000)
- Temporary port range is small

Verification command:
ss -tan state time-wait | wc -l

Solution:

# Increase temporary port range

sysctl -w net.ipv4.ip_local_port_range="1024 65535"

# Enable TIME_WAIT reuse

sysctl -w net.ipv4.tcp_tw_reuse=1

# Shorten TIME_WAIT duration

sysctl -w net.ipv4.tcp_fin_timeout=30

  ---
Cause 2: Connection count too high (normal business growth)

Symptom:

- ESTABLISHED connection count is very high
- Business indeed has a large number of clients

Verification command:
ss -tan state established | wc -l

Solution:

- Expand temporary port range
- Load balancing to disperse connections
- Add servers

  ---
Cause 3: Short connections frequently created

Symptom:

- Large number of short connections
- Both TIME_WAIT and CLOSE-WAIT are numerous

Verification command:
ss -tan | awk '{print $1}' | sort | uniq -c | sort -rn

Solution:

- Use connection pool/long connections
- Adjust TCP parameters
- Optimize application connection logic

  ---
Cause 4: Port exhaustion (most severe)
Symptom:
- Unable to establish new connections
- Error: Cannot assign requested address or Address already in use

Verification command:

# View available ports

cat /proc/sys/net/ipv4/ip_local_port_range

# View current usage

ss -tan | wc -l

Solution:

- Immediately increase port range
- Check for port leaks
- Restart problematic process
