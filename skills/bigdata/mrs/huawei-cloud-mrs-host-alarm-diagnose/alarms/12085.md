## 2. Log Directory

### 2.1 Log Priority

> When analyzing audit log dump failures, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |--------|----------|------|
> | 1 | Controller log | Dump task execution log |
> | 2 | NodeAgent log | Log collection execution log |
> | 3 | System log | Disk space information |

### 2.2 Log Path

| Log File | Path | Purpose | Priority |
|----------|------|------|--------|
| Controller log | `${BIGDATA_LOG_HOME}/controller/scriptlog/getLogs.log` | Dump task execution log | 1 |
| NodeAgent log | `${BIGDATA_LOG_HOME}/nodeagent/scriptlog/collectLog.log` | Log collection execution log | 2 |
| System log | `/var/log/messages` | Disk space information | 3 |

## 3. Log Time Format

### 3.1 Controller Log Format

```
2026-06-11 16:00:32,123 [INFO] message
```

| Field | Description | Example |
|------|------|------|
| Date and time | YYYY-MM-DD HH:MM:SS,milliseconds | `2026-06-11 16:00:32,123` |
| Log level | INFO/WARN/ERROR | `[INFO]` |
| Message | Log body | `message` |

### 3.2 System Log Format

```
Dec 20 10:30:15 hostname process_name[pid]: message
```

## 4. Error Keywords

### 4.1 Dump Failure Keywords

| Keyword | Description | Severity |
|--------|------|----------|
| `LOG SIZE is more than 5000MB` | Audit log exceeds 5000MB | P0 |
| `Collect log failed` | Log collection failed | P0 |
| `too many logs on` | Too many logs | P1 |
| `no enough space` | Insufficient disk space | P0 |
| `log size exceeds` | Log size exceeds limit | P1 |
| `Collect log failed, no enough space on hostIp` | Host space insufficient | P0 |
| `Collect log failed, too many logs on` | OMS backup path space insufficient | P1 |

### 4.2 Disk Space Keywords

| Keyword | Description | Severity |
|--------|------|----------|
| `No space left on device` | Insufficient disk space | P0 |
| `Disk full` | Disk full | P0 |
| `df` | Disk space check | P3 |

## 7. Common Root Causes and Remediation

| Root Cause | Characteristics | Remediation |
|------|------|----------|
| Service audit log too large | Controller log shows `LOG SIZE is more than 5000MB` | Check whether any anomaly causes audit log to be too large, optimize business to reduce audit log volume |
| OMS backup path storage space insufficient | Controller log shows `too many logs on` | Expand disk on OMS node, or reduce maximum audit log backup count: modify `MAX_NUM_BK_AUDITLOG` in `${CONTROLLER_HOME}/etc/om/componentsauditlog.properties` |
| Service host storage space insufficient | Controller log shows `no enough space on hostIp` | Expand disk on that host, or clean up log directory |
| NodeAgent log collection failure | NodeAgent log shows `log size exceeds` | Expand disk on that node |
| Disk space insufficient | System log shows `No space left on device` | Clean up disk space or expand |
| Dump configuration abnormal | Audit dump configuration query abnormal | Check the `${CONTROLLER_HOME}/etc/om/componentsauditlog.properties` configuration file |

### Diagnosis Steps

1. View Controller log `getLogs.log`, search for keywords:
   - `LOG SIZE is more than 5000MB` → Audit log too large
   - `Collect log failed, too many logs on` → OMS backup path space insufficient (obtain host IP)
   - `Collect log failed, no enough space on hostIp` → Service host space insufficient (obtain hostIp)
2. If OMS backup path space insufficient:
   - Log in to the obtained host IP
   - Check NodeAgent log `collectLog.log`, search for `log size exceeds` or `no enough space`
   - Expand disk on OMS node or reduce `MAX_NUM_BK_AUDITLOG`
3. If service host space insufficient:
   - Log in to the obtained hostIp
   - Check `$BIGDATA_HOME/tmp` directory remaining space
   - Expand disk on that node
4. Wait for the next dump cycle (3:00 AM) to confirm alarm recovery
