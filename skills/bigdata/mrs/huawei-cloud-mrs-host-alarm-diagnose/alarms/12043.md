# DNS Resolution Duration Exceeds Threshold (12043) Alarm Diagnosis

## 1. Diagnosis Introduction

This document covers the diagnosis and handling of the **DNS Resolution Duration Exceeds Threshold (12043)** alarm. The system periodically checks the DNS resolution duration every 30 seconds. When the DNS resolution duration exceeds the threshold (default 1000ms) for multiple consecutive checks (default 6 times), this alarm is generated. DNS resolution duration exceeding the threshold typically indicates a DNS server anomaly, DNS configuration error, or network congestion, and may affect critical functions such as Kerberos authentication and ZooKeeper services.

This section applies only to MRS 3.6.0-LTS.1 and later versions.

Alarm basic information:

| Item | Content |
|------|---------|
| Alarm ID | 12043 |
| Alarm Name | DNS Resolution Duration Exceeds Threshold |
| Alarm Severity | Important |
| Alarm Type | Network fault alarm |
| Auto-Clearable | Yes |
| System Impact | Slow Kerberos secondary authentication, ZooKeeper service abnormality, potential node failure |

## 2. Executable Operations

This section provides the operations that can be executed during alarm analysis.

### 2.1 Check DNS Configuration of the Alarm Node

Execute the following command to obtain the DNS configuration information (/etc/resolv.conf content) of the alarm node and confirm the configured DNS server IP address.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=file-content' \
  -p 'env={"FILE_PATH":"/etc/resolv.conf"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

### 2.2 Ping DNS Server to Confirm Connectivity

Execute the following command to confirm whether the configured DNS server IP address is reachable. If the ping succeeds, the DNS server is reachable; if the ping fails, the network cannot reach the DNS server.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=network-connectivity-test' \
  -p 'env={"TARGET_IP":"<DNS_SERVER_IP>"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details
- `<DNS_SERVER_IP>`: DNS server IP address, obtained from the result of `2.1 Check DNS Configuration of the Alarm Node`

### 2.3 Check Network Bandwidth Utilization

Execute the following command to check the bandwidth utilization of the alarm node's network interface. Check whether the "%ifutil" column value is close to 1.00 (i.e., 100%). If it is close to 100%, it indicates network congestion or insufficient bandwidth.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=network-io' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

### 2.5 Obtain Cluster OMS Active/Standby Node Information

```bash
python3 lakewatch_api_client.py -a query-management-node-info \
  -p 'cluster_id=<cluster_id>'
```

Parameters:
- `<cluster_id>`: Cluster ID

## 3. Manual Operations

This section provides operations that cannot be executed automatically (i.e., commands that require logging into the node manually).

### 3.0 Flush DNS Cache

When the DNS server is reachable but the resolution duration still exceeds the threshold, log in to the alarm node as the root user and execute the following command to flush the DNS cache.

```bash
systemctl restart nscd
```

Or:

```bash
nscd -i hosts
```

After flushing, wait 2 minutes and check whether the alarm is cleared.

### 3.1 Modify DNS Configuration to a Valid Address

When the DNS server cannot be pinged in `2.2 Ping DNS Server to Confirm Connectivity`, modify the alarm node's DNS configuration to a valid DNS server address.

Execute the following command to view the current DNS configuration:
```bash
cat /etc/resolv.conf
```

Use the root user to edit the DNS configuration file and replace the unreachable DNS server address with a valid one:
```bash
vi /etc/resolv.conf
```

After modification, verify whether the DNS configuration takes effect:
```bash
nslookup <domain_name>
```

- `<domain_name>`: Domain name to resolve

If nslookup can resolve the domain name normally, the DNS configuration has taken effect.

### 3.2 Check DNS Server Status

When the DNS server is reachable but the resolution duration still exceeds the threshold, log in to the DNS server node as the root user and check the DNS server service status:

```bash
systemctl status named
```

Or (depending on the DNS service type):
```bash
systemctl status dnsmasq
```

If the DNS service is abnormal, try restarting the DNS service:
```bash
systemctl restart named
```

### 3.3 Test DNS Resolution Duration with nslookup/dig

Log in to the alarm node as the root user and execute the following command to test the DNS resolution duration:

```bash
nslookup <domain_name>
```

Or use the dig command to view detailed resolution duration information:
```bash
dig <domain_name>
```

- `<domain_name>`: Domain name to resolve

Check the Query time in the resolution result. If the resolution duration still exceeds the threshold (default 1000ms), the DNS server still has an issue.

### 3.4 Contact O&M Personnel to Handle Abnormal Network Traffic

When the "%ifutil" column of the network interface in `2.3 Check Network Bandwidth Utilization` is close to 100%, it indicates network congestion or insufficient bandwidth. Contact O&M personnel to confirm whether there is abnormal traffic and handle it.

Execute the following command to view network connections and help identify the source of abnormal traffic:
```bash
netstat -anp | grep ESTABLISHED | wc -l
```

View traffic on each network interface:
```bash
sar -n DEV 1 5
```

If an abnormal traffic process is identified, further investigate by process ID:
```bash
netstat -anp | grep <PID>
```

- `<PID>`: Abnormal process ID

### 3.5 Collect Fault Information

If none of the above steps can clear the alarm, collect fault log information:

1. On the MRS Manager page, navigate to "O&M > Logs > Download"
2. Select "OmmServer" and "NodeAgent" under "Services", and select the hostname from the alarm location info
3. Click the edit button in the upper right corner, set the log collection "Start Time" and "End Time" to 10 minutes before and after the alarm generation time
4. Click "Download"
5. Contact O&M personnel and send the collected fault log information

## 4. Common Fault Handling Solutions

### 4.1 DNS Server Unreachable

**Symptoms**:
- DNS server IP address cannot be pinged
- Network cannot reach the DNS server
- DNS resolution duration persistently exceeds the threshold

**Solution**:
1. Confirm whether the DNS server node is running normally
2. If the DNS server has failed, repair or replace the DNS server
3. If it is a network routing issue, fix the network routing
4. Temporarily modify the alarm node's DNS configuration to a valid DNS server address (refer to `3.1 Modify DNS Configuration to a Valid Address`)
5. Wait 2 minutes and verify whether the alarm is automatically cleared

### 4.2 DNS Cache Expiration Causing Slow Resolution

**Symptoms**:
- DNS server is reachable
- DNS resolution duration still exceeds the threshold
- DNS cache contains expired or incorrect records

**Solution**:
1. Flush the DNS cache (refer to `3.0 Flush DNS Cache`)
2. Wait 2 minutes and verify whether the alarm is automatically cleared
3. If not recovered, test the resolution duration with nslookup/dig (refer to `3.3 Test DNS Resolution Duration with nslookup/dig`)
4. If the resolution duration still exceeds the threshold, check the DNS server status (refer to `3.2 Check DNS Server Status`)

### 4.3 Network Congestion or Insufficient Bandwidth

**Symptoms**:
- The "%ifutil" column of the network interface is close to 100%
- DNS server is reachable but with high latency
- Multiple network-related operations are slow

**Solution**:
1. Contact O&M personnel to confirm whether there is abnormal traffic (refer to `3.4 Contact O&M Personnel to Handle Abnormal Network Traffic`)
2. Handle the abnormal traffic process to release bandwidth
3. Wait 2 minutes and verify whether the alarm is automatically cleared
4. If not recovered, collect fault information and contact O&M personnel (refer to `3.5 Collect Fault Information`)

### 4.4 DNS Server Performance Issue

**Symptoms**:
- DNS server is reachable
- DNS cache has been flushed but resolution duration still exceeds the threshold
- Network bandwidth is normal
- DNS server service status is abnormal or load is too high

**Solution**:
1. Log in to the DNS server to check service status (refer to `3.2 Check DNS Server Status`)
2. If the service is abnormal, restart the DNS service
3. Check the DNS server load and resource usage
4. Wait 2 minutes and verify whether the alarm is automatically cleared
5. If not recovered, collect fault information and contact O&M personnel (refer to `3.5 Collect Fault Information`)

## 5. Alarm Diagnosis Flow

### 5.1 Diagnosis Flow Chart

```
Start
  |
  v
Obtain hostname from alarm details
  |
  v
Check DNS configuration of the alarm node (cat /etc/resolv.conf)
  |
  v
Ping DNS server to confirm connectivity (ping)
  |
  +--- DNS server unreachable ---> Modify DNS configuration to a valid address
  |                                  |
  |                                  v
  |                         Wait 2 minutes, check whether alarm is cleared
  |                                  |
  |                                  +--- Yes ---> Done
  |                                  |
  |                                  +--- No ---> Check network bandwidth utilization
  |
  +--- DNS server reachable ---> Flush DNS cache (manually execute systemctl restart nscd)
                                   |
                                   v
                         Wait 2 minutes, check whether alarm is cleared
                                   |
                                   +--- Yes ---> Done
                                   |
                                   +--- No ---> Check network bandwidth utilization
                                                  |
                                                  v
                                    Check network bandwidth utilization (sar -n DEV 1 1)
                                      Check whether "%ifutil" is close to 100%
                                                  |
                                                  +--- Close to 100% ---> Contact O&M personnel to handle abnormal traffic
                                                  |                          |
                                                  |                          v
                                                  |                 Wait 2 minutes, check whether alarm is cleared
                                                  |                          |
                                                  |                          +--- Yes ---> Done
                                                  |                          |
                                                  |                          +--- No ---> Collect fault information
                                                  |
                                                  +--- Not close to 100% ---> Check DNS server status
                                                                               |
                                                                               v
                                                                     Is DNS service normal?
                                                                               |
                                                                               +--- Abnormal ---> Restart DNS service
                                                                               |                   |
                                                                               |                   v
                                                                               |          Wait 2 minutes, check whether alarm is cleared
                                                                               |                   |
                                                                               |                   +--- Yes ---> Done
                                                                               |                   |
                                                                               |                   +--- No ---> Collect fault information
                                                                               |
                                                                               +--- Normal ---> Collect fault information
  |
  v
End (alarm cleared)
```

### 5.2 Diagnosis Conclusion Output

Based on the diagnosis flow above, output one of the following conclusions:

| Diagnosis Conclusion | Recommended Action |
|----------------------|---------------------|
| DNS server unreachable | Modify DNS configuration to a valid address, fix network routing or DNS server |
| DNS cache expired | Flush DNS cache |
| Network congestion or insufficient bandwidth | Contact O&M personnel to handle abnormal traffic |
| DNS server performance issue | Check and restart DNS service |
| Alarm persists after handling | Collect fault information and contact O&M personnel |
