## 2. Log Directory

### 2.1 Log Priority

> When analyzing semaphore set usage anomalies, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |----------|----------|-------------|
> | 1 | System log | System-level log information |
> | 2 | Process log | Abnormal process logs |

### 2.2 Log Paths

| Log File | Path | Purpose | Priority |
|----------|------|---------|----------|
| System log | `/var/log/messages` | System-level log information | 1 |
| Process log | `${BIGDATA_LOG_HOME}/<service>/` | Abnormal process logs | 2 |

### 3.1 System Log Format


| Field | Description | Example |

| Keyword | Description | Severity |
|---------|-------------|----------|
| `ipcs` | Semaphore set view command | P3 |

## 7. Common Root Causes and Repair Solutions

### Semaphore Set Check

| Check Item | Description | System Parameter |
|------------|-------------|------------------|
| Total semaphore sets | `ipcs -s \| wc -l` | Compare with SEMMNI |
| System semaphore parameters | `cat /proc/sys/kernel/sem` | SEMMSL SEMMNS SEMOPM SEMMNI |
| Semaphore set details | `ipcs -s` | View owner and creator PID |
| Orphaned semaphores | Semaphore set owner process no longer exists | Needs cleanup |

### Root Cause Classification Table

| Root Cause | Characteristics | Repair Solution |
|------------|----------------|-----------------|
| Process semaphore leak | Semaphores continuously growing, no corresponding live process | Locate and clean orphaned semaphores: `ipcrm -s <semid>` |
| Database semaphore usage | oracle/db2 user has large number of semaphores | Normal behavior, check whether SEMMSL configuration is sufficient |
| Hadoop/HDFS process usage | hdfs/yarn user has many semaphores | Check whether DataNode/NodeManager process count is abnormal |
| Zombie process residue | Process is dead but semaphores not released | Compare cpid in ipcs with live processes in ps, clean orphaned semaphores |
| Application not properly cleaned | Semaphores left after restart | Check application shutdown hooks, restart process to release semaphores |
| SEMMNI configured too low | Semaphore set usage > 80%, total approaching SEMMNI | Increase system limit: `sysctl -w kernel.sem="500 512000 64 4096"` |
| Abnormal process consuming semaphores | ipcs -s -p shows a process with large number of semaphores | Analyze process logs, restart abnormal process |

### Process Restart Operations

After confirming the abnormal process, restart based on process type:

| Process Type | Restart Command |
|--------------|-----------------|
| httpd | `su - omm` -> `sh ${BIGDATA_HOME}/om-server/Apache-httpd-*/setup/restarthttpd.sh` |
| Manager web (tomcat) | `su - omm` -> `sh ${BIGDATA_HOME}/om-server/tomcat/bin/shutdown.sh; sh ${BIGDATA_HOME}/om-server/tomcat/bin/startup.sh` |
| Other processes | Contact technical support to confirm restart method |

### System Limit Adjustment

| Operation | Command | Description |
|-----------|---------|-------------|
| Temporary adjustment | `sysctl -w kernel.sem="500 512000 64 4096"` | Takes effect immediately, lost on reboot |
| Permanent adjustment | `echo "kernel.sem = 500 512000 64 4096" >> /etc/sysctl.conf` -> `sysctl -p` | Takes effect permanently |
| Clean orphaned semaphores | `ipcrm -s <semid>` | Delete specified semaphore set |
