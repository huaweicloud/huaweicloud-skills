# Key File Permission Anomaly Log Information Description

## I. Alarm Type

| Item | Content |
|------|------|
| Alarm Name | Key file permission anomaly |
| Alarm ID | 12041 |
| Alarm Type | File permission monitoring |
| Detection Script | check_file_owner.py / check_ha_permission.py |

## II. Log Directory

>
> | Priority | Log Type | Description |
> |--------|----------|------|

> | 2 | HA logs | HA synchronized file permission detection results |

## IV. Abnormal Error Keywords

### 4.1 File Owner Related Keywords

| Keyword | Meaning | Severity |
|--------|------|----------|
| `user XXX not equal YYY` | File owner error | 🔴 P0 |
| `group XXX not equal YYY` | File user group error | 🔴 P0 |
| `group XXX not equal secadmin` | User group error (LinxOS) | 🔴 P0 |

### 4.2 File Permission Related Keywords

| Keyword | Meaning | Severity |
|--------|------|----------|
| `mask XXX not equal YYY` | File permission error | 🔴 P0 |
| `mask XXX is smaller than YYY` | Insufficient permission | 🔴 P0 |
| `not has read permission` | Missing read permission | 🟠 P1 |
| `not has write permission` | Missing write permission | 🟠 P1 |
| `dir not has x permission` | Missing execute permission | 🟠 P1 |

### 4.3 File Type and Disk Related Keywords

| Keyword | Meaning | Severity |
|--------|------|----------|
| `is dir not file` | Type mismatch (actually a directory but configured as a file) | 🟠 P1 |
| `is a regularfile not dir` | Type mismatch (actually a file but configured as a directory) | 🟠 P1 |
| `size useage XX% big than YY%` | Disk usage too high | 🟠 P1 |
| `inode useage XX% big than YY%` | Inode usage too high | 🟠 P1 |
| `file XXX is invalid` | File is invalid | 🟡 P2 |

### 4.4 Abnormal Keyword Priority and Problem Causes

| Priority | Keyword Combination | Problem Cause | Possible Impact |
|--------|------------|----------|----------|
| P0 | `user XXX not equal YYY` | File owner is not the expected user | Security risk, service abnormality |
| P0 | `group XXX not equal YYY` | File user group is not the expected group | Security risk, service abnormality |
| P0 | `mask XXX not equal YYY` | File permission does not match expectation | Security risk, service abnormality |
| P0 | `mask XXX is smaller than YYY` | Permission is less than expected value | Functionality abnormality |
| P1 | `not has read/write/x permission` | Missing corresponding permission | Functionality abnormality |
| P1 | `is dir not file` / `is a regularfile not dir` | File type mismatch | Detection false positive |
| P1 | `size useage XX% big than YY%` | Insufficient disk space | Write failure |
| P1 | `inode useage XX% big than YY%` | Inode exhaustion | Unable to create files |

## VI. System Commands

### 6.1 View keyfile Configuration Check Results

```bash
python3 lakewatch_api_client.py -a collect_alarm_log_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'alarm_time=<alarm_time>' \
  -p 'log_directory=/var/log/Bigdata/nodeagent/scriptlog' \
  -p 'log_file_name=agent_alarm_py.log*' \
  -p 'keywords=["keyfile","not equal","mask"]' \
  -p 'log_type=local' \
  -p 'node_name=<node_name>'
```

**keyfile configuration format description:**

```
server|role|file_name|user|group|mask|file_type|size_usage_limit|inode_usage_limit|mask_compare_type
```

| Field | Description | Example |
|------|------|------|
| server | Server type | - |
| role | Role name | HA, Controller, OMS |
| file_name | File path (supports environment variables) | `${BIGDATA_HOME}/xxx` |
| user | Expected user | omm |
| group | Expected user group | omm |
| mask | Expected permission | drwxr-xr-x |
| file_type | File type | file/dir |
| size_usage_limit | Disk usage threshold (optional) | NA or 80 |
| inode_usage_limit | Inode usage threshold (optional) | NA or 80 |
| mask_compare_type | Permission comparison method | == or >= |

**Permission comparison method description:**

- `==`: Actual permission must be exactly equal to the expected permission
- `>=`: Actual permission must be greater than or equal to the expected permission (each bit's permission character cannot be less than the expected value)

**LinxOS special configuration:**

- The group field of the `/etc/group` file should be configured as `secadmin` (instead of omm)

## VII. Common Root Causes and Repair Suggestions

### 7.1 File Owner Error

**Symptom:** Logs show `user XXX not equal YYY`

**Repair Suggestion:** Execute `chown <correct_user>:<correct_user_group> <file_path>`, must be executed manually after user confirmation

### 7.2 File Permission Error

**Symptom:** Logs show `mask XXX not equal YYY` or `mask XXX is smaller than YYY`

**Repair Suggestion:** Execute `chmod` to correct permissions, must be executed manually after user confirmation

### 7.3 File User Group Error

**Symptom:** Logs show `group XXX not equal YYY`

**Repair Suggestion:** Execute `chgrp <correct_user_group> <file_path>`, must be executed manually after user confirmation

### 7.4 File Type Mismatch

**Symptom:** Logs show `is dir not file` or `is a regularfile not dir`

**Repair Suggestion:**

- Check whether the file_type in the keyfile configuration matches the actual file type
- If the file type does not match, a file of the correct type needs to be recreated

### 7.5 Disk Space or Inode Usage Too High

**Symptom:** Logs show `size useage XX% big than YY%` or `inode useage XX% big than YY%`

**Repair Suggestion:** Clean up disk space or expand capacity, must be executed manually after user confirmation

### 7.6 File Does Not Exist

**Symptom:** The file path mentioned in the alarm does not exist

**Repair Suggestion:**

- Check whether the file path in the filesync.xml configuration is correct
- If it is a temporary file (e.g., sed script), it can be ignored
- If it is a required file, it needs to be recreated or restored from backup

## IX. Configuration Files and Script Paths

### Configuration Files

| Configuration File | Purpose |
|----------|------|
| `${OMS_RUN_PATH}/workspace/ha/module/hasync/plugin/conf/filesync.xml` | HA file synchronization configuration |
| `${BIGDATA_HOME}/om-agent/nodeagent/etc/agent/autocheck/keyfile` | Permission check configuration |

### Related Script Paths

| Script | Path | Detection Period |
|------|------|----------|
| check_file_owner.py | `${BIGDATA_HOME}/om-agent/nodeagent/etc/agent/autocheck/check_file_owner.py` | Every 5 minutes |
| check_ha_permission.py | `${BIGDATA_HOME}/om-agent/nodeagent/etc/agent/autocheck/check_ha_permission.py` | Every 10 minutes |
| alarm_tool.py | `${BIGDATA_HOME}/om-agent/nodeagent/etc/agent/autocheck/alarm_tool.py` | - |

### Detection Source Determination

| Path Source | Detection Script | Description |
|----------|----------|------|
| Path is in filesync.xml | check_ha_permission.py | Detects HA synchronized file permissions |
| Path is in keyfile | check_file_owner.py | Detects file permissions configured in keyfile |

### Alarm Recovery Description

After the repair is completed, the system will automatically check at the next detection period to confirm whether the alarm is recovered:

- check_file_owner.py: executed every 5 minutes
- check_ha_permission.py: executed every 10 minutes

### Excluded Directories

The following directories will be automatically excluded by check_ha_permission.py and will not be checked:

- `${BIGDATA_DATA_HOME}/LocalBackup/nas`
- `${BIGDATA_DATA_HOME}/LocalBackup/nas-verify`
