# Metadata Periodic Backup to Third-Party Server Not Configured (12057) Alarm Diagnosis

## 1. Diagnosis Introduction

This document covers the diagnosis and handling of the **Metadata Periodic Backup to Third-Party Server Not Configured (12057)** alarm. This alarm indicates that the cluster metadata does not have a periodic backup to a third-party server task configured. After system installation, the system checks whether metadata has a periodic backup to a third-party server task, and then checks once every hour. If not configured, an alarm is generated. After the user creates a metadata periodic backup to a third-party server task, the alarm is cleared.

Alarm basic information:

| Item | Content |
|------|---------|
| Alarm ID | 12057 |
| Alarm Name | Metadata Periodic Backup to Third-Party Server Not Configured |
| Alarm Severity | Important (before MRS 3.3.1) / Minor (MRS 3.3.1 and later) |
| Alarm Type | Configuration alarm |
| Auto-Clearable | Yes |
| System Impact | When both the active and standby management nodes fail simultaneously and local backup data is lost, the cluster metadata cannot be restored using backup packages |

## 2. Executable Operations

This section provides the operations that can be executed during alarm analysis.

### 2.1 Obtain Cluster OMS Active/Standby Node Information

```bash
python3 lakewatch_api_client.py -a query-management-node-info \
  -p 'cluster_id=<cluster_id>'
```

Parameters:
- `<cluster_id>`: Cluster ID

### 2.2 Collect Controller Service Logs from the Alarm Node

Execute the following command to collect relevant log information of the Controller service on the alarm node for analyzing backup task configuration and execution status.

```bash
python3 lakewatch_api_client.py -a collect_alarm_log_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'alarm_time=<alarm_time>' \
  -p 'alarm_duration_minutes=30' \
  -p 'log_directory=/var/log/Bigdata/controller' \
  -p 'log_file_name=controller.log*' \
  -p 'keywords=["backup","Backup","ERROR","WARN","exception"]' \
  -p 'log_type=local' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<alarm_time>`: Alarm trigger time
- `<node_name>`: OMS active node name

### 2.3 Check Backup-Related Configuration Files

Execute the following command to check the backup-related configuration files on the node and determine whether a periodic backup to a third-party server task has been configured.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=file-content' \
  -p 'env={"FILE_PATH":"/opt/soft/om/properties.ini"}' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

### 2.4 Obtain OMS Key Directories

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=oms_core_dir' \
  -p 'node_name=<node_name>'
```

Parameters:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Alarm node name, obtained from alarm details

## 3. Manual Operations

This section provides operations that cannot be executed automatically (i.e., operations that require logging into the Manager interface or the node manually).

### 3.1 View Current Backup Task Configuration

On the FusionInsight Manager interface, view the currently configured backup tasks:

1. Log in to the FusionInsight Manager interface
2. Navigate to "O&M > Backup & Restore > Backup Management"
3. View the current configured backup task list
4. Check whether a metadata periodic backup to a third-party server task exists

### 3.2 Create a Metadata Periodic Backup to Third-Party Server Task

On the FusionInsight Manager interface, create a backup task:

1. Log in to the FusionInsight Manager interface
2. Navigate to "O&M > Backup & Restore > Backup Management > Create"
3. Configure the backup task. The backup data to be configured must match the "additional information" in the alarm
4. Backup target types can be selected from:
   - Remote HDFS (RemoteHDFS)
   - NAS (NFS/CIFS)
   - SFTP server (SFTP)
   - OBS
5. Configure the backup period as periodic backup
6. Click "OK" to create the backup task

### 3.3 Download Controller Service Logs

On the FusionInsight Manager interface, download Controller service logs for fault analysis:

1. Log in to the FusionInsight Manager interface
2. Navigate to "O&M > Logs > Download"
3. Select "Controller" under "Services" and click "OK"
4. Click the edit button in the upper right corner, set the log collection time range to approximately 10 minutes before and after the alarm generation time
5. Click "Download"

### 3.4 Check Backup Task Execution History

On the FusionInsight Manager interface, check the execution history of backup tasks:

1. Log in to the FusionInsight Manager interface
2. Navigate to "O&M > Backup & Restore > Backup Management"
3. Select the corresponding backup task and view its execution history
4. Check whether the backup task executed successfully and whether there are failure records

## 4. Common Fault Handling Solutions

### 4.1 Metadata Periodic Backup to Third-Party Server Not Configured

**Symptoms**:
- System check finds that metadata does not have a periodic backup to a third-party server task configured
- Alarm persists

**Solution**:
1. On the FusionInsight Manager interface, navigate to "O&M > Alarm > Alarms"
2. Click the alarm in the alarm list and obtain the data module that generated the alarm from the "Additional Information"
3. Navigate to "O&M > Backup & Restore > Backup Management > Create"
4. Configure the backup task with backup data matching the alarm's additional information
5. Select backup to a third-party server (RemoteHDFS, NAS, SFTP, or OBS)
6. Configure as periodic backup
7. After successfully creating the backup task, wait 2 minutes and check whether the alarm is cleared

### 4.2 Alarm Not Cleared After Creating Backup Task

**Symptoms**:
- A metadata periodic backup to a third-party server task has been created
- The alarm still exists

**Solution**:
1. Check whether the backup task configuration matches the data module in the alarm's additional information
2. Check whether the backup task executed successfully by viewing the execution history
3. If the backup task execution failed, check whether the third-party server connection is normal
4. On the FusionInsight Manager interface, navigate to "O&M > Logs > Download"
5. Select "Controller" under "Services", click "OK", and download logs (time range: 10 minutes before and after the alarm generation time)
6. Collect fault log information and contact O&M personnel

### 4.3 Third-Party Server Connection Abnormal

**Symptoms**:
- Backup task created successfully but execution failed
- Logs show inability to connect to the third-party server

**Solution**:
1. Check whether the network connection to the third-party server is normal
2. Check whether the authentication information for the third-party server is correct
3. Check whether the storage space on the third-party server is sufficient
4. After fixing the connection issue, re-execute the backup task
5. Wait 2 minutes and check whether the alarm is cleared

## 5. Alarm Diagnosis Flow

### 5.1 Diagnosis Flow Chart

```
Start
  |
  v
Obtain alarm additional information, determine the data module to be backed up
  |
  v
Check whether a metadata periodic backup to a third-party server task is already configured
  |
  +--- Not configured ---> Create a periodic backup to third-party server task
  |                           |
  |                           v
  |                     Wait 2 minutes, check whether alarm is cleared
  |                           |
  |                           +--- Alarm cleared ---> Done
  |                           |
  |                           +--- Alarm not cleared ---> Check whether backup task config matches data module
  |                                                          |
  |                                                          v
  |                                                    Download Controller service logs
  |                                                          |
  |                                                          v
  |                                                    Contact O&M personnel
  |
  +--- Already configured ---> Check backup task execution history
                                |
                                +--- Executed successfully ---> Wait 2 minutes, check whether alarm is cleared
                                |                                  |
                                |                                  +--- Alarm cleared ---> Done
                                |                                  |
                                |                                  +--- Alarm not cleared ---> Download Controller logs, contact O&M
                                |
                                +--- Execution failed ---> Check third-party server connection
                                                            |
                                                            v
                                                      Fix connection issue, re-execute backup
                                                            |
                                                            v
                                                      Wait 2 minutes, check whether alarm is cleared
  |
  v
End (alarm cleared)
```

### 5.2 Diagnosis Conclusion Output

Based on the diagnosis flow above, output one of the following conclusions:

| Diagnosis Conclusion | Recommended Action |
|----------------------|---------------------|
| Metadata periodic backup not configured | Create a periodic backup to third-party server task |
| Backup task configuration does not match alarm | Modify backup task configuration to match alarm additional information |
| Backup task execution failed | Check third-party server connection, fix and re-execute |
| Alarm persists after handling | Collect Controller logs, contact O&M personnel |
