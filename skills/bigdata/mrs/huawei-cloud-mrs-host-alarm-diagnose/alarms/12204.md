# Disk IO Read Wait Time Exceeds Threshold Log Information

## 1. Alarm Type

| Item | Content |
|------|---------|
| Alarm Name | Disk IO Read Wait Time Exceeds Threshold |
| Alarm ID | 12204 |
| Alarm Type | Physical resource alarm |

---

## 2. Log Directory

### 2.1 Log Priority

> When analyzing disk IO read wait anomalies, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |----------|----------|-------------|
> | 1 | System log | System-level disk IO logs |
> | 2 | Kernel log | Hardware error records |
> | 3 | Disk SMART information | Disk health status |

### 2.2 Log Paths

| Log File | Path | Purpose | Priority |
|----------|------|---------|----------|
| System log | `/var/log/messages` | System-level disk IO logs | 1 |
| Kernel log | `/var/log/kern.log` or `dmesg` | Hardware error records | 2 |
| Disk SMART | Obtained via `smartctl` | Disk health status | 3 |

## 3. Log Time Format

### 3.1 System Log Format

```
Dec 20 10:30:15 hostname kernel: [message]
```

| Field | Description | Example |

| Hostname | Host name | `hostname` |

## 4. Exception Error Keywords

### 4.1 Disk IO Read Wait Keywords

| Keyword | Description | Severity |
|---------|-------------|----------|
| `r_await` | Average read operation wait time (ms); >10ms requires attention, >20ms triggers alarm | P0 |
| `svctm` | Average service time (ms); >5ms requires attention | P1 |
| `%util` | Disk utilization; >80% approaching saturation | P1 |
| `aqu-sz` | I/O queue depth; >4 indicates queue buildup | P1 |
| `r/s` | Read operations per second | P3 |
| `rkB/s` | Kilobytes read per second | P3 |
| `rrqm/s` | Merged read requests per second | P3 |

### 4.2 Hardware Error Keywords

| Keyword | Description | Severity |
|---------|-------------|----------|
| `I/O error` | I/O error | P0 |
| `read-only` | File system became read-only | P0 |
| `device reset` | Device reset | P1 |
| `timeout` | I/O timeout | P1 |
| `ata` | ATA error | P1 |
| `scsi` | SCSI error | P1 |

### 4.3 SMART Health Keywords

| Keyword | Description | Severity |
|---------|-------------|----------|
| `Reallocated_Sector_Ct` | Reallocated sector count; >0 requires attention | P1 |
| `Current_Pending_Sector` | Pending sectors | P1 |
| `Offline_Uncorrectable` | Offline uncorrectable error | P0 |

## 7. Common Root Causes and Repair Solutions

### Key Metric Judgment Matrix

| Metric | Normal | Warning | Critical | Description |
|--------|--------|---------|----------|-------------|
| r_await | <5ms | 10-30ms | >30ms | Read operation wait time |
| %util | <50% | 50-80% | >80% | Disk busy ratio |
| aqu-sz | <2 | 2-4 | >4 | I/O queue buildup |
| svctm | <2ms | 2-5ms | >5ms | Average service time |

### Key Judgment Logic

| Condition Combination | Conclusion | Next Step |
|-----------------------|------------|-----------|
| High r_await + High %util | Disk bandwidth/throughput saturated | Scale up disk / Replace with SSD / Distribute load |
| High r_await + Low %util | Possible hardware issue / queue configuration / RAID rebuild | Check hardware SMART and dmesg |
| High r_await + Low svctm | Long queue wait time (scheduling issue) | Adjust I/O scheduler |
| High r_await + High svctm | Slow hardware service (disk itself is slow) | Replace disk |
| High r/s + Low rkB/s | Many small IOs (random read, low efficiency) | Optimize read pattern, increase read-ahead |
| Low r/s + High rkB/s | Few large IOs (sequential read, high efficiency) | Normal pattern, consider scaling up |

### Root Cause Classification Table

| Root Cause | Characteristics | Repair Solution |
|------------|----------------|-----------------|
| Unreasonable alarm threshold configuration | r_await below default threshold 10s, no business impact | Log in to Manager to modify threshold: O&M > Alarm > Threshold Settings > Cluster Name > Host > Disk > Average Time Required per Read Operation |
| Disk bandwidth saturated | %util > 80%, high r_await | Scale up disk / Replace with SSD / Distribute load to other nodes |
| Large amount of random reads | High r/s, low rkB/s, many small IOs | Optimize application read pattern, change random reads to sequential reads, increase read-ahead |
| Insufficient cache | Low memory cached, repeatedly reading same files | Increase memory / Adjust cache strategy |
| Insufficient read-ahead | Sequential read but fragmented | Increase `read_ahead_kb`: `echo 2048 > /sys/block/<dev>/queue/read_ahead_kb` |
| atime update overhead | Reads accompanied by large amounts of metadata writes | Mount with `noatime` option: `mount -o remount,noatime <mount_point>` |
| Frequent swap | vmstat si > 0, reading swap area | Increase memory / Set `swappiness=0`: `sysctl vm.swappiness=0` |
| I/O scheduler mismatch | SSD using cfq scheduler | Change to none/mq-deadline: `echo mq-deadline > /sys/block/<dev>/queue/scheduler` |
| Impending disk failure | smartctl reports errors, dmesg reports errors | Replace disk |
| RAID degraded rebuild | Sudden I/O surge, abnormal RAID status | Avoid rebuild window / Replace with faster disk |
| Hot file concentration | Single disk hotspot, other disks idle | Balance data distribution |
| Peak business period | High r_await during specific time periods | Scale up node or stagger high-IO business execution |
