## 3. Log Time Format

### 3.1 Format A: Space-separated format (HA log, runtime log)

```
2024-12-20 10:30:15.123 CST  [Thread-1234] [Level] [Module] Message content
```

| Field | Description | Example |
|------|-------------|---------|
| Date and time | Year-Month-Day Hour:Minute:Second.Millisecond | `2024-12-20 10:30:15.123` |
| Timezone | CST timezone | `CST` |
| Thread ID | Thread identifier | `[Thread-1234]` |
| Log level | INFO/WARN/ERROR/FATAL | `[ERROR]` |
| Module name | Module identifier | `[Knox]` |
| Message content | Log body | `gateway service error` |

### 3.2 Format B: T-separated format (GC log)

```
2024-12-20T10:30:15.123+08:00: [GC pause (G1 Evacuation Pause) 4096M->1024M(4096M) 200.123ms]
```

## 4. Detailed Log Description

### 4.1 HA Resource Log (knox.log)

#### Log Path
```
/var/log/Bigdata/omm/oms/ha/scriptlog/knox.log*
```

#### Exception Error Keywords

| Keyword | Meaning | Severity |
|---------|---------|----------|
| `ERROR` | Error message | 🟠 P1 |
| `Failed` | Operation failed | 🟠 P1 |
| `connect knox failed` | API call failed | 🟠 P1 |
| `knox does not listen the float ip` | Port not listening on floating IP | 🟠 P1 |
| `stopService knox begin` | Service is stopping | 🟡 P2 |
| `startService knox begin` | Service is starting | 🟡 P2 |
| `knox pid is:` | Process PID info | 🟢 P3 |
| `Resource Status Notify` | Resource status notification | 🟢 P3 |

#### Keyword Priority and Root Cause

| Priority | Keyword Combination | Root Cause | Possible Impact |
|----------|---------------------|------------|-----------------|
| P1 | `knox does not listen the float ip` | Port not listening on floating IP | Service unavailable |
| P1 | `connect knox failed` | API call failed | Service unavailable |
| P1 | `ERROR` + `knox` | Knox service exception | Service unavailable |
| P1 | `Failed` | Operation failed | Functional exception |
| P2 | `stopService knox begin` | Normal stop | No impact |
| P2 | `startService knox begin` | Normal start | No impact |
