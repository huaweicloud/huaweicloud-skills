## II. Log Directory

### 2.1 Log Priority

> When analyzing network write packet error rate anomalies, it is recommended to view logs in the following priority order:
>
> | Priority | Log Type | Description |
> |----------|----------|-------------|
> | 1 | System log | System-level network log information |
> | 2 | Kernel log | Kernel network error records |

### 2.2 Log Path

| Log File | Path | Purpose | Priority |
|----------|------|---------|----------|
| System log | `/var/log/messages` | System-level network log information | 1 |
| Kernel log | `/var/log/kern.log` or `dmesg` | Kernel network error records | 2 |

## VII. Common Root Causes and Repair Solutions

| Root Cause | Characteristics | Repair Solution |
|------------|----------------|-----------------|
| Unreasonable alarm threshold configuration | Error rate below default threshold 0.5%, no business impact | Log in to Manager to modify threshold: O&M > Alarm > Threshold Settings > Cluster Name > Host > Network Write Info > Write Packet Error Rate |
| Poor network environment quality | Physical network errors, multiple nodes alarming simultaneously | Contact network administrator to check switches, cables, optical modules, and other physical network devices |
| Cable or optical module fault | High carrier error rate, many CRC errors | Replace cables or optical modules, check physical interface connections |
| NIC link abnormal | System log shows `Link detected: no` or `no carrier` | Check cable connection, replace faulty cables or optical modules |
| NIC speed/duplex mismatch | Error rate persistently high, NIC negotiated speed abnormal | Manually set NIC speed and duplex mode: `ethtool -s <nic_name> speed <speed> duplex <full|half>` |
| NIC transmit queue overflow | Many FIFO errors, high transmit load | Increase NIC transmit queue: `ethtool -G <nic_name> tx <value>` |
