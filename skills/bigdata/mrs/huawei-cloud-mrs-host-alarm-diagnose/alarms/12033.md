# Slow Disk Failure Alarm Diagnosis

## 1. Diagnosis Introduction

This document mainly covers the diagnosis and handling of the **Slow Disk Failure (12033)** alarm. A slow disk failure typically refers to a storage device with severely degraded read/write performance, causing excessive system IO wait times and affecting overall cluster performance.

Alarm basic information:

| Item | Content |
|------|------|
| Alarm ID | 12033 |
| Alarm Name | Slow disk failure |
| Alarm Severity | Major |
| Alarm Type | Hardware failure alarm |
| Auto-clearable | No |
| System Impact | Disk read/write performance degradation, causing IO wait, may affect data read/write and task execution |

---

## 2. Executable Operations

This section provides the related operations that can be executed during the alarm analysis process.

### 2.1 Determine Whether the Alarm Cluster is a Virtual Machine

Execute the following command. If the result is `none`, it is a physical machine. If the output is `kvm`, `vmware`, `oracle` or other virtualization platform names, it is a virtual machine environment.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=systemd-detect-virt' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information

### 2.2 Determine Whether the `df -h` Output Contains the Disk Name

Execute the following command. If the command result contains the alarm disk name, the alarm disk name exists; otherwise, it does not.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=disk-space' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information

### 2.3 Determine Whether the Mapping Between Disk Name and Disk Device Can Be Viewed

Execute the following command. If the command result contains the alarm disk information, the mapping between the alarm disk and device exists; otherwise, it does not.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=lsblk' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information

### 2.4 Determine Whether the Alarm Disk Has RAID Configured

Execute the following command. If the third column of the command result showing the alarm disk name displays `ATA`, `SATA`, or `SAS`, the disk does not have RAID configured. If it displays other information, the disk may have RAID configured.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=lsscsi' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information

### 2.5 Determine Whether Non-RAID Hardware Supports SMART

Execute the following command. If the result contains "SMART support is: Enabled", the disk supports SMART. If the result contains "Device does not support SMART" or other content, the disk does not support SMART.

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=smartctl_-i' \
  -p 'env={"DISK_NAME":"<DISK_NAME>"}' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information
- `<DISK_NAME>`: Alarm disk name

### 2.6 Obtain Cluster OMS Active/Standby Node Information

```bash
python3 lakewatch_api_client.py -a query-management-node-info \
  -p 'cluster_id=<cluster_id>'
```

Parameter description:
- `<cluster_id>`: Cluster ID

### 2.7 Obtain OMS Key Directories

```bash
python3 lakewatch_api_client.py -a collect_alarm_node_res_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'strategy_name=oms_core_dir' \
  -p 'node_name=<node_name>'
```

Parameter description:
- `<cluster_id>`: Cluster ID
- `<node_name>`: Name of the node where the alarm occurred, obtained from the alarm information

## 3. Non-Executable Operations

This section provides the related operations that cannot be executed during the alarm analysis process (i.e., commands that need to be executed manually after logging into the node).

### 3.1 Determine Whether the RAID Disk Supports SMART

Execute `smartctl -d [sat|scsi]+megaraid,[DID] -H --all <alarm_dis_name>` to check whether the hardware supports SMART.

- `[sat|scsi]` indicates the disk type; both types above need to be attempted.
- `[DID]` indicates the slot information; values 0 through 15 need to be attempted.
- `<alarm_dis_name>`: Disk name, obtained from the alarm information

Execution example:
```bash
smartctl -d sat+megaraid,0 -H --all <alarm_dis_name>
smartctl -d sat+megaraid,1 -H --all <alarm_dis_name>
smartctl -d sat+megaraid,2 -H --all <alarm_dis_name>
smartctl -d sat+megaraid,3 -H --all <alarm_dis_name>
smartctl -d sat+megaraid,4 -H --all <alarm_dis_name>
...
smartctl -d sat+megaraid,15 -H --all <alarm_dis_name>
```

Try different combinations of disk type and slot information. If the result shows "SMART support is: Enabled", the disk supports SMART. Record the disk type and slot information combination used when the command succeeds. If none of the above command combinations show "SMART support is: Enabled" after trying them all, the disk does not support SMART.

### 3.2 View RAID Disk Basic Information to Determine Whether the Disk Is Normal

Execute `smartctl -d [sat|scsi]+megaraid,[DID] -H --all <alarm_dis_name>` to view SMART basic information and determine whether the disk is normal.

- `[sat|scsi]` indicates the disk type, determined according to `3.1 Determine Whether the RAID Disk Supports SMART`.
- `[DID]` indicates the slot information, determined according to `3.1 Determine Whether the RAID Disk Supports SMART`.
- `<alarm_dis_name>`: Alarm disk name

For example, execute:
```bash
smartctl -d sat+megaraid,2 -H --all /dev/sda
```

View the "SMART overall-health self-assessment test result" content in the command result:
- If it is "FAILED", the disk is faulty and needs to be replaced
- If it is "PASSED", further check the count of "Reallocated_Sector_Ct" or "Elements in grown defect list". If it is greater than 100, the disk is considered faulty and needs to be replaced

### 3.3 View the RAID Disk GLIST List to Determine Whether the Disk Is Normal

Execute `smartctl -d [sat|scsi]+megaraid,[DID] -l error -H <alarm_dis_name>` to view the disk GLIST list and further determine whether the disk is normal.

- `[sat|scsi]` indicates the disk type, determined according to `3.1 Determine Whether the RAID Disk Supports SMART`.
- `[DID]` indicates the slot information, determined according to `3.1 Determine Whether the RAID Disk Supports SMART`.
- `<alarm_dis_name>`: Alarm disk name

For example, execute:
```bash
smartctl -d sat+megaraid,2 -l error -H <alarm_dis_name>
```

View the "Command/Feature_name" column in the command result:
- If "READ SECTOR(S)" or "WRITE SECTOR(S)" appears, the disk has bad sectors
- If other errors appear, the disk circuit board has problems
- Both errors indicate the disk is abnormal and needs to be replaced
- If "No Errors Logged" is displayed, there are no error logs, and disk SMART self-test can be triggered

### 3.4 RAID Disk SMART Self-Test

Execute `smartctl -d [sat|scsi]+megaraid,[DID] -t long <alarm_dis_name>` to trigger the disk SMART self-test.

- `[sat|scsi]` indicates the disk type, determined according to `3.1 Determine Whether the RAID Disk Supports SMART`.
- `[DID]` indicates the slot information, determined according to `3.1 Determine Whether the RAID Disk Supports SMART`.
- `<alarm_dis_name>`: Alarm disk name

For example, execute:
```bash
smartctl -d sat+megaraid,2 -t long <alarm_dis_name>
```

After the command is executed, the self-test completion time will be prompted. After waiting for the self-test to complete, re-execute `3.2 View RAID Disk Basic Information to Determine Whether the Disk Is Normal` and `3.3 View the RAID Disk GLIST List to Determine Whether the Disk Is Normal` to check whether the disk is normal.

### 3.5 View Non-RAID Disk Basic Information to Determine Whether the Disk Is Normal

Execute `smartctl -H --all <alarm_dis_name>` to view SMART basic information and determine whether the disk is normal.

- `<alarm_dis_name>`: Alarm disk name

For example, execute:
```bash
smartctl -H --all <alarm_dis_name>
```

View the "SMART overall-health self-assessment test result" content in the command result:
- If it is "FAILED", the disk is faulty and needs to be replaced
- If it is "PASSED", further check the count of "Reallocated_Sector_Ct" or "Elements in grown defect list". If it is greater than 100, the disk is considered faulty and needs to be replaced

### 3.6 View Non-RAID Disk GLIST List to Determine Whether the Disk Is Normal

Execute `smartctl -l error -H <alarm_dis_name>` to view the disk GLIST list and further determine whether the disk is normal.

- `<alarm_dis_name>`: Alarm disk name

For example, execute:
```bash
smartctl -l error -H <alarm_dis_name>
```

View the "Command/Feature_name" column in the command result:
- If "READ SECTOR(S)" or "WRITE SECTOR(S)" appears, the disk has bad sectors
- If other errors appear, the disk circuit board has problems
- Both errors indicate the disk is abnormal and needs to be replaced
- If "No Errors Logged" is displayed, there are no error logs, and disk SMART self-test can be triggered

### 3.7 Non-RAID Disk SMART Self-Test

Execute `smartctl -t long <alarm_dis_name>` to trigger the disk SMART self-test.

- `<alarm_dis_name>`: Alarm disk name

For example, execute:
```bash
smartctl -t long <alarm_dis_name>
```

After the command is executed, the self-test completion time will be prompted. After waiting for the self-test to complete, re-execute `3.5 View Non-RAID Disk Basic Information to Determine Whether the Disk Is Normal` and `3.6 View Non-RAID Disk GLIST List to Determine Whether the Disk Is Normal` to check whether the disk is normal.

### 3.8 Handling When SMART Is Not Supported

When a disk does not support SMART, it is usually because the configured RAID card does not support it. In this case, you need to use the corresponding RAID card vendor's inspection tool for handling.

## 4. Common Alarm Fault Handling Solutions

### 4.1 Disk Has Bad Sectors

**Symptoms**:
- SMART information shows "Reallocated_Sector_Ct" or "Elements in grown defect list" count greater than 100
- GLIST list shows "READ SECTOR(S)" or "WRITE SECTOR(S)" errors
- Disk read/write performance significantly degraded

**Handling solution**:
1. Confirm whether the node where the faulty disk is located is the OMS primary node. If so, perform active/standby switchover before replacing the disk
2. Check whether the faulty disk is mounted on an OMS key directory. If so, migrate data first
3. Replace the faulty disk
4. Verify whether the alarm is automatically cleared after replacement

### 4.2 Disk Circuit Board Fault

**Symptoms**:
- GLIST list shows errors not related to read/write
- Disk cannot be properly identified or respond

**Handling solution**:
1. Confirm whether the node where the faulty disk is located is the OMS primary node. If so, perform active/standby switchover before replacing the disk
2. Check whether the faulty disk is mounted on an OMS key directory. If so, migrate data first
3. Replace the faulty disk
4. Verify whether the alarm is automatically cleared after replacement

### 4.3 Disk SMART Self-Test Failed

**Symptoms**:
- SMART overall-health self-assessment test result shows "FAILED"

**Handling solution**:
1. Immediately back up important data
2. Confirm whether the node where the faulty disk is located is the OMS primary node. If so, perform active/standby switchover before replacing the disk
3. Replace the faulty disk
4. Verify whether the alarm is automatically cleared after replacement

### 4.4 Emergency Recovery System Fault

**Scenario**: Slow disk failure causes system running lag, delayed page refresh, or slow interface response, making O&M operations impossible

**Handling solution**:
- **Primary OMS Node**:
  1. Log in to the primary OMS node as the omm user
  2. Execute the active/standby switchover command:
     - IPv4 mode: `${OMS_RUN_PATH}/workspace/ha/module/hacom/tools/ha_client_tool --ip=127.0.0.1 --port=20013 --switchover --name=product`
     - IPv6 mode: `${OMS_RUN_PATH}/workspace/ha/module/hacom/tools/ha_client_tool --ip=::1 --port=20013 --switchover --name=product`
  3. After the active/standby switchover is successful, the system resumes normal operation
  4. Replace the faulty disk

- **Primary Node of Active/Standby Mode Instance**:
  1. Log in to FusionInsight Manager
  2. Select "Cluster > Services > Name of the service to operate"
  3. On the service details page, click "More" and select "Perform xxx Switchover"
  4. Enter the password of the currently logged-in user to confirm identity, and click "OK"
  5. In the pop-up interface, click "OK" to perform the role instance active/standby switchover
  6. After the active/standby switchover is successful, the system resumes normal operation
  7. Replace the faulty disk

## 5. Alarm Diagnosis Flow

### 5.1 Diagnosis Flow Chart

```
Start
  │
  ▼
Obtain hostname and disk name from alarm information
  │
  ▼
Determine whether the alarm cluster is a virtual machine (systemd-detect-virt)
  │
  ├─── Virtual machine ──→ Determine whether df -h output contains the alarm disk name
  │                     │
  │                     ├─── Contains disk name ──→ Determine whether the disk has RAID configured
  │                     │
  │                     └─── Does not contain disk name ──→ Analyze log cause
  │
  └─── Physical machine ──→ Determine whether df -h output contains the alarm disk name
                        │
                        ├─── Contains disk name ──→ Determine whether the disk has RAID configured
                        │
                        └─── Does not contain disk name ──→ Analyze log cause
  │
  ▼
Determine whether the disk has RAID configured
  │
  ├─── RAID configured ──→ Determine whether the RAID disk supports SMART
  │                         │
  │                         ├─── Supports SMART ──→ View RAID disk basic information
  │                         │                       │
  │                         │                       ▼
  │                         │              View RAID disk GLIST list
  │                         │                       │
  │                         │                       ├─── Has errors ──→ Disk faulty, needs replacement
  │                         │                       │
  │                         │                       └─── No errors ──→ Trigger SMART self-test
  │                         │
  │                         └─── Does not support SMART ──→ Use RAID card vendor tool for handling
  │
  └─── No RAID configured ──→ Determine whether non-RAID hardware supports SMART
                          │
                          ├─── Supports SMART ──→ View non-RAID disk basic information
                          │                       │
                          │                       ▼
                          │              View non-RAID disk GLIST list
                          │                       │
                          │                       ├─── Has errors ──→ Disk faulty, needs replacement
                          │                       │
                          │                       └─── No errors ──→ Trigger SMART self-test
                          │
                          └─── Does not support SMART ──→ Use RAID card vendor tool for handling
  │
  ▼
Determine whether active/standby switchover is needed
  │
  ├─── OMS primary node ──→ Trigger active/standby switchover for emergency system recovery
  │                        │
  │                        ▼
  │                 Replace the faulty disk
  │
  └─── Non-primary node ──→ Directly replace the faulty disk
  │
  ▼
End (alarm cleared)
```

### 5.2 Diagnosis Conclusion Output

Based on the diagnosis flow above, output one of the following diagnosis conclusions:

| Diagnosis Conclusion | Recommended Operation |
|----------|----------|
| Disk faulty - bad sectors | Replace the disk |
| Disk faulty - circuit board problem | Replace the disk |
| Disk SMART self-test failed | Replace the disk |
| Hardware does not support SMART | Use RAID card vendor tool for inspection |
| Alarm still occurs after handling | Continue to replace the disk |
