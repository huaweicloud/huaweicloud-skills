## 3. Log Time Format

### 3.1 Format A: Space-separated format (HA log, runtime log)

```
2024-12-20 10:30:15.123 CST  [Thread-1234] [Level] [Module] Message content
```

| Field | Description | Example |
|------|-------------|---------|
| Date and time | Year-Month-Day Hour:Minute:Second.Millisecond | `2024-12-20 10:30:15.123` |
| Timezone | CST timezone | `CST` |
| Thread ID | Thread identifier | `[Thread-1234]` |
| Log level | INFO/WARN/ERROR/FATAL | `[ERROR]` |
| Module name | Module identifier | `[Executor]` |
| Message content | Log body | `executor service error` |

### 3.2 Format B: T-separated format (GC log)

```
2024-12-20T10:30:15.123+08:00: [GC pause (G1 Evacuation Pause) 4096M->1024M(4096M) 200.123ms]
```

## 4. Detailed Log Description

### 4.1 HA Resource Log (executor*)

#### Log Path
```
/var/log/Bigdata/omm/oms/ha/scriptlog/executor*
```

#### Exception Error Keywords

| Keyword | Meaning | Severity |
|---------|---------|----------|
| `ERROR` | Error message | 🟠 P1 |
| `exception` | Exception caught | 🟠 P1 |
| `process of executor is in the D state` | Process in D state | 🔴 P0 |
| `connect executor failed` | HTTP connection failed | 🟠 P1 |
| `PID is xxx` | Process existence info | 🟢 P3 |
| `checkServiceStatus,currentStatus is standby` | Standby node status | 🟢 P3 |

#### Keyword Priority and Root Cause

| Priority | Keyword Combination | Root Cause | Possible Impact |
|----------|---------------------|------------|-----------------|
| P0 | `process of executor is in the D state` | Process in D state (I/O blocked) | Service unresponsive |
| P1 | `connect executor failed` | HTTP connection failed | Service unavailable |
| P1 | `ERROR` + `executor` | Executor service exception | Service unavailable |
| P1 | `exception` | Business exception | Functional exception |

#### Search Command Examples

```bash
python3 lakewatch_api_client.py -a collect_alarm_log_data \

  -p 'log_directory=/var/log/Bigdata/omm/oms/ha/scriptlog' \
  -p 'log_file_name=executor*' \
  -p 'keywords=[]' \
  -p 'log_type=local' \
  -p 'node_name=<node_name>'
```

### 4.3 GC Log (gc.log)

#### Log Path
```
/var/log/Bigdata/executor/gc.log*
```

#### Log Time Format
```
2024-12-20T10:30:15.123+08:00: [GC pause (G1 Evacuation Pause) 4096M->1024M(4096M) 200.123ms]
```

#### Exception Error Keywords

| Keyword | Meaning | Severity |
|---------|---------|----------|
| `Full GC` | Full garbage collection | 🟠 P1 |
| `OutOfMemoryError` | Out of memory | 🔴 P0 |

#### Keyword Priority and Root Cause

| Priority | Keyword Combination | Root Cause | Possible Impact |
|----------|---------------------|------------|-----------------|
| P0 | `OutOfMemoryError` | Out of memory | Process crash |
| P1 | `Full GC` | Frequent Full GC | Performance degradation |

#### Search Command Examples

```bash
python3 lakewatch_api_client.py -a collect_alarm_log_data \
  -p 'cluster_id=<cluster_id>' \
  -p 'alarm_time=<alarm_time>' \
  -p 'log_directory=/var/log/Bigdata/executor' \
  -p 'log_file_name=gc.log*' \
  -p 'keywords=["Full GC","OutOfMemoryError"]' \
  -p 'log_type=local' \
  -p 'node_name=<node_name>' \
  -p 'time_pattern=^\[([0-9]{4})-([0-9]{2})-([0-9]{2})T([0-9]{2}):([0-9]{2}):([0-9]{2})||ymdHMS'
```
