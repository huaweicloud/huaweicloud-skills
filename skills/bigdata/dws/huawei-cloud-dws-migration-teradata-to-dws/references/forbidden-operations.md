# Teradata 到 DWS 迁移高危操作禁止列表

> 本文档定义了 AI 自动迁移过程中**严格禁止**的高危操作。
> 所有迁移脚本和 AI 决策引擎在执行任何操作前，必须参照本列表进行安全校验。
> 核心原则：**源端绝对只读，目标端受控写入，系统环境不可破坏**。

---

## 一、源端（Teradata）禁止操作 — 最高优先级 🔴

> **铁律：对源端 Teradata 的所有访问必须为只读，绝不修改任何数据、结构、权限或会话状态。**

### 1.1 DDL 写操作（修改源端结构）

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `CREATE TABLE/VIEW/INDEX/...` | 🔴 极高 | 在源端创建对象 |
| 表/视图/索引等对象删除 | 🔴 极高 | 删除源端对象 |
| `ALTER TABLE/VIEW/...` | 🔴 极高 | 修改源端表结构 |
| `RENAME` | 🔴 极高 | 重命名源端对象 |
| `REPLACE VIEW/PROCEDURE` | 🔴 极高 | 替换源端对象定义 |

### 1.2 DML 写操作（修改源端数据）

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `INSERT` | 🔴 极高 | 向源端插入数据 |
| `UPDATE` | 🔴 极高 | 修改源端数据 |
| `DELETE` | 🔴 极高 | 删除源端数据 |
| `DELETE ALL` | 🔴 极高 | 清空源端表 |
| `MERGE` (UPSERT) | 🔴 极高 | 合并写入源端 |

### 1.3 批量加载工具（破坏性数据写入）

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `FastLoad` | 🔴 极高 | Teradata 批量加载，会写入源端 |
| `MultiLoad` | 🔴 极高 | Teradata 多表加载，会写入源端 |
| `TPump` | 🔴 极高 | Teradata 持续加载，会写入源端 |
| `BTEQ`（含写操作） | 🔴 极高 | BTEQ 可执行任意 SQL，需限制为只读 |
| `FastExport`（写回模式） | 🟡 中 | FastExport 本身只读，但需确认未配置写回 |

### 1.4 事务控制（可能影响源端一致性）

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `BEGIN TRANSACTION` / `BT` | 🟠 高 | 在源端开启写事务 |
| `END TRANSACTION` / `ET` | 🟠 高 | 提交源端事务 |
| `ABORT` | 🟠 高 | 中止源端事务 |
| `ROLLBACK` | 🟡 中 | 回滚源端事务 |
| `COMMIT` | 🟡 中 | 提交源端事务 |
| `CHECKPOINT` | 🟠 高 | 设置源端检查点 |

### 1.5 权限/安全操作

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `GRANT` | 🔴 极高 | 授予源端权限 |
| `REVOKE` | 🔴 极高 | 撤销源端权限 |
| `GIVE` | 🔴 极高 | 转移源端数据库所有权 |
| `MODIFY USER` | 🔴 极高 | 修改源端用户 |
| `CREATE USER` | 🔴 极高 | 创建源端用户 |
| `DROP USER` | 🔴 极高 | 删除源端用户 |

### 1.6 会话/系统状态修改

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `SET QUERY_BAND` | 🟠 高 | 修改会话查询带 |
| `SET SESSION` | 🟠 高 | 修改会话参数 |
| `DATABASE` | 🟡 中 | 切换默认数据库 |
| `SET TIME ZONE` | 🟡 中 | 修改时区设置 |
| `SET ROLE` | 🟡 中 | 切换角色 |

### 1.7 数据库管理操作

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `ALTER DATABASE` | 🔴 极高 | 修改源端数据库属性 |
| 数据库删除 | 🔴 极高 | 删除源端整个数据库 |
| `CREATE DATABASE` | 🟡 中 | 在源端创建新数据库 |
| `MODIFY DATABASE` | 🔴 极高 | 修改源端数据库配置 |
| `ARCHIVE` / `RESTORE` | 🔴 极高 | 源端备份/恢复操作 |
| `COPY` | 🔴 极高 | 源端数据复制操作 |

## 二、目标端（DWS）禁止操作 — 高优先级 🟠

> **原则：目标端允许写入迁移数据，但禁止破坏性操作。**

### 2.1 破坏性 DDL

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| 数据库删除 | 🔴 极高 | 删除整个数据库 |
| Schema 级联删除 | 🔴 极高 | 级联删除 schema 及所有对象 |
| 已迁移表删除 | 🟠 高 | 删除已成功迁移的表（除非用户明确确认） |
| 已迁移表清空 | 🟠 高 | 清空已迁移数据（除非重迁移场景） |
| `ALTER TABLE DROP COLUMN` | 🟠 高 | 删除列（可能导致数据丢失） |

### 2.2 破坏性数据操作

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| 全表数据无条件删除 | 🔴 极高 | 无条件删除全表数据 |
| `UPDATE table SET ...`（无 WHERE） | 🔴 极高 | 无条件更新全表数据 |
| 表重建（先删后建） | 🟠 高 | 先删后建（应使用 ALTER 或清空操作替代） |

### 2.3 权限滥用

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| `GRANT ALL TO PUBLIC` | 🔴 极高 | 向所有用户授予全部权限 |
| `ALTER USER`（修改管理员） | 🔴 极高 | 修改管理员账户 |
| `CREATE USER`（超范围） | 🟠 高 | 创建超出迁移范围的用户 |

## 三、系统/环境级禁止操作 🟠

### 3.1 文件系统

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| 递归删除根目录及全部文件 | 🔴 极高 | 系统级破坏 |
| 删除源端配置文件 | 🔴 极高 | 删除 migration_info.xlsx 等关键配置 |
| 删除已生成的迁移输出（迁移过程中） | 🟠 高 | 删除 DDL/校验报告等中间产物 |
| 覆盖已有输出文件（无备份） | 🟡 中 | 应先备份再覆盖 |

### 3.2 网络连接

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| 修改源端 Teradata 网络配置 | 🔴 极高 | 可能导致源端失联 |
| 关闭/重启 Teradata 服务 | 🔴 极高 | 影响源端生产 |
| 关闭/重启 DWS 集群 | 🟠 高 | 影响迁移进度 |
| 修改防火墙规则 | 🟠 高 | 可能中断迁移连接 |

### 3.3 进程/资源

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| 强制终止（强杀信号）迁移进程 | 🟠 高 | 强制终止可能导致数据不一致 |
| 占用源端全部 CPU/内存 | 🟠 高 | 影响源端生产性能 |
| 并发度过高导致源端拒绝连接 | 🟡 中 | 应限制并发查询数 |

## 四、数据安全/隐私禁止操作 🔴

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| 明文输出密码/凭证到日志 | 🔴 极高 | 凭证泄露 |
| 将源端数据写入非目标位置 | 🔴 极高 | 数据泄露到未授权位置 |
| 跳过 SSL/TLS 加密连接 | 🟠 高 | 明文传输敏感数据 |
| 将含敏感数据的 CSV 留在临时目录 | 🟠 高 | 迁移完成后应清理中间文件 |
| 在日志中打印完整行数据 | 🟡 中 | 应只记录行数/摘要 |

## 五、迁移逻辑禁止操作 🟠

| 禁止操作 | 风险等级 | 说明 |
|---------|---------|------|
| 跳过数据类型校验直接迁移 | 🟠 高 | 可能导致数据截断/精度丢失 |
| 跳过行数校验直接完成 | 🟠 高 | 无法发现数据丢失 |
| 无回滚地批量导入大表 | 🟡 中 | 应支持断点续传/分批导入 |
| 修改源端数据以适配目标类型 | 🔴 极高 | 绝不修改源端数据 |
| 忽略字符集差异直接导入 | 🟠 高 | 可能导致乱码 |
| 并发迁移同一张表 | 🟠 高 | 可能导致数据重复/不一致 |

## 七、只读白名单（源端 Teradata 允许的操作）

以下为**允许**的安全只读操作，AI 和迁移脚本可自由使用：

```python
READONLY_SQL_PREFIXES = (
    'SELECT',                # 查询数据/元数据
    'SHOW',                  # SHOW TABLE / SHOW VIEW 获取 DDL
    'HELP',                  # HELP TABLE / HELP COLUMN 获取结构
    'COLLECT STATISTICS',    # 收集统计信息（不修改数据）
    'EXPLAIN',               # 查看执行计划
    'WITH',                  # WITH ... SELECT 递归查询
    'DUMP',                  # 数据导出
    'EXPORT',                # 数据导出
)
```

## 八、安全校验实现规范

### 三重防护机制

迁移脚本和 AI 决策引擎必须采用**白名单优先 + 黑名单兜底 + 默认拒绝**三重防护：

```python
def validate_sql(sql: str) -> None:
    """
    三重安全校验：所有 SQL 在执行前必须通过此校验。

    1. 黑名单检查 — 显式禁止已知危险操作
    2. 白名单检查 — 显式允许已知安全操作
    3. 默认拒绝 — 无法确认的 SQL 一律拒绝
    """
    sql_clean = remove_comments(sql).strip().upper()

    # 第一重：黑名单检查
    for forbidden in FORBIDDEN_SQL_PREFIXES:
        if sql_clean.startswith(forbidden):
            raise WriteOperationError(
                f"禁止在源端执行写操作: {forbidden}\n"
                f"SQL: {sql_clean[:200]}"
            )

    # 第二重：白名单检查
    is_readonly = any(
        sql_clean.startswith(allowed)
        for allowed in READONLY_SQL_PREFIXES
    )

    # 第三重：默认拒绝
    if not is_readonly:
        raise WriteOperationError(
            f"无法确认 SQL 为只读操作，默认拒绝执行。\n"
            f"SQL: {sql_clean[:200]}"
        )
```

### 黑名单完整列表

```python
FORBIDDEN_SQL_PREFIXES = (
    # DDL 写操作
    'CREATE', 'DROP', 'ALTER', 'RENAME', 'REPLACE',
    # DML 写操作
    'INSERT', 'UPDATE', 'DELETE', 'MERGE',
    # 批量加载工具
    'LOAD', 'BTEQ',
    # 事务控制
    'BEGIN TRANSACTION', 'END TRANSACTION', 'ABORT',
    'ROLLBACK', 'COMMIT', 'CHECKPOINT',
    'BT', 'ET',
    # 权限操作
    'GRANT', 'REVOKE', 'GIVE',
    # 会话状态
    'SET QUERY_BAND', 'SET SESSION', 'SET ROLE', 'SET TIME ZONE',
    # 数据库管理
    'ARCHIVE', 'RESTORE', 'COPY', 'DATABASE',
    # 用户管理
    'MODIFY USER', 'CREATE USER', 'DROP USER',
)
```

## 九、违规处理流程

当检测到高危操作时，按以下流程处理：

1. **立即中止** — 中止当前操作，不执行该 SQL/命令
2. **记录日志** — 将违规操作、时间、上下文写入安全审计日志
3. **抛出异常** — 抛出 `WriteOperationError` 或 `SecurityViolationError`
4. **通知用户** — 向用户报告违规详情，等待人工确认
5. **不自动重试** — 对安全违规操作不进行自动重试
